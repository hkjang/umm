# v0.34.1 — 자동 찾기가 채팅 주소를 덮어쓰고 있었습니다

v0.34.0에서 임베딩 Gateway 주소를 따로 뒀습니다. 그러면서 **그 전제로 쓰여 있던 것들**을 같이 고쳤어야
했는데, 놓쳤습니다.

## 자동 찾기

관리자 → AI Gateway의 **자동 찾기**는 임베딩 서버를 뒤져 모델 목록을 보여 줍니다. 거기서 모델을
고르면 찾은 주소를 **`Base URL`(채팅 모델 주소)에** 써 넣었습니다.

둘이 한 칸을 쓰던 시절에는 맞는 동작이었습니다. 이제는 **채팅 모델을 임베딩 전용 서버로 겨누는**
셈이라, 자동 찾기를 쓰는 순간 답변 기능이 망가집니다.

이제 임베딩 칸에 씁니다.

```
채팅 Base URL     : https://chat-model.example/v1   ← 그대로
임베딩 Gateway    : http://127.0.0.1:11434          ← 찾은 주소
임베딩 모델       : bge-m3
```

## 안내문도 옛말을 하고 있었습니다

기본 임베딩 경고에 v0.28.0부터 이렇게 적혀 있었습니다.

> 그 다음 **위의 AI Gateway 주소를** `http://embeddings:11434` 으로 … 저장하고 다시 측정하세요.

시키는 대로 하면 채팅 모델 주소가 임베딩 서버로 바뀝니다. `compose.yaml`의 주석도 같은 말을 하고
있었습니다. 둘 다 **임베딩 칸**을 가리키도록 고쳤고, *"채팅 모델 주소는 그대로 두면 됩니다"*를
덧붙였습니다.

## CI에서 실제로 도는 테스트

자동 찾기는 임베딩 서버가 떠 있어야 동작합니다. 그대로 테스트하면 **CI에서는 건너뛰어져 아무것도
지키지 못합니다** — v0.30.0에서 배운 것입니다.

그래서 찾기 응답을 가로채 가짜 서버 하나를 돌려주고, **채팅 주소가 그대로인지**를 확인합니다.
