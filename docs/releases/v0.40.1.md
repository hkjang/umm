# v0.40.1 — 같은 덱이 보는 곳에 따라 다르게 말했습니다

v0.39·v0.40이 나간 뒤 **진짜 Ptium을 다시 띄워 전체 경로를 재검증**하다가 찾았습니다.
잘 도는지 확인만 하려던 것이었습니다.

```
공간의 발표 목록:   회귀 점검 | 슬라이드 1장 바뀜
바뀐 그 메모에서:   회귀 점검 | 바뀐 것 없음      ← 틀림
```

**메모 쪽이 더 중요한 자리입니다.** 방금 그 생각을 고쳐 쓴 참이고, "이 생각을 인용한 발표가
있습니다"라고 말해야 할 바로 그 순간인데 — 아무 문제 없다고 답하고 있었습니다.

두 핸들러가 **각자 응답을 조립**한 탓입니다. 덱을 열 주소는 둘 다 붙이는데 낡음 개수는
한쪽만 붙였습니다. 조립기 하나를 공유하게 해서 세 번째 호출자가 같은 실수를 못 하게 했습니다.

**읽지 못한 개수는 0이 아니라 없음으로 둡니다.** "아무것도 안 바뀌었다"는 주장인데, 실패한
쿼리는 그 주장을 할 처지가 아닙니다.

## 서 있는 김에 전체를 다시 걸어 봤습니다

Living Presentation은 지금까지 **손으로 쓴 SQL로만** 확인했었습니다. 이번에는 브라우저가
실제로 쓰는 엔드포인트로 했습니다.

| 한 일 | 결과 |
| --- | --- |
| 실제 Ptium에 덱 생성 | `ready`, 생각 4개 |
| `PUT /notes/{id}`로 메모 **이동** (version 오름) | 변화 없음 |
| 같은 메모 **고쳐 쓰기** | 슬라이드 1장 바뀜 |
| | `slide 3 changed → 역시 주 1회를 유지하기로 했다` |
| 다시 만들기 | 변화 없음 |

사람이 실제로 걷는 경로에서도 성립합니다.
