# v0.47.1 — API 키가 언제 멈추는지 말합니다

`개인 설정`은 마지막으로 남아 있던 화면입니다. 키와 웹훅을 실제로 만들어 놓고 봤습니다.

## 키가 언제 멈추는지가 어디에도 없었습니다

한 줄이 이렇게 나오고 있었습니다.

```
umm_key_zq8bvraz_••••  ·  2026. 8. 26.
```

`2026. 8. 26.` 은 **만든 날**입니다. 아무 설명도 붙어 있지 않고요. 그런데 서버는 이미 이렇게
보내고 있었습니다.

```json
"expiresAt": "2026-11-24T03:08:05+09:00"
```

**석 달 뒤 이 키는 멈춥니다.** 화면 어디에도 없었습니다. 잊고 있던 키야말로 만료일이 궁금한
키인데, 화면은 **가장 손쓸 수 없는 날짜 하나**만 보여 주고 있었습니다.

### 교체 중에는 더 심합니다

키를 회전시키면 이전 키가 하루 더 살아 있다가 멈춥니다. 그 상태를 재 봤습니다.

```
회사 자동화   overlap   overlapUntil = 2026-08-27T03:09
```

화면에는 노란 배지에 `overlap` 이라고만 적혀 있었습니다. **언제까지인지는 없었습니다.**
회전이라는 작업이 통째로 그 마감 하나를 위한 것인데요.

이제 이렇게 나옵니다.

```
umm_key_gc2qyxhs_••••  ·  2026. 8. 27. 오전 3:09까지만 동작합니다  ·  아직 사용된 적 없음
umm_key_zq8bvraz_••••  ·  만료 2026. 11. 24.                      ·  마지막 사용 2026. 8. 25.
```

`lastUsedAt` 도 응답에 있었고 쓰이지 않고 있었습니다. **아직 뭔가 이 키를 쓰고 있는지**는
폐기해도 되는지를 정할 때 필요한 정보입니다.

## 같은 화면에서 말투가 갈렸습니다

```
키:    ACTIVE / overlap / revoked     ← 저장된 값
웹훅:  활성 / 중지                     ← 사람의 말
```

바로 위아래입니다. 이제 키도 **사용 중 / 교체 중 / 폐기됨** 입니다.

## 검증

되돌려서 확인했습니다.

```
✘ 만든 날짜를 다시 라벨 없이 표시  → 만료·마감 문구 없음으로 실패
✘ 저장된 상태값을 다시 출력        → 실패
```

## 덧: 지난번 교훈을 그대로 썼습니다

Go 스위트가 깨끗한 DB 에서 하나 실패했습니다. 지난 릴리스에 적어 둔 대로 **손대지 않은
main 을 같은 조건에서 먼저 돌렸습니다.**

```
내 변경, 전체 스위트     → TestDreamInboxAcceptance 실패
손대지 않은 main, 전체    → quota·autolink 실패  ← 실패는 하되 다른 것이
내 변경, 그 테스트 하나   → 통과
```

**손대지 않은 코드도 실패합니다.** 실패하는 항목이 실행마다 다르니 이 스위트는 로컬에서
전체를 한 번에 돌리는 방식과 맞지 않습니다. 이번 변경은 프런트엔드 한 파일이라 Go 테스트에
닿지도 않습니다. E2E 도 마찬가지였습니다 — Go 테스트가 게이트웨이 설정을 남긴 DB 에서는
admin-gateway 둘이 실패하고, **아무도 건드리지 않은 DB 에서는 69개 전부 통과**합니다.
