# umm v0.17.0 — 좋은 임베딩까지 한 번의 클릭

v0.10.0에서 기본 임베딩이 뜻이 아니라 어휘를 잰다는 것을 **측정**했고, 화면에 노출했고, v0.12.0 이후로는 판별 못 하는 백엔드에서 기능이 **거부**되도록 만들었습니다.

그런데 기본 설치는 여전히 어휘 위에서 돕니다. 남은 것은 지식이 아니라 **마찰**이었습니다.

제대로 된 모델을 붙이려면 세 가지를 알아야 했습니다.

1. 기본값이 어휘라는 사실 — v0.10.0이 답했습니다
2. 어딘가에 게이트웨이가 돌고 있다는 사실 — 컴포즈 프로파일이 답했습니다
3. **모델 이름이 무엇인지** — 아무도 답하지 않았습니다

---

## 1. 자동으로 찾기

관리자 → AI Gateway에 **자동으로 찾기** 버튼이 생겼습니다. umm이 문서에 적어 둔 주소들을 조사해 응답하는 게이트웨이와 그 모델 목록을 보여 줍니다.

```
http://embeddings:11434
  * paraphrase-multilingual:latest

http://host.docker.internal:11434
  * paraphrase-multilingual:latest
  * bona/bge-m3-korean:latest
  * bge-m3:latest
    qwen3.6:27b
    gemma4:31b
```

모델을 누르면 주소와 이름이 채워집니다. 그다음은 기존 **연결 테스트**와 **임베딩 품질 측정**이 이어받습니다.

`*` 표시는 **이름으로 짐작한 것**이지 확인한 것이 아닙니다. 게이트웨이는 자기가 서빙하는 모든 모델을 나열하고 응답 어디에도 무엇이 임베딩 모델인지 적혀 있지 않습니다. 채팅 모델 열 개 중 임베딩 두 개를 위로 올려 주는 정도이고, **실제로 임베딩하는지는 연결 테스트가 정합니다.**

### 조사하는 주소는 바이너리에 박혀 있습니다

요청에서 주소를 받지 않습니다. 받는다면 이 화면이 **서버가 닿을 수 있는 곳이면 어디든 조사하는 수단**이 되고, umm 자신의 사이드카를 찾는 데는 그런 것이 전혀 필요 없습니다.

후보 주소도 응답을 신뢰하지 않습니다. 그 포트에 다른 것이 떠 있을 수 있으므로 HTML, 오류, 잘못된 JSON, 거대한 본문 모두 테스트로 고정해 두었습니다.

## 2. 사이드카가 스스로 모델을 받습니다

이전에는 두 명령이었습니다.

```bash
docker compose --profile embeddings up -d
docker compose exec embeddings ollama pull bge-m3   # ← 이걸 알아야 했습니다
```

이제 하나입니다.

```bash
docker compose --profile embeddings up -d
```

컨테이너가 뜨면서 스스로 받습니다. 볼륨에 이미 있으면 no-op이라 재시작 비용이 없고, 네트워크가 없는 기계도 이미 가진 것으로 올라옵니다.

**healthcheck도 고쳤습니다.** 서버가 응답하는 것이 아니라 **모델이 실제로 존재하는 것**을 확인합니다. 그러지 않으면 umm이 첫 사용에서 404를 내는 게이트웨이를 가리키게 됩니다.

`UMM_EMBEDDING_MODEL`로 받을 모델을 바꿀 수 있습니다.

## 3. 실제로 확인한 경로

빈 스택에서 시작해 끝까지 밟았습니다.

```
docker compose --profile embeddings up -d
  → 사이드카가 paraphrase-multilingual을 받고 healthy

자동으로 찾기
  → http://embeddings:11434 (사이드카가 먼저)
  → http://host.docker.internal:11434

연결 테스트
  → ok · paraphrase-multilingual:latest · 768차원

임베딩 품질 측정
  이전:  semantic=false  정확도 0.042  최근접 동일 주제 0.188
  이후:  semantic=true   정확도 0.854  최근접 동일 주제 0.875
```

---

## 여전히 남은 것

**기본 설치는 그대로 어휘 위에서 돕니다.** 이번 릴리스는 그 사실을 바꾸지 않았습니다 — 거기서 벗어나는 데 드는 노력을 줄였을 뿐입니다.

모델을 umm 이미지에 넣는 것은 여전히 `CGO_ENABLED=0` 정적 단일 바이너리를 포기해야 하는 일이고, 그 교환은 아직 하지 않았습니다.

## 업그레이드

스키마 변경이 없습니다. 이미지만 교체하면 됩니다.

```bash
docker run -d --name umm --restart unless-stopped \
  -p 8080:8080 \
  -e POSTGRES_DSN='postgres://umm:password@postgres.internal:5432/umm?sslmode=require' \
  -e BOOTSTRAP_ADMIN='admin' \
  -e BOOTSTRAP_ADMIN_PASSWORD='your-strong-password' \
  -e ENCRYPTION_KEY='your-32-char-random-encryption-key' \
  umm:v0.17.0
```

- 이미 사이드카를 쓰고 있다면 `docker compose --profile embeddings up -d`로 다시 올리면 자동 pull 방식으로 바뀝니다. 볼륨은 그대로 쓰이므로 다시 받지 않습니다.
- 자동 찾기는 관리자 세션에서만 동작하며, 조사 주소는 고정되어 있습니다.
