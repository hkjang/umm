# v0.34.4 — 비밀 값을 빠뜨리면 테스트가 먼저 알아챕니다

v0.34.0에서 임베딩 API Key를 추가하면서, 마스킹 목록에 넣는 걸 **거의 잊을 뻔했습니다.**

잊었다면 이렇게 됩니다.

```
GET /api/v1/admin/settings
  api_key           : ••••••••
  embedding_api_key : sk-live-...        ← 평문
```

설정을 읽을 수 있는 사람에게 키가 그대로 나가고, 저장도 **암호화 없이** 됩니다. 아무 오류도 나지
않고, 화면도 멀쩡해 보입니다.

## 이름으로 판별합니다

새 테스트는 저장된 설정을 훑어 **`_key`·`_secret`·`_token`·`_password`·`_credential`로 끝나는 필드**를
전부 찾고, 그것들이 마스킹 목록에 있는지 확인합니다.

값이 아니라 **이름**으로 판별하는 게 핵심입니다. 갓 설치한 인스턴스에서는 키가 비어 있을 텐데,
"지금 비어 있으니 괜찮다"로 통과하면 안 됩니다.

목록에서 `api_key`를 빼고 돌려 확인했습니다.

```
ai_gateway.api_key looks like a credential but is not in secretFields("ai_gateway"):
  it would be returned in plain text by the settings API and stored unencrypted
```

## 반대 방향은 검사하지 않습니다

"목록에 있는데 저장된 설정에 없는 이름"도 잡으려 했는데, 처음 돌렸을 때 바로 걸렸습니다 —
`embedding_api_key`는 아직 아무도 저장하지 않았으니 당연히 없습니다. **아직 저장 안 됨**과 **오타**를
JSON만 봐서는 구분할 수 없습니다.

그리고 오타라면 진짜 필드가 마스킹되지 않은 채 남으므로 **위 검사가 이미 잡습니다.** 그래서 뺐습니다.

## 확인한 것

- 목록에서 필드를 빼고 돌려 실패 확인
- 검사 대상이 0개면 테스트가 스스로 실패합니다 — 아무것도 안 보면서 통과하지 않도록
- 전체 Go 테스트 통과
