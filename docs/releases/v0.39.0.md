# v0.39.0 — 발표 자료가 언제 사실이 아니게 되는지 알려 줍니다

생각으로 만든 발표는 **그 생각이 바뀌는 순간** 사실이 아니게 됩니다.

어느 생각이 어느 슬라이드에 있는지 아는 건 umm뿐이니, 알아챌 수 있는 것도 umm뿐입니다.

```
이 공간으로 만든 발표
임원 보고            [슬라이드 1장 바뀜]   ↗ 열기
```

## 명백해 보이는 신호가 틀린 신호였습니다

노트의 `version`을 보면 될 것 같습니다. 확인해 보니 안 됩니다.

```sql
UPDATE notes SET content=…, title=…, x=…, y=…, width=…, height=…, rotation=…,
                 version=version+1   -- 전부 같은 문장
```

**메모를 끌어서 옮기기만 해도 version이 오릅니다.** 캔버스에서 가장 자주 하는 일이 그것인데,
그러면 모든 발표 자료가 **영구히 "낡음"** 이 되고 경고는 첫날부터 아무 의미가 없어집니다.

경고가 늘 켜져 있으면 그건 경고가 아닙니다.

## 그래서 문장의 지문을 봅니다

옮기면 안 바뀌고, **고쳐 쓰면 바뀝니다.**

md5는 **데이터베이스가 양쪽에서** 계산합니다 — 슬라이드를 기록할 때와 나중에 확인할 때.
"같은 문장"의 정의가 Go에 하나, SQL에 하나 생겨서 서로 어긋나는 일을 막습니다.

브라우저에서 확인했습니다:

| 한 일 | 결과 |
| --- | --- |
| 생각을 고쳐 씀 | **슬라이드 1장 바뀜** |
| 공간의 **모든 메모**를 옮김 | 변화 없음 |

## 고쳐 쓴 것과 지운 것은 다릅니다

하나는 **슬라이드를 최신으로 만들 수 있고**, 다른 하나는 **출처 자체를 잃었습니다.**

"낡음" 하나로 묶으면 지금 보고 있는 게 어느 쪽인지 감춥니다. 할 수 있는 일이 다른데요.

## 모르는 것을 낡았다고 하지 않습니다

지문 없이 만들어진 슬라이드 — 이번 업그레이드 직전에 만든 것들 — 은 **보고하지 않습니다.**

아무도 모르는데 "낡았다"고 하는 건 아무 말도 안 하는 것보다 나쁩니다. 업그레이드하는 날
모든 발표 자료에 경고가 켜지면, 그 경고는 시작하자마자 무의미해집니다.

## 검증

통합 테스트 10개, **고의로 망가뜨린 6군데가 전부 잡혔습니다**:

```
staleness keyed on version, not the words      caught   ← 설계 결정 자체
title left out of the fingerprint              caught
unknown fingerprints treated as stale          caught
fingerprint never recorded on write            caught
deleted collapsed into changed                 caught
counts ignore membership                       caught
```

첫 줄이 핵심입니다. version으로 바꾸면 **"메모를 옮겨도 낡지 않는다"** 테스트가 실패합니다.
