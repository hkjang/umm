# umm v0.8.1 — 권한·동시성 경계를 끝까지 지키는 패치

v0.8.1은 v0.8.0의 규모·보안·접근성 개선을 그대로 유지하면서, 협업 멤버가 제거되는 바로 그 순간에도 이전 권한으로 콘텐츠가 반환되거나 변경되지 않도록 접근 경계를 강화한 보안·신뢰성 패치입니다. 릴리스 전 자동 리뷰에서 발견한 실시간 알림 경합과 LISTEN 단절 뒤 SSE 폴백 지연, 구버전 관리자 저장의 보안 한도 초기화, `notes:read` key에 암묵적으로 열려 있던 AI Assist 외부 호출, 권한 회수 뒤 댓글 mutation의 오프라인 큐 고착과 Dream 파생 콘텐츠·Gateway 전송 경합, 웹훅 HTTP 전송 중 구독·사용자·공간 권한 회수 경합, 느린 외부 호출 access lease의 request pool 고갈, proxy header 신뢰, 임베딩 개인정보·장애 폴백·두 단계 설정 전환 및 AI 제외 전환 경합, 일반 사용자 세션에 열려 있던 Prometheus 운영 지표, 다중 인스턴스 AI 쿼터 경합, 병렬 로그인 추측과 성공 로그인 기반 제한 우회, API 키 난수 실패, legacy master-key 회전 누락과 마스킹 설정 저장 경합, 오프라인 큐 업그레이드·저장소 quota/권한 오류, 부분 가져오기 초안 유실, Today 활동 설정의 검토 목록 유실, 작은 DB pool의 알림 교착·LISTEN 독점, 고정 PWA 파일의 과도한 장기 캐시, 삭제된 생각의 댓글 mutation·알림 노출, 다국어 User-Agent와 웹훅·Gateway 오류의 UTF-8 경계 절단도 함께 닫았습니다.

필수 환경변수 네 개는 그대로입니다. TLS 종료 proxy를 사용하는 배포만 선택 환경변수 `UMM_TRUSTED_PROXY_CIDRS`에 직접 연결되는 proxy IP/CIDR을 지정해야 forwarding header를 인정합니다. 마이그레이션 008과 009는 기동 시 자동 적용되며 각각 AI 쿼터의 대기 예약·24시간 소비 원장과 전용 `ai:assist` 허용 scope를 추가합니다.

## 원자적 콘텐츠 권한 확인

기존 구현 일부는 공간 접근권한을 먼저 확인하고 다음 쿼리에서 콘텐츠를 읽었습니다. 두 statement 사이에 관리자가 멤버를 제거하면, 이미 통과한 확인 결과로 짧은 시간 동안 본문이 반환될 가능성이 있었습니다.

이제 다음 조회는 **콘텐츠를 읽는 PostgreSQL statement 자체**에 현재 공간 owner/member 조건을 결합합니다.

- Canvas 생각 목록과 연결선
- 생각 수정 이력
- 댓글과 답글
- 들어오는 링크·나가는 링크(백링크)
- 공간 멤버 목록

공간이나 생각이 실제로 비어 있는 경우와 접근권한이 사라진 경우도 구분합니다. 접근 가능한 빈 목록은 정상적으로 빈 배열을 반환하고, 제거된 멤버의 요청은 `404`로 닫힙니다. 데이터베이스 일시 오류는 권한 없음으로 숨기지 않고 `500`으로 기록·응답해 운영자가 원인을 찾을 수 있습니다.

댓글 생성·해결·삭제도 같은 경계를 적용합니다. 생성 transaction은 생각·공간 행과 호출자의 현재 멤버십 행을 잠근 채 댓글, 알림, 실시간 공간 이벤트, webhook outbox를 한 번에 확정합니다. 멤버 제거가 먼저 확정되면 생성은 아무 부수 효과 없이 닫히고, 생성이 먼저 잠금을 얻으면 제거가 commit 뒤까지 기다리므로 사전 확인 결과가 뒤늦게 재사용되지 않습니다. 작성자는 현재 공간 멤버인 동안에만 자신의 댓글을 삭제할 수 있고, 공간에서 제거된 뒤 보관한 댓글 ID로 삭제 이벤트나 webhook을 만들 수 없습니다. 원본 생각이 soft-delete된 뒤에는 공간 owner나 편집자도 보관한 댓글 ID로 해결·재개·삭제 행과 협업 이벤트·webhook을 만들 수 없습니다. 공간 owner와 현재 `manage` 멤버의 활성 생각 관리 권한은 유지됩니다.

## 내보내기 경계 강화

공간 내보내기는 생각 목록을 가져올 때 현재 접근권한을 확인하고, 응답 파일을 쓰기 직전에 공간 이름을 조회할 때도 권한을 다시 확인합니다. 승인 대기와 실제 다운로드 사이에 공유가 취소된 경우에도 내보내기 본문이 전송되지 않습니다.

## 동시성과 네트워크 신뢰 경계 강화

- **실시간 SSE fan-out과 즉시 failover**: 구독 해제와 알림 publish가 겹칠 때 닫힌 채널로 전송해 프로세스가 panic할 수 있던 경로를 제거했습니다. 구독은 레지스트리에서만 제거하고 요청 context가 reader 수명을 끝냅니다. LISTEN 연결의 단절·복구도 모든 열린 구독자에게 coalesced wake-up으로 전달해 cursor 이후를 즉시 따라잡고 타이머를 각각 1초 폴백·30초 safety net으로 다시 맞춥니다. 단절 직전에 건강한 stream이 설정한 30초 deadline을 기다리며 협업 변경을 늦게 보는 구간을 없앴고, 상태 신호는 실제 event 전달 지표에 합산하지 않습니다.
- **신뢰할 proxy만 전달 헤더 사용과 완전한 Origin 비교**: 기본값에서는 모든 `X-Forwarded-For`, `X-Real-IP`, `X-Forwarded-Proto`를 무시합니다. 명시한 proxy 대역에서 온 요청만 오른쪽부터 신뢰 체인을 검증해 실제 client IP와 scheme을 정하므로, 외부 클라이언트가 로그인/API rate limit이나 HTTPS 판단을 header로 우회할 수 없습니다. 브라우저 변경 요청은 `Origin`의 scheme·hostname·effective port가 현재 요청 또는 관리자 공개 URL과 모두 같아야 하므로 HTTPS 서비스에 대한 `http://같은-host` 요청도 거부합니다. credential·path·query가 포함된 비정상 Origin 역시 fail closed 합니다.
- **개인정보와 벡터 공간을 지키는 빠른 임베딩 폴백**: 메모나 공간에서 AI 제외를 켜면 선택적 임베딩 모델이 설정되어 있어도 본문을 외부 Gateway에 보내지 않고 전체 비교 집합을 로컬 vector로 처리합니다. 초기 확인과 외부 dispatch 사이의 경합도 닫았습니다. 원격 호출 직전에 현재 `ai_gateway` 설정과 대상 note·space 행을 shared lock으로 다시 확인하고 외부 응답과 vector 저장이 끝날 때까지 전용 AI lease를 유지합니다. 제외 변경이 먼저 확정되면 본문을 로컬에서만 처리하고 회로 차단기를 열지 않으며, lease가 먼저 시작되면 제외 transaction이 호출 종료까지 기다리므로 이미 캡처한 본문이 새 정책을 넘어 전송되지 않습니다. 공간 범위 검색도 space와 현재 membership을 query embedding 호출 종료까지 잠가 제외·공유 회수가 먼저 적용된 검색어를 외부로 보내지 않습니다. 긴 임베딩 lease는 Dream·AI Assist와 같은 인스턴스당 최대 2개 전용 연결을 사용해 request pool을 고갈시키지 않습니다. 원격 Gateway가 실패하면 검색 SQL과 Canvas 연관 개수·연관 생각·군집도 한 알고리즘의 로컬 공간으로 맞춥니다. 첫 batch가 실패한 즉시 남은 batch를 로컬로 전환하고 5분간 회로 차단 상태를 사용해 batch마다 또는 Canvas를 열 때마다 긴 timeout이 반복되지 않습니다. 한 응답의 vector 차원이 하나라도 다르면 batch 전체를 잘못된 벡터 공간으로 거부하고 동일 차원의 로컬 폴백으로 전환합니다. 원격 알고리즘은 모델명과 정규화한 endpoint의 SHA-256 fingerprint를 함께 사용하므로 같은 모델명을 유지한 채 Gateway 주소를 바꿔도 이전 벡터를 재사용하지 않습니다. 원격 응답을 저장하는 첫 pass뿐 아니라 장애 뒤 모든 비교 대상을 로컬 vector로 다시 맞추는 두 번째 pass도 원래 settings-managed provider의 세대를 유지합니다. 각 저장 transaction이 현재 설정 행을 shared lock으로 확인하므로 두 pass 사이 또는 호출 중 설정이 바뀌면 이전 세대 결과를 폐기하고, 새 Gateway의 같은-version 벡터를 로컬 값으로 다시 덮지 않습니다. 콘텐츠 version이 낮은 결과도 알고리즘 차이만으로 최신 벡터를 교체할 수 없습니다.
- **원자적 AI 일일 한도**: 대화형 요청, 자동 Dream, 관리자 AI 평가 모두 실제 Gateway 호출 직전에 사용자별 PostgreSQL advisory lock 아래 자리를 선점하고 24시간 소비 원장으로 먼저 영속화합니다. 여러 replica의 동시 실행, 요청 취소, `ai_calls` 로그 실패에도 한도를 넘지 않습니다. Gateway 전에 버려진 대기 예약은 최대 35분 뒤 회수되고, 최종 source lease에서 접근권한·AI 제외 상태 변경을 발견한 경로는 아직 호출에 쓰지 않은 영속 claim을 즉시 취소합니다. 쿼터 저장소를 확인할 수 없으면 비용 보호를 위해 `503`으로 fail closed 합니다.
- **병렬 요청에도 정확한 로그인 상한**: 같은 주소나 계정을 공유하는 요청은 모든 replica가 함께 쓰는 PostgreSQL advisory transaction lock을 정렬된 순서로 얻습니다. 잠금 확인, 사용자 조회와 bcrypt 비밀번호 검증, 실패 횟수 기록 또는 session 저장을 같은 transaction 연결에서 끝내므로 `login_max_failures`개의 요청이 동시에 시작해도 각자 잠금 전 상태를 보고 상한 밖의 비밀번호를 더 검사하지 못합니다. 추가 연결을 빌리지 않아 `pool_max_conns=1`에서도 자신이 보유한 연결을 기다리지 않습니다. 로그인 성공 시에는 해당 계정의 실패 횟수만 초기화하고 주소별 실패 이력은 유지해, 공격자가 자신이 소유한 정상 계정으로 같은 IP의 credential-stuffing 횟수를 지우는 우회도 막습니다. 잠금 상태를 읽거나 기록할 수 없거나 보안 난수/session 저장 같은 내부 단계가 실패하면 잘못된 비밀번호로 세지 않고 transaction을 되돌린 뒤 `503`으로 fail closed 합니다.
- **구버전 관리자에서도 보존되는 보안 한도**: 보안 섹션의 whole-object PUT에서 새 필드를 모르는 구버전 client가 로그인 실패 횟수·잠금 시간·분당 API·분당 AI·하루 AI 한도를 생략하면, 서버가 설정별 PostgreSQL advisory transaction lock을 얻고 최신 확정 행에서 그 필드만 병합합니다. 동시에 저장한 관리자의 최신 값을 stale snapshot으로 지우지 않고, 명시한 `ai_daily_limit: 0`은 무제한 값으로 그대로 적용하며 `null`이나 범위 밖 값은 `400`으로 거부합니다. 롤링 업그레이드 중 키 scope나 회전 정책을 저장해도 이미 조정한 보호 수준이 기본값으로 조용히 돌아가지 않습니다.
- **부분·대용량 가져오기 초안 보존**: 마크다운 생각을 여러 개 가져오다 일부 요청이 실패해도 성공한 항목은 Canvas에 유지하고 실패한 항목만 편집기에 다시 구성합니다. 200개를 넘는 초안은 실제 개수를 안내하고 가져오기를 시작하지 않으며 201번째 이후 원문도 그대로 보존합니다. 가져오기 창을 닫거나 원문 전체를 지우지 않아 문서를 나누거나 네트워크·데이터베이스 일시 오류 뒤 안전하게 재시도할 수 있습니다.
- **원자적 개인 설정과 즉시 테마 적용**: 언어·테마처럼 서로 다른 부분 설정 요청이 겹쳐도 PostgreSQL row lock 안에서 최신 값에 순서대로 병합하므로 마지막 요청이 앞선 선택을 되돌리지 않습니다. 로그인 후 계정의 밝게·어둡게 설정을 현재 Mantine provider에 즉시 반영하고 `system`은 자동 모드로 복원해 이전 계정의 테마가 남지 않습니다.
- **HTML로 고정하고 릴리스마다 재검증하는 PWA 앱 셸**: 서비스 워커가 성공한 navigation 응답을 `/`에 저장할 때 `text/html`인지 확인하고 캐시 쓰기 완료까지 기다립니다. manifest·asset JSON·SVG를 주소창에서 직접 열어도 오프라인 앱 셸을 정적 파일로 덮어쓰지 않습니다. Vite의 8자 content hash가 붙은 `assets/` bundle만 1년 immutable로 제공하고 `/manifest.webmanifest`, `/umm-sw.js`, `/umm-icon.svg`, `/asset-manifest.json` 같은 고정 URL은 `no-cache`로 재검증해 새 릴리스의 start URL·shortcut·아이콘이 이전 값에 고정되지 않습니다.
- **업그레이드 중에도 보존되는 오프라인 변경**: 계정별 큐가 이미 만들어진 뒤 이전 앱 탭이 레거시 큐에 변경을 추가해도, 다음 인증 갱신이 두 큐를 공용 Web Lock 아래 생성 시각 순으로 병합한 뒤에만 레거시 키를 제거합니다. 같은 멱등 ID는 한 번만 유지하고 동일 리소스의 연속 PUT/PATCH는 최신 항목으로 합쳐 구버전 탭과 신버전 탭을 함께 열어 둔 배포 전환에서도 대기 변경이 사라지지 않습니다.
- **저장되지 않은 변경을 성공으로 표시하지 않는 오프라인 큐**: `localStorage`와 `sessionStorage` 접근을 공용 예외 경계 안에서 실행합니다. quota 초과나 private/sandbox 정책으로 쓰기가 실패하면 `offline-storage-unavailable`과 “오프라인 저장 실패” 안내를 반환하고 mutation을 `queued`로 표시하지 않습니다. Canvas는 메모마다 마지막 서버 확정 응답 또는 성공적으로 기록된 queue snapshot을 별도로 추적합니다. 비내구성 autosave 실패 뒤 더 최신 편집이 없으면 즉시 그 snapshot으로 화면을 복원해 메모가 저장된 것처럼 남지 않으며, 요청 도중 만들어진 새 편집은 객체 세대로 구분해 자신의 직렬화된 저장 시도까지 보존합니다. 저장소 읽기가 거부되어도 인증된 queue owner를 탭 메모리에 유지하고 언어·Canvas 연결선 설정과 Dream session marker도 안전한 폴백을 사용해 앱 bootstrap과 상태 표시를 계속합니다. 읽을 수 없거나 손상된 기존 큐를 빈 배열로 덮어쓰거나 계정 queue migration 중 레거시 키를 먼저 삭제하지 않습니다. flush 결과를 저장하지 못한 경우에도 성공한 것처럼 재시도 일정을 만들지 않고 사용자가 저장 공간·사이트 권한을 복구하도록 안내합니다.
- **권한 회수 뒤에도 진행하는 오프라인 큐**: 로그인 세션은 살아 있지만 공간에서 제거되었거나 원본 생각이 삭제되어 댓글 해결·재개·삭제를 더는 적용할 수 없으면 서버가 `comment-mutation-forbidden` 403 Problem Details를 반환합니다. 브라우저는 인증 복구 가능성이 있는 일반 401/403과 이 terminal type을 구분해 거부된 댓글 항목만 사유와 함께 제거하고 다음 mutation을 계속 replay합니다. 매 reconnect마다 같은 항목에서 멈춰 unrelated offline edit까지 동기화되지 않던 경로를 닫았습니다.
- **유료 AI 호출을 분리한 최소 권한 scope**: `/ai/assist`는 선택 note 본문을 외부 Gateway로 보내고 사용자 AI 쿼터를 소비하므로 이제 전용 `ai:assist` scope를 요구합니다. 일반 조회 자동화용 `notes:read` key는 AI Assist를 호출할 수 없습니다. 마이그레이션 009가 기존 관리자의 허용 scope 배열에 `ai:assist`를 중복 없이 추가해 개인 설정에서 실제 발급할 수 있게 하며, OpenAPI의 `x-required-scope`도 같은 경계를 선언합니다. 브라우저 session의 전체 권한 동작은 유지됩니다.
- **Prometheus 운영 지표의 명시적 권한 경계**: `/api/v1/metrics`는 관리자 브라우저 session 또는 정확히 `metrics:read` scope를 가진 API key만 허용합니다. 일반 사용자 session의 내부 wildcard는 더 이상 지표 scope를 암묵적으로 통과하지 않으며, 관리자 계정이 발급했더라도 `notes:read`처럼 다른 scope만 가진 key는 `403`으로 닫힙니다. 브라우저 관리자 운영과 최소 권한 모니터링 자동화를 각각 유지하면서 일반 사용자에게 route·latency·build 정보가 노출되지 않습니다.
- **Gateway 호출까지 유지되는 AI source lease**: AI Assist는 선택한 원본을, 자동 Dream은 현재 접근 가능한 사용자 작성 원본만 먼저 선별한 뒤 호출 직전에 note·space·membership을 다시 잠급니다. Dream 재생성·발전은 여기에 Dream 행과 Dream 공간도 포함합니다. 모든 관련 공간을 UUID 순서로 잠그고 외부 Gateway 호출이 끝날 때까지 lease를 유지하므로, 공유 회수나 AI 제외가 먼저 확정되면 영속화한 쿼터를 전용 pre-call 취소 경로로 되돌리고 본문을 보내지 않으며 lease가 먼저 시작되면 정책 변경은 호출 종료까지 기다립니다. 긴 lease는 request pool 밖의 인스턴스당 최대 2개 PostgreSQL 연결로 제한해 두 Gateway가 30분 timeout까지 지연되어도 readiness·인증·Canvas 요청 연결을 점유하지 않고, 세 번째 lease는 연결 없이 slot을 기다립니다. 자동 생성에서 품질을 통과한 Dream·source·알림도 같은 transaction에서 원자적으로 저장합니다.
- **HTTP 응답까지 유지되는 웹훅 authorization lease**: delivery를 선점한 워커는 `claimed_at` 세대가 정확히 일치하는지 확인하고 delivery·subscription·owner user·event space·membership 행을 실제 HTTP 응답과 모든 재시도가 끝날 때까지 잠급니다. 멤버십 회수·사용자 비활성화·구독 중지가 먼저 확정되면 외부 endpoint를 호출하지 않으며, 전달 lease가 먼저 시작되면 정책 변경 transaction은 terminal delivery 상태, payload 삭제, 구독 성공/실패 counter가 같은 transaction으로 확정될 때까지 기다립니다. 전달 slot을 얻기 전에 delivery를 `processing`으로 바꾸지 않고 row lock이 활성 전달의 만료 재선점을 막으므로, 용량 대기나 다른 replica가 오래된 claim으로 payload를 중복 전송하는 창도 닫았습니다. 웹훅 lease는 request pool 밖의 인스턴스당 최대 3개 연결로 제한됩니다.
- **공유 회수와 함께 닫히는 Dream 수명주기**: 공유 공간에서 사용자가 작성한 생각으로 생성된 개인 Dream도 현재 공간 접근권한 안에서만 보입니다. `/today`, Dream 검토함·상세·source query가 Dream의 `user_id`뿐 아니라 현재 공간 owner/member 조건을 함께 확인해, 멤버 제거 뒤 공간 이름·파생 AI 본문·근거·제안·원본 생각이 응답에 남지 않습니다. 피드백·노출·숨김은 Dream 행과 현재 membership을 같은 transaction에서 잠근 뒤 상태와 개인화 점수를 한 번에 확정합니다. 채택은 기존에 materialize된 Dream 재시도까지 편집권한을 먼저 잠급니다. 따라서 보관한 ID나 point-in-time 권한 조회로 상태·선호·메모·AI 호출을 만들 수 없습니다. 새 Dream 알림에는 공간 ID를 함께 저장하고, 이전 알림도 Dream 행에서 실제 공간을 찾아 목록·unread count를 거르므로 알림 본문으로 우회 노출되지 않습니다. 행 자체는 보존하므로 다시 공유되면 동일한 현재 권한 규칙으로 다시 표시됩니다.
- **난수 실패 시 닫히는 API 키 회전**: 새 secret과 prefix의 보안 난수 생성을 모두 확인한 뒤에만 교체 키를 저장합니다. 어느 단계든 난수 생성이 실패하거나 prefix가 비정상적으로 짧으면 교체 transaction을 중단해 약한 키 저장과 slice panic을 막고 기존 키 상태를 보존합니다. 키 생성과 회전이 같은 검증 경로를 사용합니다.
- **이전 AI prompt와 동시 설정 저장까지 끝나는 master-key 회전**: `enc:` wrapper 도입 전에 raw v1 암호문으로 저장된 AI prompt도 회전 대기 값에 포함하고 fallback key로 복호화해 현재 primary key의 `enc:v2.<key-id>...` 형식으로 다시 저장합니다. 접두사 없는 현재 v2 값도 wrapper를 정규화합니다. OIDC·AI Gateway의 마스킹 저장은 기존 secret을 요청 시점에 복사하지 않고 해당 필드를 생략한 뒤, 회전과 같은 설정별 PostgreSQL advisory transaction lock을 얻어 최신 암호문을 병합합니다. 회전 전에 열어 둔 관리 화면을 동시에 저장해도 이전 ciphertext가 새 값을 덮지 않으므로 `pendingRotation=0`, `unreadable=0` 확인 뒤 이전 키를 안전하게 제거할 수 있습니다.
- **예측 가능한 PostgreSQL 연결 상한과 작은 pool 교착 방지**: request pool 자동 최대값을 host CPU 수와 무관한 인스턴스당 16으로 제한하고, DSN의 명시적 `pool_max_conns`를 그대로 존중하면서 `pool_min_conns`만 상한 이하로 cap합니다. 상한 1~2에서는 전용 LISTEN을 비활성화해 모든 pool 연결을 request에 남기고, 상한 3부터도 request용 두 자리를 보존합니다. 긴 access lease는 이 pool과 분리해 AI 최대 2개, 웹훅 최대 3개 연결만 사용하므로 인스턴스 전체의 최악 상한은 `pool_max_conns + 5`이고 느린 Gateway나 웹훅 수신기가 일반 트래픽을 막지 않습니다. 각 상한을 넘는 lease는 새 DB 연결을 만들지 않고 slot을 기다립니다. 알림 endpoint와 짧은 Dream 채택 transaction은 request 연결을 중첩 점유하지 않습니다. 운영은 request 동시성과 worker 여유를 위해 `pool_max_conns` 4 이상을 권장하며 제공 compose는 16을 명시합니다.
- **다국어 User-Agent를 보존하는 세션 생성**: 로그인 header를 잘못된 UTF-8 제거 후 최대 300 byte로 제한하되 rune 경계에서만 자릅니다. 300번째 byte를 가로지르는 한국어·다국어 문자가 깨진 문자열로 PostgreSQL `text` INSERT를 실패시키고 올바른 자격 증명을 실패 시도로 누적하는 일을 막습니다. 직접 호출되는 세션 생성 경로도 같은 정규화를 다시 적용합니다.
- **UTF-8 안전한 외부 오류 기록**: 웹훅 전달 오류는 잘못된 byte를 제거하고 500 byte 안의 완전한 rune 경계로 제한한 뒤 delivery와 subscription을 같은 transaction에서 갱신합니다. 다국어 오류가 경계에서 잘려 PostgreSQL이 update 전체를 거부하고 delivery가 `processing`으로 되돌아가거나 연속 실패 횟수가 멈추는 일을 막습니다. AI 임베딩·Dream Gateway의 비정상 응답 본문도 같은 공용 경계 처리로 300 byte까지 제한하고, Dream 내부의 사용자·오류 문자열도 짧더라도 유효한 UTF-8로 정규화해 관리자 응답·작업 상태·AI 호출 로그 기록을 보호합니다.
- **현재 리소스만 집계하는 알림**: `resource_type='note'` 알림은 저장 당시의 공간 ID만 믿지 않고 현재 생각 행을 기준으로 soft-delete 상태와 실제 공간 owner/member 권한을 함께 확인합니다. 삭제된 생각의 댓글·멘션 본문은 목록과 unread count에서 모두 빠지며, `resource_space_id`가 없던 이전 note·Dream 알림도 각각 현재 생각 또는 Dream의 실제 공간으로 권한을 계산해 멤버 제거 뒤 노출되지 않습니다. 새 Dream 알림은 생성 시 공간 ID를 함께 기록합니다. 행을 지우지 않고 조회에서 동적으로 숨기므로 리소스 상태나 공유가 복원되면 알림도 같은 접근 규칙으로 다시 표시됩니다.
- **Today 검토 목록과 활동 설정 분리**: 개인 설정의 “리뷰 요약에 활동 포함”은 최근 댓글 활동 query만 제어합니다. 설정을 꺼도 고정한 생각, 다시 보기 시각이 된 생각, 14일 이상 검토하지 않은 생각은 기본 검토함과 개수에 계속 남아 빈 화면으로 오인하지 않습니다.

## 회귀 검증

암호문 변조 검증은 Base64 문자열의 마지막 문자를 바꾸는 방식 대신 디코딩된 인증 태그 byte를 직접 뒤집습니다. padding이 없는 Base64의 사용되지 않는 하위 bit만 달라져 원본 byte와 같아질 수 있던 간헐적 false failure를 제거하면서, AES-GCM 인증 실패 자체를 매 실행 확실히 검사합니다.

PostgreSQL 17 통합 테스트가 같은 로그인 세션으로 멤버 제거 전후를 직접 재현합니다.

- 제거 전에는 댓글·백링크·Canvas·수정 이력과 멤버 목록을 정상 조회합니다.
- 제거 직후에는 네 콘텐츠 경로와 멤버 목록이 모두 `404` 또는 `pgx.ErrNoRows`로 종료되는지 확인합니다.
- 다중 인스턴스 스모크 스크립트의 실행 권한을 복구해 CI가 실제 스크립트를 빠뜨리지 않고 실행합니다.
- Go race detector로 SSE publish/close 동시 실행을 반복하고 panic·data race가 없는지 확인합니다.
- 신뢰/비신뢰 proxy, 다단 `X-Forwarded-For`, IPv6, 잘못된 header의 fail-closed 동작을 단위 테스트합니다.
- HTTPS/HTTP 동일 Origin, 기본 443 port, 다른 scheme·port, credential 포함 Origin과 신뢰 proxy scheme을 단위 테스트해 cross-scheme session write가 거부되는지 확인합니다.
- 서로 다른 두 Store 연결에서 12개 AI 쿼터 요청을 동시에 시작해 정확히 하나만 한도 1을 예약하는 PostgreSQL 17 통합 테스트를 수행합니다.
- 원격 embedding 오류가 실제 local algorithm label과 vector를 함께 반환하는지 검증합니다.
- 원격 Gateway가 같은 응답에 2차원·3차원 vector를 섞으면 strict 검사는 오류를 반환하고 일반 호출은 두 입력 모두 동일한 로컬 차원으로 폴백하는지 확인합니다.
- 자동 Dream Gateway 경로가 소진된 일일 한도에서 외부 요청을 한 번도 보내지 않는지, 소비 원장이 `ai_calls` 없이도 유지되는지 검증합니다.
- 요청 context를 취소한 뒤에도 AI 호출 관측 로그가 독립 context로 기록되는지 확인합니다.
- 일부 원격 vector만 남은 상태에서 장애가 나도 Canvas 비교 집합 전체가 하나의 로컬 알고리즘으로 정규화되는지 검증합니다.
- 로컬 폴백 vector가 최신이면 5분 회로 차단 안에서 실패한 Gateway를 다시 호출하지 않고, 재시도 시점 뒤에는 복구 확인을 한 번 수행하는지 검증합니다.
- 부분 가져오기 실패 후 가져오기 창이 열린 채로 실패한 생각만 마크다운 편집기에 남고, 그 초안을 다시 분해해도 내용이 보존되는지 검증합니다.
- 201개 이상의 마크다운 초안은 실제 개수를 표시하고 가져오기를 비활성화하며, 마지막 항목까지 편집기와 parser 결과에 남는지 검증합니다.
- 66개 메모의 첫 원격 embedding batch가 실패하면 두 번째 batch는 원격 호출 없이 즉시 로컬로 완료되는지 확인합니다.

## 업그레이드

릴리스의 `SHA256SUMS`를 확인한 뒤 오프라인 이미지를 로드하고 기존 네 필수 환경변수와 데이터베이스를 그대로 사용하세요.

```bash
sha256sum -c SHA256SUMS
gzip -dc umm-v0.8.1.tar.gz | docker load

docker run -d --name umm --restart unless-stopped \
  -p 8080:8080 \
  -e POSTGRES_DSN='postgres://umm:password@postgres.internal:5432/umm?sslmode=require' \
  -e BOOTSTRAP_ADMIN='admin' \
  -e BOOTSTRAP_ADMIN_PASSWORD='your-strong-password' \
  -e ENCRYPTION_KEY='your-32-char-random-encryption-key' \
  umm:v0.8.1
```

마이그레이션 008은 `ai_quota_reservations`와 만료·원본 호출 조회 index를 생성하고 업그레이드 직전 24시간의 `ai_calls`를 한 번만 원장에 반영합니다. 마이그레이션 009는 기존 허용 API key scope를 보존하면서 `ai:assist`를 중복 없이 추가합니다. 둘 다 기동 시 자동 적용됩니다. 업그레이드 전 PostgreSQL 백업과 현재 암호화 키를 별도 보관하고, 배포 후 `/healthz`, `/readyz`, 로그인, Canvas 조회, `notes:read` key의 AI Assist `403`, `ai:assist` key의 정상 scope 통과와 AI 한도 응답을 확인하세요. Prometheus 수집은 `metrics:read` 전용 key로 확인하고 일반 사용자 session과 다른 scope key가 `403`인지도 점검하세요.

TLS 종료 proxy를 사용하는 경우에만 다음 값을 추가합니다. 직접 배포에서는 생략하는 것이 안전한 기본값입니다.

