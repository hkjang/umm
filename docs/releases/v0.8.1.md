# umm v0.8.1 — 권한·동시성 경계를 끝까지 지키는 패치

v0.8.1은 v0.8.0의 규모·보안·접근성 개선을 그대로 유지하면서, 협업 멤버가 제거되는 바로 그 순간에도 이전 권한으로 콘텐츠가 반환되거나 변경되지 않도록 접근 경계를 강화한 보안·신뢰성 패치입니다. 릴리스 전 자동 리뷰에서 발견한 실시간 알림 경합, proxy header 신뢰, 임베딩 개인정보·장애 폴백·설정 전환 경합, 다중 인스턴스 AI 쿼터 경합, 로그인 제한 우회, API 키 난수 실패, 부분 가져오기 초안 유실도 함께 닫았습니다.

필수 환경변수 네 개는 그대로입니다. TLS 종료 proxy를 사용하는 배포만 선택 환경변수 `UMM_TRUSTED_PROXY_CIDRS`에 직접 연결되는 proxy IP/CIDR을 지정해야 forwarding header를 인정합니다. 마이그레이션 008은 기동 시 자동 적용되며 AI 쿼터의 대기 예약과 24시간 소비 원장을 추가합니다.

---

## 원자적 콘텐츠 권한 확인

기존 구현 일부는 공간 접근권한을 먼저 확인하고 다음 쿼리에서 콘텐츠를 읽었습니다. 두 statement 사이에 관리자가 멤버를 제거하면, 이미 통과한 확인 결과로 짧은 시간 동안 본문이 반환될 가능성이 있었습니다.

이제 다음 조회는 **콘텐츠를 읽는 PostgreSQL statement 자체**에 현재 공간 owner/member 조건을 결합합니다.

- Canvas 생각 목록과 연결선
- 생각 수정 이력
- 댓글과 답글
- 들어오는 링크·나가는 링크(백링크)
- 공간 멤버 목록

공간이나 생각이 실제로 비어 있는 경우와 접근권한이 사라진 경우도 구분합니다. 접근 가능한 빈 목록은 정상적으로 빈 배열을 반환하고, 제거된 멤버의 요청은 `404`로 닫힙니다. 데이터베이스 일시 오류는 권한 없음으로 숨기지 않고 `500`으로 기록·응답해 운영자가 원인을 찾을 수 있습니다.

댓글 삭제도 같은 경계를 적용합니다. 작성자는 현재 공간 멤버인 동안에만 자신의 댓글을 삭제할 수 있고, 공간에서 제거된 뒤 보관한 댓글 ID로 삭제 이벤트나 webhook을 만들 수 없습니다. 공간 owner와 현재 `manage` 멤버의 관리 권한은 유지됩니다.

## 내보내기 경계 강화

공간 내보내기는 생각 목록을 가져올 때 현재 접근권한을 확인하고, 응답 파일을 쓰기 직전에 공간 이름을 조회할 때도 권한을 다시 확인합니다. 승인 대기와 실제 다운로드 사이에 공유가 취소된 경우에도 내보내기 본문이 전송되지 않습니다.

## 동시성과 네트워크 신뢰 경계 강화

- **실시간 SSE fan-out**: 구독 해제와 알림 publish가 겹칠 때 닫힌 채널로 전송해 프로세스가 panic할 수 있던 경로를 제거했습니다. 구독은 레지스트리에서만 제거하고 요청 context가 reader 수명을 끝냅니다.
- **신뢰할 proxy만 전달 헤더 사용**: 기본값에서는 모든 `X-Forwarded-For`, `X-Real-IP`, `X-Forwarded-Proto`를 무시합니다. 명시한 proxy 대역에서 온 요청만 오른쪽부터 신뢰 체인을 검증해 실제 client IP를 정하므로, 외부 클라이언트가 로그인/API rate limit이나 HTTPS 판단을 header로 우회할 수 없습니다.
- **개인정보와 벡터 공간을 지키는 빠른 임베딩 폴백**: 메모나 공간에서 AI 제외를 켜면 선택적 임베딩 모델이 설정되어 있어도 본문을 외부 Gateway에 보내지 않고 전체 비교 집합을 로컬 vector로 처리합니다. AI 제외 공간으로 범위를 제한한 검색도 접근권한과 제외 상태를 먼저 확인하고 검색어를 로컬에서 임베딩하므로 민감한 검색 문구가 Gateway로 나가지 않습니다. 원격 Gateway가 실패하면 검색 SQL과 Canvas 연관 개수·연관 생각·군집도 한 알고리즘의 로컬 공간으로 맞춥니다. 첫 batch가 실패한 즉시 남은 batch를 로컬로 전환하고 5분간 회로 차단 상태를 사용해 batch마다 또는 Canvas를 열 때마다 긴 timeout이 반복되지 않습니다. 원격 알고리즘은 모델명과 정규화한 endpoint의 SHA-256 fingerprint를 함께 사용하므로 같은 모델명을 유지한 채 Gateway 주소를 바꿔도 이전 벡터를 재사용하지 않습니다. 저장 transaction이 현재 설정 행을 잠그고 endpoint·모델 세대를 다시 확인하므로, 설정 변경 전에 시작해 늦게 도착한 응답은 폐기되고 새 Gateway의 벡터를 덮어쓰지 못합니다. 콘텐츠 version이 낮은 결과도 알고리즘 차이만으로 최신 벡터를 교체할 수 없습니다.
- **원자적 AI 일일 한도**: 대화형 요청, 자동 Dream, 관리자 AI 평가 모두 실제 Gateway 호출 직전에 사용자별 PostgreSQL advisory lock 아래 자리를 선점하고 24시간 소비 원장으로 먼저 영속화합니다. 여러 replica의 동시 실행, 요청 취소, `ai_calls` 로그 실패에도 한도를 넘지 않습니다. Gateway 전에 버려진 대기 예약은 최대 35분 뒤 회수되며, 쿼터 저장소를 확인할 수 없으면 비용 보호를 위해 `503`으로 fail closed 합니다.
- **로그인 주소 제한 유지**: 로그인 성공 시 해당 계정의 실패 횟수만 초기화하고 주소별 실패 이력은 유지합니다. 공격자가 자신이 소유한 정상 계정에 로그인해 같은 IP에서 다른 계정에 누적한 credential-stuffing 횟수를 지우는 우회를 막습니다.
- **부분 가져오기 초안 보존**: 마크다운 생각을 여러 개 가져오다 일부 요청이 실패해도 성공한 항목은 Canvas에 유지하고 실패한 항목만 편집기에 다시 구성합니다. 가져오기 창을 닫거나 원문 전체를 지우지 않아 네트워크·데이터베이스 일시 오류 뒤 안전하게 재시도할 수 있습니다.
- **원자적 개인 설정과 즉시 테마 적용**: 언어·테마처럼 서로 다른 부분 설정 요청이 겹쳐도 PostgreSQL row lock 안에서 최신 값에 순서대로 병합하므로 마지막 요청이 앞선 선택을 되돌리지 않습니다. 로그인 후 계정의 밝게·어둡게 설정을 현재 Mantine provider에 즉시 반영하고 `system`은 자동 모드로 복원해 이전 계정의 테마가 남지 않습니다.
- **HTML로 고정한 PWA 앱 셸**: 서비스 워커가 성공한 navigation 응답을 `/`에 저장할 때 `text/html`인지 확인하고 캐시 쓰기 완료까지 기다립니다. manifest·asset JSON·SVG를 주소창에서 직접 열어도 오프라인 앱 셸을 정적 파일로 덮어쓰지 않습니다.
- **난수 실패 시 닫히는 API 키 회전**: 새 secret과 prefix의 보안 난수 생성을 모두 확인한 뒤에만 교체 키를 저장합니다. 어느 단계든 난수 생성이 실패하거나 prefix가 비정상적으로 짧으면 교체 transaction을 중단해 약한 키 저장과 slice panic을 막고 기존 키 상태를 보존합니다. 키 생성과 회전이 같은 검증 경로를 사용합니다.

## 회귀 검증

PostgreSQL 17 통합 테스트가 같은 로그인 세션으로 멤버 제거 전후를 직접 재현합니다.

- 제거 전에는 댓글·백링크·Canvas·수정 이력과 멤버 목록을 정상 조회합니다.
- 제거 직후에는 네 콘텐츠 경로와 멤버 목록이 모두 `404` 또는 `pgx.ErrNoRows`로 종료되는지 확인합니다.
- 다중 인스턴스 스모크 스크립트의 실행 권한을 복구해 CI가 실제 스크립트를 빠뜨리지 않고 실행합니다.
- Go race detector로 SSE publish/close 동시 실행을 반복하고 panic·data race가 없는지 확인합니다.
- 신뢰/비신뢰 proxy, 다단 `X-Forwarded-For`, IPv6, 잘못된 header의 fail-closed 동작을 단위 테스트합니다.
- 서로 다른 두 Store 연결에서 12개 AI 쿼터 요청을 동시에 시작해 정확히 하나만 한도 1을 예약하는 PostgreSQL 17 통합 테스트를 수행합니다.
- 원격 embedding 오류가 실제 local algorithm label과 vector를 함께 반환하는지 검증합니다.
- 자동 Dream Gateway 경로가 소진된 일일 한도에서 외부 요청을 한 번도 보내지 않는지, 소비 원장이 `ai_calls` 없이도 유지되는지 검증합니다.
- 요청 context를 취소한 뒤에도 AI 호출 관측 로그가 독립 context로 기록되는지 확인합니다.
- 일부 원격 vector만 남은 상태에서 장애가 나도 Canvas 비교 집합 전체가 하나의 로컬 알고리즘으로 정규화되는지 검증합니다.
- 로컬 폴백 vector가 최신이면 5분 회로 차단 안에서 실패한 Gateway를 다시 호출하지 않고, 재시도 시점 뒤에는 복구 확인을 한 번 수행하는지 검증합니다.
- 부분 가져오기 실패 후 가져오기 창이 열린 채로 실패한 생각만 마크다운 편집기에 남고, 그 초안을 다시 분해해도 내용이 보존되는지 검증합니다.
- 66개 메모의 첫 원격 embedding batch가 실패하면 두 번째 batch는 원격 호출 없이 즉시 로컬로 완료되는지 확인합니다.
- 메모별·공간별 AI 제외 본문과 AI 제외 공간으로 범위를 제한한 검색어가 원격 embedding Gateway를 한 번도 호출하지 않고 로컬 vector만 사용하는지 검증합니다. 같은 사용자의 일반 공간 검색은 구성한 Gateway를 계속 사용하는지도 함께 확인합니다.
- 다른 계정의 정상 로그인 전후에 두 인스턴스로 나눠 보낸 실패 횟수가 같은 IP에서 이어져 설정한 주소 잠금에 도달하는지 확인합니다.
- 일일 한도를 모두 쓴 관리자의 AI 평가가 Gateway를 호출하지 않고 동일한 쿼터 오류로 종료되는지 검증합니다.
- 언어와 테마의 두 부분 요청이 같은 저장값을 읽도록 의도적으로 멈춘 뒤 동시에 재개해도 최종 행에 두 변경이 모두 보존되는지 검증합니다.
- 로그인 계정의 `dark`와 `system` 테마가 현재 Mantine provider, 문서 color-scheme 속성, 다음 로드를 위한 저장값에 함께 반영되는지 검증합니다.
- 같은 embedding 모델명을 유지한 채 서로 다른 Gateway로 전환하면 알고리즘 식별자와 vector 차원이 바뀌고, 내용 version이 같아도 새 endpoint에서 다시 임베딩되는지 검증합니다.
- 이전 Gateway 응답을 의도적으로 멈춘 상태에서 같은 모델명의 새 Gateway로 전환한 뒤 새 vector를 먼저 저장하고, 늦게 재개한 이전 응답과 더 낮은 콘텐츠 version이 현재 행을 덮어쓰지 못하는지 PostgreSQL 17에서 검증합니다.
- 빌드된 서비스 워커를 모의 Cache Storage에서 실행해 manifest navigation은 기존 HTML 셸을 보존하고 앱 경로의 HTML navigation만 셸을 갱신하는지 검증합니다.
- 현재 멤버인 댓글 작성자는 자신의 댓글을 삭제할 수 있지만, 멤버 제거 뒤 같은 댓글 ID로 재시도하면 행·실시간 이벤트·webhook outbox가 모두 변경되지 않는지 검증합니다.
- API 키 secret 또는 prefix 난수 생성 실패와 비정상적으로 짧은 prefix가 빈 키 자료와 오류를 반환하고, 정상 난수만 완전한 `umm_key_...` 형식으로 조립되는지 단위 테스트합니다.

## 업그레이드

릴리스의 `SHA256SUMS`를 확인한 뒤 오프라인 이미지를 로드하고 기존 네 필수 환경변수와 데이터베이스를 그대로 사용하세요.

```bash
sha256sum -c SHA256SUMS
gzip -dc umm-v0.8.1.tar.gz | docker load

docker run -d --name umm --restart unless-stopped \
  -p 8080:8080 \
  -e POSTGRES_DSN='postgres://umm:password@postgres.internal:5432/umm?sslmode=require' \
  -e BOOTSTRAP_ADMIN='admin' \
  -e BOOTSTRAP_ADMIN_PASSWORD='your-strong-password' \
  -e ENCRYPTION_KEY='your-32-char-random-encryption-key' \
  umm:v0.8.1
```

마이그레이션 008은 자동 적용되며 `ai_quota_reservations`와 만료·원본 호출 조회 index를 생성하고, 업그레이드 직전 24시간의 `ai_calls`를 한 번만 원장에 반영합니다. 업그레이드 전 PostgreSQL 백업과 현재 암호화 키를 별도 보관하고, 배포 후 `/healthz`, `/readyz`, 로그인, Canvas 조회와 AI 한도 응답을 확인하세요.

TLS 종료 proxy를 사용하는 경우에만 다음 값을 추가합니다. 직접 배포에서는 생략하는 것이 안전한 기본값입니다.

```bash
-e UMM_TRUSTED_PROXY_CIDRS='10.42.0.0/16,fd00:42::/64'
```

수동 rollback이 꼭 필요하면 백업을 확인한 운영자가 008, 007 순서로 down script를 실행해야 합니다. 자동 rollback은 수행되지 않습니다.
