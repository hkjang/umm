# umm v0.8.1 — 권한·동시성 경계를 끝까지 지키는 패치

v0.8.1은 v0.8.0의 규모·보안·접근성 개선을 그대로 유지하면서, 협업 멤버가 제거되는 바로 그 순간에도 이전 권한으로 콘텐츠가 반환되지 않도록 읽기 경계를 강화한 보안·신뢰성 패치입니다. 릴리스 전 자동 리뷰에서 발견한 실시간 알림 경합, proxy header 신뢰, 임베딩 장애 폴백, 다중 인스턴스 AI 쿼터 경합, 부분 가져오기 초안 유실도 함께 닫았습니다.

필수 환경변수 네 개는 그대로입니다. TLS 종료 proxy를 사용하는 배포만 선택 환경변수 `UMM_TRUSTED_PROXY_CIDRS`에 직접 연결되는 proxy IP/CIDR을 지정해야 forwarding header를 인정합니다. 마이그레이션 008은 기동 시 자동 적용되며 AI 쿼터의 대기 예약과 24시간 소비 원장을 추가합니다.

---

## 원자적 콘텐츠 권한 확인

기존 구현 일부는 공간 접근권한을 먼저 확인하고 다음 쿼리에서 콘텐츠를 읽었습니다. 두 statement 사이에 관리자가 멤버를 제거하면, 이미 통과한 확인 결과로 짧은 시간 동안 본문이 반환될 가능성이 있었습니다.

이제 다음 조회는 **콘텐츠를 읽는 PostgreSQL statement 자체**에 현재 공간 owner/member 조건을 결합합니다.

- Canvas 생각 목록과 연결선
- 생각 수정 이력
- 댓글과 답글
- 들어오는 링크·나가는 링크(백링크)
- 공간 멤버 목록

공간이나 생각이 실제로 비어 있는 경우와 접근권한이 사라진 경우도 구분합니다. 접근 가능한 빈 목록은 정상적으로 빈 배열을 반환하고, 제거된 멤버의 요청은 `404`로 닫힙니다. 데이터베이스 일시 오류는 권한 없음으로 숨기지 않고 `500`으로 기록·응답해 운영자가 원인을 찾을 수 있습니다.

## 내보내기 경계 강화

공간 내보내기는 생각 목록을 가져올 때 현재 접근권한을 확인하고, 응답 파일을 쓰기 직전에 공간 이름을 조회할 때도 권한을 다시 확인합니다. 승인 대기와 실제 다운로드 사이에 공유가 취소된 경우에도 내보내기 본문이 전송되지 않습니다.

## 동시성과 네트워크 신뢰 경계 강화

- **실시간 SSE fan-out**: 구독 해제와 알림 publish가 겹칠 때 닫힌 채널로 전송해 프로세스가 panic할 수 있던 경로를 제거했습니다. 구독은 레지스트리에서만 제거하고 요청 context가 reader 수명을 끝냅니다.
- **신뢰할 proxy만 전달 헤더 사용**: 기본값에서는 모든 `X-Forwarded-For`, `X-Real-IP`, `X-Forwarded-Proto`를 무시합니다. 명시한 proxy 대역에서 온 요청만 오른쪽부터 신뢰 체인을 검증해 실제 client IP를 정하므로, 외부 클라이언트가 로그인/API rate limit이나 HTTPS 판단을 header로 우회할 수 없습니다.
- **일관되고 빠른 임베딩 폴백**: 원격 임베딩 Gateway가 실패해 로컬 vector로 폴백하면 검색 SQL도 로컬 algorithm 행만 선택합니다. Canvas 연관 개수·연관 생각·군집은 비교 대상 전체를 로컬 공간으로 다시 맞춘 뒤 한 알고리즘의 vector만 읽습니다. 장애 감지 후 5분간 로컬 회로 차단 상태를 사용해 Canvas를 열 때마다 긴 원격 timeout이 반복되지 않으며, 설정 변경 시 즉시 새 Gateway를 확인합니다.
- **원자적 AI 일일 한도**: 대화형 요청과 자동 Dream 모두 실제 Gateway 호출 직전에 사용자별 PostgreSQL advisory lock 아래 자리를 선점하고 24시간 소비 원장으로 먼저 영속화합니다. 여러 replica의 동시 실행, 요청 취소, `ai_calls` 로그 실패에도 한도를 넘지 않습니다. Gateway 전에 버려진 대기 예약은 최대 35분 뒤 회수되며, 쿼터 저장소를 확인할 수 없으면 비용 보호를 위해 `503`으로 fail closed 합니다.
- **부분 가져오기 초안 보존**: 마크다운 생각을 여러 개 가져오다 일부 요청이 실패해도 성공한 항목은 Canvas에 유지하고 실패한 항목만 편집기에 다시 구성합니다. modal을 닫거나 원문 전체를 지우지 않아 네트워크·데이터베이스 일시 오류 뒤 안전하게 재시도할 수 있습니다.

## 회귀 검증

PostgreSQL 17 통합 테스트가 같은 로그인 세션으로 멤버 제거 전후를 직접 재현합니다.

- 제거 전에는 댓글·백링크·Canvas·수정 이력과 멤버 목록을 정상 조회합니다.
- 제거 직후에는 네 콘텐츠 경로와 멤버 목록이 모두 `404` 또는 `pgx.ErrNoRows`로 종료되는지 확인합니다.
- 다중 인스턴스 스모크 스크립트의 실행 권한을 복구해 CI가 실제 스크립트를 빠뜨리지 않고 실행합니다.
- Go race detector로 SSE publish/close 동시 실행을 반복하고 panic·data race가 없는지 확인합니다.
- 신뢰/비신뢰 proxy, 다단 `X-Forwarded-For`, IPv6, 잘못된 header의 fail-closed 동작을 단위 테스트합니다.
- 서로 다른 두 Store 연결에서 12개 AI 쿼터 요청을 동시에 시작해 정확히 하나만 한도 1을 예약하는 PostgreSQL 17 통합 테스트를 수행합니다.
- 원격 embedding 오류가 실제 local algorithm label과 vector를 함께 반환하는지 검증합니다.
- 자동 Dream Gateway 경로가 소진된 일일 한도에서 외부 요청을 한 번도 보내지 않는지, 소비 원장이 `ai_calls` 없이도 유지되는지 검증합니다.
- 요청 context를 취소한 뒤에도 AI 호출 관측 로그가 독립 context로 기록되는지 확인합니다.
- 일부 원격 vector만 남은 상태에서 장애가 나도 Canvas 비교 집합 전체가 하나의 로컬 알고리즘으로 정규화되는지 검증합니다.
- 로컬 폴백 vector가 최신이면 5분 회로 차단 안에서 실패한 Gateway를 다시 호출하지 않고, 재시도 시점 뒤에는 복구 확인을 한 번 수행하는지 검증합니다.
- 부분 가져오기 실패 후 modal이 열린 채로 실패한 생각만 마크다운 편집기에 남고, 그 초안을 다시 분해해도 내용이 보존되는지 검증합니다.

## 업그레이드

릴리스의 `SHA256SUMS`를 확인한 뒤 오프라인 이미지를 로드하고 기존 네 필수 환경변수와 데이터베이스를 그대로 사용하세요.

```bash
sha256sum -c SHA256SUMS
gzip -dc umm-v0.8.1.tar.gz | docker load

docker run -d --name umm --restart unless-stopped \
  -p 8080:8080 \
  -e POSTGRES_DSN='postgres://umm:password@postgres.internal:5432/umm?sslmode=require' \
  -e BOOTSTRAP_ADMIN='admin' \
  -e BOOTSTRAP_ADMIN_PASSWORD='your-strong-password' \
  -e ENCRYPTION_KEY='your-32-char-random-encryption-key' \
  umm:v0.8.1
```

마이그레이션 008은 자동 적용되며 `ai_quota_reservations`와 만료·원본 호출 조회 index를 생성하고, 업그레이드 직전 24시간의 `ai_calls`를 한 번만 원장에 반영합니다. 업그레이드 전 PostgreSQL 백업과 현재 암호화 키를 별도 보관하고, 배포 후 `/healthz`, `/readyz`, 로그인, Canvas 조회와 AI 한도 응답을 확인하세요.

TLS 종료 proxy를 사용하는 경우에만 다음 값을 추가합니다. 직접 배포에서는 생략하는 것이 안전한 기본값입니다.

```bash
-e UMM_TRUSTED_PROXY_CIDRS='10.42.0.0/16,fd00:42::/64'
```

수동 rollback이 꼭 필요하면 백업을 확인한 운영자가 008, 007 순서로 down script를 실행해야 합니다. 자동 rollback은 수행되지 않습니다.
