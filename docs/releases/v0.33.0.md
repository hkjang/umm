# v0.33.0 — 첫 화면 숫자가 진짜 개수가 아니었습니다

v0.32.2에서 결정 기록이 조용히 끊기는 걸 고쳤습니다. 그래서 **umm이 자르는 자리를 전부** 찾아
하나씩 봤습니다.

첫 화면에 있었습니다.

## 연결 대기 6

생각 2,010개짜리 공간을 열었습니다. `오늘의 리뷰` 요약 타일이 이렇게 말합니다.

```
연결 대기   6
```

데이터베이스에 직접 물어봤습니다.

```
2006
```

## 왜 그랬나

각 목록 질의에 `LIMIT 5~8`이 붙어 있고, 타일 숫자는 그 **잘린 목록의 길이**였습니다.

```go
out.Counts["orphans"] = len(out.Orphans)   // 6
```

목록이 미리보기인 건 맞습니다 — 여섯 개만 보여 주는 건 괜찮습니다. 문제는 **타일이 개수처럼
생겼다는 것**입니다. "연결 대기" 옆의 숫자를 총계 말고 다르게 읽을 방법이 없습니다.

## 지금은

타일은 세고, 목록은 미리보기로 남습니다.

```
연결 대기   2006      (아래 목록은 여전히 6개)
```

네 타일 모두 각자 목록의 **WHERE 절을 그대로** 반복합니다. 조건이 다른 개수는 잘린 개수보다
나쁩니다 — 숫자와 목록이 서로 어긋나는데 둘 다 이상해 보이지 않으니까요.

한 번의 왕복으로 넉넉히 처리됩니다.

```
/today   0.014s   (2,010개 공간)
```

## 확인한 것

- 목록 상한을 넘긴 공간에서 타일이 총계를 말하고 목록은 상한을 지키는지 통합 테스트로 고정
- 타일 숫자가 아래 목록보다 작아지지 않는지 고정
- 실제 2,010개 공간에서 `6 → 2006` 확인
- 전체 Go 테스트 통과
