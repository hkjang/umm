# v0.31.0 — 되짚기가 큰 공간에서 조용히 꺼져 있었습니다

v0.30.1에서 배운 것을 나머지에 적용했습니다. **API로만 확인한 것을 브라우저로 다시 봤습니다.**

v0.23.0 조력자는 정상이었습니다. 되짚기(v0.27.0)는 아니었습니다.

## 두 가지가 겹쳐 있었습니다

### 1. 흔한 중복이 중요한 것을 밀어냈습니다

오늘의 리뷰는 중복 쌍을 **유사도 순으로 10개**만 보여 줍니다. 비슷한 문장이 많은 공간에서는
평범한 중복이 열 자리를 다 차지하고, **거절한 결정을 다시 쓰고 있다는 신호가 밀려납니다.**

*"이거 두 번 적었어요"*와 *"이미 하지 않기로 한 걸 다시 쓰고 있어요"*는 같은 소식이 아닙니다.
뒤의 것에만 **이유가 붙어 있고**, 그 이유가 필요한 겁니다.

이제 표시된 쌍이 먼저 옵니다. 나머지는 유사도 순 그대로입니다.

### 2. v0.30.0이 되짚기에 구멍을 냈습니다

바로 앞 릴리스에서 한 공간당 **최근 1,000개**만 비교하도록 막았습니다. 중복은 거의 언제나 최근
쪽에 있으니까요.

**되짚기는 아닙니다.** 되짚기는 *오늘 쓴 것*과 *오래전에 접어 둔 것*을 짝짓습니다. 오래된 쪽이
최근 창 밖에 있으면 **쌍이 아예 만들어지지 않습니다.**

즉 v0.30.0은 이 기능을, **그것이 가장 필요한 오래된 공간에서 조용히 껐습니다.** 제가 v0.30.0
릴리스 노트에 "큰 공간이야말로 이미 거절한 결정을 다시 쓸 가능성이 높은 곳"이라고 써 놓고서요.

접어 둔 갈래의 생각은 이제 최근 창과 **교차 비교**로 따로 들어옵니다. 전체를 다시 도는 게 아니라
*"새로 쓴 것이 접어 둔 것의 반복인가"*만 묻는 곱셈이라 비용이 작습니다.

## 실측으로 확인했습니다

생각 2,010개짜리 공간, 접어 둔 갈래는 **가장 오래된 쪽**에 있습니다.

고치기 전 — 오늘의 리뷰 중복 10개 전부 `setAside: None`.

고친 뒤, 오늘 반복되는 생각을 하나 적자:

```
1.000  | setAside: 젠킨스 직접 운영 | 플러그인 호환 부담이 통제권으로 얻는 것보다 컸습니다
0.984  | setAside: None
0.983  | setAside: None
```

브라우저에서도 확인했습니다:

```
접어 둔 갈래를 다시 쓰고 있습니다 · 젠킨스 직접 운영
배포 파이프라인을 젠킨스로 직접 운영하면 통제권을 가져올 수 있다
접어 둔 이유: 플러그인 호환 부담이 통제권으로 얻는 것보다 컸습니다
```

## 덤: 경계가 비교만 줄이고 읽기는 그대로였습니다

같은 자리를 재 보니 오늘의 리뷰가 **3.35초**였습니다. 첫 화면이 그 시간을 기다립니다.

v0.30.0의 경계는 `ListNotes`로 **공간 전체를 읽은 뒤** 1,000개로 잘랐습니다. 즉 2,010개 생각과
그 연결을 전부 읽어서 1,000개만 쓰고 버렸습니다. **비교는 줄었고 읽기는 그대로였습니다.**

필요한 만큼만 읽는 질의로 바꿨습니다.

```
3.352s → 0.428s
```

되짚기는 그대로 1순위입니다.

## 왜 미리 못 봤나

v0.27.0을 만들 때는 작은 공간에서 확인했습니다. v0.30.0에서 경계를 넣을 때는 **중복만 생각하고
되짚기를 생각하지 않았습니다.** 두 기능이 같은 코드 경로를 공유한다는 걸 알면서도요.

큰 공간에 실제 데이터를 넣고 화면을 열어 봐야 보였습니다.

## 확인한 것

- 전체 Go 테스트 통과, 웹 53개 통과
- 순위 규칙은 백엔드 없이 도는 단위 테스트로 고정 — 표시된 쌍이 앞서고, 나머지는 순서 유지
- 2,010개 공간에서 실제로 되짚기가 1순위로 나오는지 API와 브라우저 양쪽에서 확인
- 오늘의 리뷰 3.352s → 0.428s (같은 공간, 같은 결과)
- 최근 쪽을 읽는지, 경계 아래 공간은 자르지 않는지 실제 질의로 고정
