# v0.38.0 — 생각을 발표 자료로, 내가 쓴 문장 그대로

umm이 [Ptium](https://github.com/hkjang/ptium)으로 발표 자료를 만듭니다.

"PPT 만들기" 버튼이 아니라 **생각 그래프를 발표 구성으로 컴파일하는 것**입니다. 그 차이가
이 릴리스의 거의 전부입니다.

## 모델이 다시 쓰지 않습니다

Ptium에 들어가는 길은 둘입니다.

| | `prompt` | **덱 소스** |
| --- | --- | --- |
| 슬라이드 문장 | **모델이 새로 씀** | **본인이 쓴 그대로** |
| 분량 | 12000자 상한 | 없음 |
| 같은 공간을 두 번 | 매번 다름 | **항상 같은 덱** |
| 미리보기 | 불가 | 실물 |

`PresentationCreate` 스키마는 `additionalProperties: false`에 평문 `prompt` 하나만 받습니다.
노트 100개짜리 공간이면 본문만으로 상한에 닿고, 연결은 갈 자리가 없습니다.

**umm은 Ptium에 prompt를 단 한 번도 보내지 않습니다.** 요청에 `prompt`가 나타나면 테스트가
실패합니다. 대신 `PUT /presentations/{id}/source`로 덱 소스를 컴파일합니다.

몇 달 뒤에 읽었을 때 내가 생각한 것과 모델이 쓴 것을 **구분할 수 없는 것** — umm이 처음부터
막으려던 그 해악은 슬라이드에서도 똑같습니다.

## 관계 어휘가 이미 발표 구조였습니다

| umm에 기록해 둔 것 | 슬라이드 |
| --- | --- |
| `follows` | 발표 순서 |
| `supports` · `refines` | 주장 아래 근거 |
| `answers` | 질문 슬라이드의 내용 |
| **`contradicts`** | **`@comparison`** |
| `kind=question` | `@section` |

`contradicts`가 핵심입니다. umm은 의견 충돌을 **한쪽을 지워서 해결하지 않고 기록**합니다.
그래서 같은 노트를 요약해서는 **절대 못 만드는 슬라이드**가 나옵니다.

Dream 분석에서 뺀 생각은 덱에서도 빠지고, 조용히 사라지는 대신 **개수로 보고**됩니다.

## 만들기 전에 봅니다

```
[슬라이드 5장] [생각 6개] [1개 제외] [레이아웃 미확인]

┃2  격주 회고가 정말 더 나은가?  질문
┃3  회고 주기를 격주로 줄여 보자  맞섬
┃   · 격주로 하면 사이 기간의 맥락을 잊는다
 4  주기가 짧으면 논의가 얕아진다
    · 지난 분기 회고 3회가 일정 때문에 취소됐다
 5  다음 스프린트에 4주만 시험해 보고 정한다
```

덱이 아니라 **생각이 사는 공간에서** 고칠 수 있어야 하니까요.

`레이아웃 미확인`을 숨기지 않습니다. Ptium은 덱이 있어야 측정할 수 있고, **경고 없는
미리보기가 검사조차 안 된 미리보기처럼 보이면** 안 됩니다.

## 슬라이드가 출처를 말합니다

슬라이드가 본인 문장을 담으므로, **없는 말을 넣지 않았는지 확인할 수 있어야** 합니다.
반대 방향도 마찬가지입니다 — 두 덱이 인용하는 메모를 고치는 건 아무도 안 쓴 메모를
고치는 것과 다른 결정입니다.

Ptium 데이터는 복제하지 않습니다. 링크만 저장하고, 매핑은 slide id가 아니라 **위치**로
합니다 (재컴파일하면 id가 바뀌고 umm은 그걸 알 방법이 없습니다).

## 단위 테스트가 다 통과하는 동안에도 틀려 있었습니다

이 릴리스에서 **테스트가 못 잡고 실제로 해 봐야 나온 결함이 넷**입니다.

**하나 — 덱 순서가 엉망이었습니다.** 실제 공간(질문·근거·충돌·결정)에 돌려 보니 비교
슬라이드가 맨 앞, 정작 본인이 쓴 질문이 네 번째에 내용도 없이 놓였습니다. 체인이 배치
순서를 무시하고 통째로 앞으로 나왔고, 충돌의 양쪽을 아무도 선점하지 않아 질문이 한쪽을
흡수했고, 근거가 한 단계만 따라와 근거의 근거가 홀로 남았습니다.

**둘 — 미리보기가 덱에 없을 줄을 보여 줬습니다.** 비교 슬라이드가 제목을 첫 불릿으로 한 번
더 찍었습니다. 소스를 쓸 때는 중복을 버리는데 스토리라인은 갖고 있었습니다. 미리보기가
덱과 다른 말을 하는 것 — 이 기능이 막으려는 바로 그 거짓말입니다. 이제 **소스의 모든 불릿과
스토리라인의 모든 포인트를 대조하는 불변식**이 지킵니다.

**셋 — 관리자가 Ptium 주소를 저장할 수 없었습니다.** `PUT /admin/settings/ptium`이 404.
검증기도 비밀 등록도 시드 행도 있는데 **allowlist에만** 빠졌습니다. 그 위에 쌓은 전부가 실제
배포에서는 동작할 수 없었습니다. 이름 하나 넣는 건 테스트할 가치가 없으니 **부류로**
테스트합니다: 검증기가 있는 모든 섹션은 쓸 수 있어야 한다.

**넷 — 진짜 Ptium에 붙였더니 401이었습니다.** umm은 비밀을 `enc:` 접두사로 암호화해
저장하는데, 브리지가 그 문자열을 **그대로 Bearer 토큰으로** 보냈습니다. 실패 모습이 "키가
틀렸다"와 똑같아서, **유일하게 맞았던 것을 다시 붙여넣게** 만드는 종류입니다.

## 진짜로 만들어 봤습니다

Ptium 1.11.11을 실행하고 API 키를 발급받아, 화면에서 버튼을 눌러 **27KB PowerPoint 파일**을
받았습니다.

```
# 회고 주기 재검토              @cover
# 격주 회고가 정말 더 나은가?    @section
# 회고 주기를 격주로 줄여 보자   @comparison
  // umm:notes=e6d02d16…,7dece71c…
  - 격주로 하면 사이 기간의 맥락을 잊는다
```

`// umm:notes=` 주석이 **Ptium의 재컴파일 왕복을 견뎠습니다.** 검증할 방법이 없던 설계
도박이었는데, 저쪽에서 편집한 뒤에도 슬라이드가 출처를 말할 수 있다는 뜻입니다.
