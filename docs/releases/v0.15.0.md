# umm v0.15.0 — 생각 수집함

생각을 적으려면 먼저 어디에 적을지 정해야 했습니다. 앱을 열고, 공간을 고르고, 그다음에 씁니다.

**그 순서가 거꾸로입니다.** 생각은 어디 속하는지 알기 전에 옵니다. 공간을 먼저 물으면 생각은 결정을 기다리고, 기다리는 생각은 보통 다른 데 적히고 끝납니다.

---

## 1. 어디서든 담기

모든 화면 상단에 입력칸이 하나 생겼습니다.

```
무슨 생각을 하고 있나요?  [                    ]  →
```

공간을 묻지 않습니다. Enter 한 번이면 **수집함**에 들어갑니다. Shift+Enter는 줄바꿈입니다.

수집함은 **평범한 공간**입니다. 검색되고, 임베딩되고, Dream이 보고, 연결할 수 있습니다. 그래서 아래쪽의 어떤 기능도 "두 번째 종류의 저장소"를 새로 배울 필요가 없습니다. 플래그는 두 가지만 합니다 — 정리되지 않은 생각이 어디로 갈지 정하고, **그 공간을 지우지 못하게** 막습니다. 지우면 다음 수집이 조용히 새 수집함을 만들면서 이전 것을 잃어버립니다.

저장에 실패하면 **입력한 내용을 지우지 않습니다.** 담았다는 신호는 칸이 비는 것이고, 그게 수집의 유일한 약속입니다.

오프라인에서도 담깁니다. 기차에서 적은 생각은 터널을 지나야 하고, 재시도가 사본을 두 개 만들어서도 안 됩니다.

---

## 2. 나중에 정리하기

생각을 고르면 옆 패널에 **다른 공간으로 옮기기**가 나옵니다.

여기서 umm은 자기가 할 수 있는 말만 합니다.

| 임베딩 상태 | 표시 | 근거 |
| :--- | :--- | :--- |
| 의미를 판별함 | 내용이 가까운 순 | `basis=meaning`, 점수 표시 |
| 판별하지 못함 | 최근 작업한 순 | `basis=recent` |

기본 임베딩은 겹치는 단어를 재므로, 그걸 "내용이 가깝다"고 내놓으면 거짓말입니다. 그럴 때는 **최근 순으로 보여 주고 그렇다고 말합니다.** 자동 연결이 긋는 것과 같은 선입니다.

bge-m3를 붙이고 `세션 쿠키에 SameSite를 꼭 넣자`를 담았을 때 실제 결과입니다.

```
보안     basis=meaning  score=0.463
자전거   basis=meaning  score=0.372
```

### 연결은 함께 갈 수 없습니다

연결은 공간에 속하고 양쪽 끝이 그 안에 있어야 합니다. 그래서 옮기는 생각은 연결을 **가져갈 수 없고**, umm은 몇 개를 정리하는지 **미리 알려 줍니다.** 나중에 발견하게 두지 않습니다.

---

## 3. 에이전트도 담을 수 있습니다

MCP에 `capture_thought`가 생겼습니다.

```json
{"name":"capture_thought","arguments":{"content":"회고 때 물어볼 것"}}
```

공간을 고를 이유가 없을 때 씁니다. 고를 이유가 있으면 기존 `create_note`가 있습니다.

---

## 4. 만들면서 발견해 고친 것

### 추천 점수가 전부 0이었습니다

순서는 그럴듯했는데 점수가 전부 `0.00`이었습니다. 실제로 돌려 보다가 발견했습니다.

`loadEmbeddings`는 **저장된 벡터만 읽습니다.** 벡터는 공간을 조회할 때 만들어지는데, 방금 담은 생각의 공간은 조회한 적이 없으니 벡터가 없었습니다. 없는 벡터와의 코사인은 0이고, **정렬된 것처럼 보이지만 정렬이 아닌 목록**이 나왔습니다.

생각의 공간도 함께 조회하도록 고쳤습니다. 그리고 후보를 공간마다 따로 비교하던 것을 **한 번에** 모아 비교하도록 바꿨습니다 — 공간별로 서로 다른 알고리즘의 저장 벡터가 선택되면 순위를 매기려는 그 공간들 사이에서 점수가 비교 불가능해집니다.

벡터가 없으면 0점 목록 대신 **최근 순으로 물러섭니다.**

### 수집이 오프라인 큐에서 거부됐습니다

재시도 키는 오프라인 Canvas 변경에만 허용되어 있어서 `/capture`가 400을 받았습니다. 수집이야말로 오프라인을 견뎌야 하는 동작이라 허용 목록에 넣었습니다. 이웃 경로가 딸려 들어가지 않는지도 테스트로 고정했습니다.

## 업그레이드

**마이그레이션이 있습니다** (013). 수집함은 처음 담을 때 만들어지므로 기존 사용자에게 빈 공간이 미리 생기지 않습니다.

```bash
docker run -d --name umm --restart unless-stopped \
  -p 8080:8080 \
  -e POSTGRES_DSN='postgres://umm:password@postgres.internal:5432/umm?sslmode=require' \
  -e BOOTSTRAP_ADMIN='admin' \
  -e BOOTSTRAP_ADMIN_PASSWORD='your-strong-password' \
  -e ENCRYPTION_KEY='your-32-char-random-encryption-key' \
  umm:v0.15.0
```

- 공간 목록의 `isInbox`로 수집함을 구분할 수 있습니다. 삭제 요청은 이유와 함께 거부됩니다.
- 롤백하면 플래그만 사라지고 수집함은 평범한 공간으로 남습니다. 안에 든 생각은 그대로입니다.
