# v0.66.1 — 연결되어 있는데 연결을 기다리는 변경

오프라인 보관함은 연결이 돌아오면 스스로 비워집니다. 그 "스스로"는 브라우저의 `online`
이벤트 하나뿐이고, **연결과 상관없이 멈춘 경우에는 그 이벤트가 오지 않습니다.**

```
    다른 탭이 같은 변경을 쓰는 중이었습니다

            전                              후
    ━━━━━━━━━━━━━━━━━━━━━━      ━━━━━━━━━━━━━━━━━━━━━━
    409 예약 진행 중              409 예약 진행 중
    큐에 남김                     큐에 남김 · 2초 뒤 다시
    ↓                            ↓
    (아무 일도 없음)              동기화 완료
    "1개 변경이 연결을            (배너 사라짐)
     기다리는 중"
     ← 연결은 되어 있음
```

## 다시 시도한다고 적혀 있었지만 아무도 다시 시도하지 않았습니다

같은 변경을 두 곳에서 보내면 서버는 409에 `idempotency-in-progress`를 담아 돌려줍니다.
이것은 버전 충돌이 아니라 **지금 적용되고 있다**는 뜻이라, umm은 충돌 대화상자를 띄우지
않고 큐에 그대로 둡니다. 여기까지가 v0.8.0이 고친 것이고, 옳습니다.

문제는 그다음입니다. 예약이 풀리는 것은 다른 요청이 끝나는 일이라 **브라우저가 알려 줄 방법이
없습니다.** 그래서 그 변경은 큐에 앉아 `1개 변경이 연결을 기다리는 중`이라는 배너를 띄웁니다
— 연결은 처음부터 되어 있는데도. 사람이 `지금 동기화`를 직접 누르기 전까지 아무 일도
일어나지 않았습니다.

같은 구멍이 하나 더 있습니다. **브라우저가 눈치채지 못한 채 요청이 실패한 경우** —
서버가 연결을 끊거나 중간의 무언가가 요청을 삼켰지만 `navigator.onLine`은 계속 참인
경우입니다. 오프라인이 아니므로 `offline`도 `online`도 뜨지 않고, 역시 아무도 다시 오지
않았습니다.

## 스스로 풀리는 이유에는 타이머를 겁니다

이제 두 경우 모두 다음 시도를 예약합니다 — 예약 진행 중은 **2초**(다른 요청이 끝나는 데
걸리는 시간), 연결이 멀쩡한데 실패한 요청은 **5초**(408·429·5xx가 이미 쓰던 기본값).

브라우저가 정말로 오프라인이 된 경우는 예외입니다. 그때는 `online` 이벤트가 제 일을 하고,
타이머는 걸리지도 않고 걸렸더라도 오프라인 상태에서는 발사되지 않습니다.

## 충돌은 지연이 아니라 결정입니다

타이머를 걸면서 같이 고쳐야 했던 것이 있습니다. 큐에 든 변경은 자기가 쓰인 시점의 버전을
들고 있어서, **버전 충돌은 다시 보낸다고 풀리지 않습니다.** 몇 번을 보내도 같은 409입니다.

그리고 매번 `umm:offline-conflict`가 다시 발생합니다. 그 이벤트를 받는 캔버스는 병합
대화상자를 열면서 `setMergeDraft(...)`로 편집칸을 다시 채웁니다 — **사람이 병합문을 타이핑하는
동안 5초마다 타이핑한 것이 지워지는 것**이 그 의미였습니다. 지금까지는 5xx가 재시도를 돌릴
때만 일어났지만, 이번 타이머가 그 경우를 넓힙니다.

그래서 충돌을 이미 보여 준 변경은 **다시 보내지 않습니다.** 큐에 남고, 배너의 숫자에
들어가고, 사람의 결정을 기다립니다. 어느 쪽을 고르든 결정은 그 변경을 큐에서 지우고, 그때
붙잡아 두던 것도 같이 풀립니다.

## 확인한 것

```
✓ 예약 진행 중 409 → 2초 뒤 스스로 다시 시도해 동기화됨
✓ 연결이 멀쩡한데 던진 요청 → 5초 뒤 스스로 다시 시도해 동기화됨
✓ 브라우저가 오프라인이면 타이머는 발사되지 않음 (online 이벤트가 담당)
✓ 충돌한 변경은 두 번째 flush에서 요청조차 나가지 않음
✓ 충돌 이벤트는 한 번만 — 열려 있는 병합칸이 덮어써지지 않음
✓ 결정(어느 쪽이든)이 변경을 큐에서 지우고 붙잡음도 함께 풀림
✓ 큐에서 사라진 변경의 붙잡음은 다음 flush에서 정리됨
```

| 바꾼 것 | 잡은 것 |
| :--- | :--- |
| 스스로 풀리는 보류에 타이머 | 연결되어 있는데 영원히 기다리는 변경 |
| 충돌한 변경은 재전송 안 함 | 5초마다 지워지는 병합 편집칸 |
