# v0.58.1 — 아무 일도 하지 않는다고 써 놓고 숫자를 적지 않습니다

어제 낸 밴드 미리보기에 제가 직접 쓴 주석을 지키지 않은 곳이 있었습니다.

> 아무도 보지 못할 산술을 설명하지 않습니다.

임베딩이 의미 비교에 부적합하다고 판정되면 캔버스는 위치로 묶습니다. 그래서 패널은
**"군집 기준은 아무 일도 하지 않습니다"** 라고 알려 줍니다. 그리고 **바로 밑에 묶음 개수
표를 그렸습니다.**

```
⚠ 캔버스는 위치로 묶으므로 군집 기준은 아무 일도 하지 않습니다.

                          지금        바꾸면
묶음 수                      9            9      ← 아무 일도 안 한다면서요
묶인 생각                  204          204
```

방금 한 말을 도로 무르는 표였습니다.

## 고친 것

의미 비교가 안 되는 백엔드에서는 **묶음 네 줄을 아예 계산하지도, 표시하지도 않습니다.**
응답의 `clusters`·`grouped`·`largestCluster`·`ungrouped`도 0으로 남고, `semantic: false`가
그 이유입니다. OpenAPI에 "0을 개수로 읽지 말 것"이라고 적었습니다.

**연관 생각 쪽은 그대로입니다.** 그건 어느 백엔드에서나 채점되니까요.

umm 기본 설치가 쓰는 로컬 char-gram 임베딩이 바로 이 경우입니다. 즉 **많은 설치에서
이 표의 절반은 처음부터 아무 의미가 없었습니다.**

## 어제 한 말을 하나 정정합니다

v0.58.0을 내면서, 기본 군집 기준 1.1이 주제가 뚜렷하게 갈린 실제 공간에서 묶음을 놓치고
있을지 모른다고 썼습니다. **틀렸습니다.**

주제 2~8개 × 각 30개, 주제 간 어휘 겹침을 0~6단어로 바꿔 가며 20가지를 재봤습니다.
**밴드 1.1은 전부 91~100%를 묶었습니다.** 무너지는 건 "갈린 주제"가 아니라
**"거의 같은 노트로만 채워진 공간"** 이었습니다 — 시험이 만든 코퍼스가 주제마다 똑같은
문장에 번호만 붙인 것이었거든요.

```
주제당 30개, 노트마다 바뀌는 단어 수
  0단어 → 13% 묶임
  1단어 → 98% 묶임
```

**단어 하나로 돌아옵니다.** 현실적인 공간이 아닙니다. 기본값은 그대로 둡니다.

이걸 시험으로 박아 뒀습니다. 나중에 기본값이나 척도나 임베딩이 바뀌어서 캔버스가 조용히
비면 잡힙니다. 무너지는 쪽도 같이 박았습니다 — **그게 없으면 "다 묶으면 통과"인 시험이라
아무것도 증명하지 못합니다.**

## 확인한 것

```
✓ 의미 비교가 안 되면 묶음 숫자를 내보내지 않음
✓ 그래도 연관 생각 숫자는 그대로
✓ 화면에서도 묶음 네 줄이 사라지고 경고만 남음
✓ 기본 밴드가 평범한 공간의 70% 이상을 묶음 (실측 91~100%)
✓ 거의 같은 노트만 있으면 50% 아래로 무너짐
✓ 묶인 생각 + 혼자 남는 생각 = 전체
```

변형 시험 넷 다 잡혔습니다: 판정을 무시하고 계산하게 → 통합 시험이 잡음, 기본 밴드를
2.6으로 → 0% 묶임을 잡음, 문턱을 무력화 → 무너짐 시험이 잡음, 화면 조건을 뒤집어 →
e2e가 잡음.

## 복구하다가 하나 낼 뻔했습니다

변형을 되돌리는 `sed` 가 **경고문 자체의 조건까지 같이 바꿔 버렸습니다.** 그대로 뒀으면
의미 비교가 **되는** 설치에서 "안 됩니다" 경고가 떴을 겁니다. 시험은 전부 통과했습니다 —
그 조합을 보는 시험이 없었으니까요. **번들 해시가 원래대로 돌아오지 않은 것**만으로
알아챘습니다.
