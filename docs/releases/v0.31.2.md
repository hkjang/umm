# v0.31.2 — 안내서가 제품을 따라잡았습니다

v0.23.0부터 v0.31.1까지 열여섯 번 릴리스했습니다. 릴리스 노트에는 다 적혀 있었습니다.

**사용자 안내서 네 권에는 한 줄도 없었습니다.**

```
features.md    갈래=0  결정 기록=0  조력자=0  렌즈=0
user-guide.md  갈래=0  결정 기록=0  조력자=0  렌즈=0
api-guide.md   갈래=0  결정 기록=0  조력자=0  렌즈=0
admin-guide.md 갈래=0  결정 기록=0  조력자=0  렌즈=0
```

릴리스 노트는 **무엇이 바뀌었는지** 말합니다. 안내서는 **무엇을 쓸 수 있는지** 말합니다. 새로
들어온 사람이 읽는 건 뒤쪽입니다.

## 사용자 가이드

- **4-1 내 기억에 물어보기 · 살펴보고 답하기** — 두 모드의 차이, 근거가 없으면 모델을 부르지 않는 이유, 조력자가 읽기만 하는 이유
- **4-2 생각의 갈래와 결정 기록** — 만들고 넣고 정리하는 법, **이유가 필수인 까닭**, 접어 둔 갈래가 어디에 나타나는지
- **4-3 한 갈래만 보기** — 흐리게 두되 숨기지 않는 이유, 왜 의미가 아니라 구조로 좁히는지

## 기능 가이드

`/decisions`, 갈래, 초점 렌즈, 조력자를 화면 단위로 추가했습니다. 되짚기 쌍에 **합치기 버튼을 주지
않는 이유**(합치면 접어 둔 쪽이 남습니다)도 적었습니다.

## API 가이드

`/ai/ask` · `/ai/agent` · 갈래 6종 · `/turning-points`를 표에 넣고, MCP 도구 목록을 실제 13개로
맞췄습니다(`list_lines` 등 5개가 빠져 있었습니다). `note_lines`의 `abandoned`가 무슨 뜻인지도
적었습니다.

## 관리자 가이드

**4-2 유사도 기준**을 새로 썼습니다. 열 개 항목의 기본값을 표로 정리하고 — **코드와 하나씩
대조했습니다** — 왜 `duplicate_similarity`만 절대값인지 설명했습니다:

> 중복이 많은 공간은 자기 분포가 통째로 올라가서, **중복이 가장 많을 때 중복이 특별해 보이지 않게**
> 됩니다.

규모 경계(1,000개)와 그 실측 근거, 접어 둔 갈래가 교차 비교로 따로 들어오는 이유도 적었습니다.

## PDF 6종 재생성

마크다운만 고치고 PDF를 두면 두 문서가 갈라집니다. `scripts/generate_pdf.js`로 전부 다시 만들었습니다.

## 확인한 것

- 문서에 적은 기본값 10개를 `intelligence_settings.go`·`scale.go`·`quality.go`와 대조
- MCP 도구 목록을 `toolDefinitions()`와 대조
- 전체 Go 테스트 통과, OpenAPI 정합성 검사 통과
