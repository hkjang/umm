# v0.47.3 — 헤더의 두 버튼이 손가락에 맞습니다

지난 릴리스에 **"휴대폰에서 44px 미만 탭 대상 21개"** 라고 적어 두었습니다. 이번에 제대로
재 봤더니 **그 숫자가 틀렸습니다.** 먼저 그것부터 바로잡습니다.

## 21개 중 대부분은 제 측정 실수였습니다

캔버스에는 확대/축소 변환이 걸려 있습니다. 그때 확대율은 **0.38** 이었습니다.

```
메모 메뉴   화면에서 17x17    ← 이렇게 보고했었습니다
           레이아웃으로는 44x44  ← 실제 CSS 값
```

`getBoundingClientRect` 는 변환이 적용된 값을 돌려줍니다. 캔버스 요소를 그걸로 재면 **축소된
크기**가 나오고, 그건 규칙이 잘못됐다는 뜻이 아니라 **사용자가 축소해 놓았다는 뜻**입니다.
확대하면 그대로 커집니다.

지지난 릴리스에서 칩 겹침을 재다가 똑같은 함정에 빠졌었는데, 그 교훈을 **바로 다음 작업에서
또 놓쳤습니다.** 이번엔 `offsetWidth`/`offsetHeight` — 변환이 건드리지 못하는 레이아웃
픽셀로 쟀습니다.

## 이 프로젝트는 이미 44px 을 정해 두고 있었습니다

```css
@media (pointer: coarse) {
  .mantine-ActionIcon-root, .mantine-Button-root, .related-chip {
    min-width: 44px; min-height: 44px;
  }
}
```

규칙도 있고 동작도 합니다. `pointer: coarse` 와 `hover: none` 둘 다 켜져 있었고, 이 목록에
이름이 있는 컨트롤은 **전부 이미 44px 이었습니다.**

## 다만 두 개가 이 목록에 없었습니다

```
메뉴 열기   28x28   ← Mantine Burger
알림        22x28   ← UnstyledButton
```

**둘 다 ActionIcon 도 Button 도 아닙니다.** 그래서 이미 내려 둔 결정이 이 둘에게만 닿지
않았습니다. 새 규칙을 만든 게 아니라, **있던 규칙을 빠진 자리에 적용했습니다.**

```
후:  메뉴 열기 44x44 · 알림 44x44   (글리프 크기는 그대로)
```

## 정직하게 적어 둘 것

박스가 커지면서 flex 행이 간격을 다시 나눕니다. **로고가 약 40px 오른쪽으로 이동했습니다.**
글리프 자체는 그대로이고 잘리거나 겹치는 곳은 없지만, "그려지는 것은 전혀 바뀌지 않는다"고
말하면 사실과 다릅니다.

## 남겨 두는 것 (설계 판단이 필요합니다)

```
사이드바 항목   379x41   ← 3px 모자람, 항목 간격은 5px
프로필 메뉴     126x40   ← 4px 모자람
로고           36x36
React Flow 컨트롤 34x34  ← 외부 라이브러리
```

3~4px 모자란 것들은 키우면 **사이드바 높이가 21px 늘어나는 등 눈에 띄게 배치가 달라집니다.**
기계적인 히트 영역 확대가 아니라 헤더·사이드바 간격에 대한 설계 판단이라, 재어만 두고
손대지 않았습니다.

## 검증

되돌려서 확인했습니다.

```
✘ 두 선택자를 규칙에서 제거   → "메뉴 열기 is 28px wide" 로 실패
✘ 알림 버튼의 클래스 제거     → "알림 is missing" 으로 실패
```

헤더가 계속 들어맞는지도 함께 봅니다 — **밖으로 밀려난 컨트롤은 작은 컨트롤보다 나쁩니다.**
