# v0.29.0 — 에이전트도 접어 둔 갈래를 압니다

v0.28.1에서 내보내기가 갈래를 빠뜨리고 있던 걸 고쳤습니다. 그러면 **같은 문이 또 있나** 하고
찾아봤습니다. 있었습니다.

## MCP

외부 에이전트는 `/mcp`로 이 기억을 읽습니다. `list_notes`와 `search_notes`가 돌려주는 생각은
**접어 둔 갈래에 있든 아니든 똑같이 생겼습니다.**

v0.24.0부터 v0.27.0까지 웹 화면과 내장 조력자에게 가르친 것 — 접어 둔 생각을 현재 방침처럼
말하지 말 것 — 이 **문 하나에만** 적용되고 있었습니다.

`ai_excluded`가 연결을 통해 새던 것과 같은 종류입니다. 한 경로에서 막고 다른 경로에서 흘리면
막은 게 아닙니다.

### 지금은

`list_notes` · `search_notes`가 `note_lines`를 함께 돌려줍니다.

```json
"note_lines": {
  "…": { "name": "젠킨스 직접 운영", "status": "abandoned",
          "resolution": "플러그인 호환 부담이 통제권으로 얻는 것보다 컸습니다" }
}
```

그리고 `list_lines` 도구가 생겼습니다. 도구 설명에 **표시된 것이지 추론된 것이 아니라는 점**과
**빈 결과의 뜻**을 적었습니다 — `find_contradictions`·`find_open_questions`와 같은 규칙입니다.

도구 목록이 바뀌면 실패하는 테스트가 이미 있었고, 정확히 그 일을 했습니다. 외부 계약이 바뀌는
일이니 **일부러** 고쳤습니다.

## 합치기는 갈래를 옮기지 않습니다 — 이유를 적었습니다

두 생각을 합칠 때 살아남는 쪽은 **자기 갈래를 유지하고, 상대의 갈래를 물려받지 않습니다.**
코드가 원래 그랬는데 아무 데도 적혀 있지 않았습니다.

이건 버그가 아니라 선택입니다. 합치기는 "어느 쪽을 남길지 내가 골랐다"는 뜻입니다. 거기에 갈래를
얹으면 **그 사람이 여기서 내리지 않은 결정**으로 생각을 분류하는 셈이고, 그 갈래가 접어 둔
것이라면 "이건 거절됐다"라고 말하는 셈입니다. **지어내는 쪽이 잃는 쪽보다 나쁩니다.**

그리고 가장 중요한 경우는 이미 막혀 있습니다 — v0.27.0에서 한쪽만 접어 둔 갈래인 쌍에는 오늘의
리뷰가 합치기 버튼을 주지 않습니다.

## 확인한 것

- 전체 Go 테스트 통과, 웹 53개 통과
- **실제 API 키로 MCP를 호출해 확인**: 생각 10개 중 2개에 `abandoned` 갈래와 이유가 붙어 옴
- 도구 설명이 `note_lines`와 `abandoned`의 뜻을 말하는지 테스트로 고정
- `list_lines` 설명이 "추론이 아님"과 "빈 결과의 뜻"을 말하는지 고정
