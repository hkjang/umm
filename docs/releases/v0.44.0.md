# v0.44.0 — 저장하지 않은 설정을 조용히 버리지 않습니다

관리자 화면을 열두 섹션 다 걸어 봤습니다. 깨진 곳은 없었고, **조용히 잃는 곳**이 있었습니다.

## 타이핑하고 나가면 그냥 사라졌습니다

재현한 그대로입니다.

```
서비스 이름을 "바뀐 이름"으로 입력
카드에 "저장되지 않은 변경사항이 있습니다"  ← 보이고 있음
'내 공간' 클릭
  → 경고 없음
  → 나가짐
돌아와 보면 필드는 "umm"
```

**나가는 길에 아무 말이 없고, 돌아왔을 때 흔적도 없습니다.** 잃은 것보다 알려주지 않은 것이
나쁩니다. 타이핑하는 내내 카드가 새 값을 보여 주고 있었으니까요.

이제 나가기 전에 묻습니다. **어느 섹션인지 이름을 말합니다** — 여러 섹션을 만지던 관리자에게
"저장 안 된 게 있다"만으로는 무엇이 걸려 있는지 알 수 없습니다.

`여기 남기`가 첫 번째 버튼입니다. 자세히 읽지 않는 사람이 **되돌릴 수 있는 쪽**을 누르게
됩니다.

## 섹션을 옮기는 건 나가는 게 아닙니다

일반 → Dream Layer로 옮겨도 편집은 그대로 남고 표시도 유지됩니다. 여기서 물으면 아무것도
아닌 일에 대화상자를 띄우는 셈입니다.

## 나가는 문이 여럿이었습니다

사이드바만 막으면 **가장 빠른 출구가 잃는 출구**가 됩니다.

| 문 | |
| --- | --- |
| 사이드바 링크 | 물음 |
| `내 공간` 버튼 | 물음 |
| 로고 · 개인 설정 메뉴 | 물음 |
| 모바일 탭 | 물음 |
| **빠른 이동 (Ctrl+K)** | 물음 |
| 탭 닫기 · 새로고침 | 브라우저가 물음 |
| 브라우저 뒤로가기 | **막지 못합니다** |

마지막 줄은 정직하게 적어 둡니다. React Router의 blocker가 제자리이고 그건 data router가
필요한데, 이 앱의 라우트는 인증 상태로 만들어집니다 — 관리자 라우트의 보호 구조를 뜯는 일을
경고 대화상자 하나 때문에 할 수는 없습니다.

## 검증

되돌려서 확인했습니다. 가드를 빼면 **셋이 실패**하고, 통과하는 셋은 **없음을 확인하는
테스트**라 전에도 옳았습니다.

```
✘ 나가기 전에 묻고, 남으면 작업이 유지된다
✘ 일부러 나가면 나가진다
✘ 빠른 이동도 묻는다
✓ 섹션 이동은 방해하지 않는다     — 원래 옳았음
✓ 잃을 게 없으면 아무 말 없다     — 없음 확인
✓ 저장하면 더 묻지 않는다         — 없음 확인
```
