# v0.47.2 — 칩이 생각을 덮지 않습니다

화면을 하나씩 보는 일은 끝났지만, 전부 **데스크톱 폭**에서만이었습니다. 이번엔 휴대폰(412px)
으로 전부 다시 열었습니다.

## 휴대폰 레이아웃 자체는 멀쩡했습니다

```
오늘의 리뷰 · Dreams · 결정 기록 · 검토·승인 · 개인 설정
  가로 넘침 없음 · 탭 바 정상 · 작은 탭 대상 없음
```

지난 스크롤 작업이 이 부분을 이미 덮고 있었습니다. **문제는 캔버스에서 나왔고, 알고 보니
휴대폰만의 문제가 아니었습니다.**

## 칩이 글자 위에 그려지고 있었습니다

`관련 N` 과 `+N줄` 은 둘 다 카드 아래 모서리에 `position: absolute` 로 얹혀 있습니다.
**글자 옆이 아니라 글자 위입니다.**

레이아웃 픽셀로 쟀습니다 — 카드 아래 모서리에서 위로 얼마나 떨어져 있는지입니다.

```
글자가 닿을 수 있는 바닥   16px
칩이 차지하는 구간         10px ~ 33px
                          ─────────
                          17px 만큼 마지막 줄이 칩 아래에 깔림
```

`+N줄` 쪽이 특히 그렇습니다. **생각의 일부가 가려져 있다고 알리는 칩이, 스스로 생각의
일부를 가리고 있었습니다.**

이제 칩이 있는 카드만 아래쪽을 비워 둡니다.

```
후:  글자 바닥 42px  ·  칩 상단 33px  →  9px 여유
```

가려졌던 그 줄은 이제 `+N줄` 에 **정직하게 포함됩니다.** 고치기 전 스크린샷의 카드에는
`+1줄` 이 없었고, 고친 뒤에는 생겼습니다 — 반쯤 그려져 있던 줄이 이제 숨은 줄로 세어지는
것입니다.

## 데스크톱도 마찬가지였습니다

휴대폰에서 눈에 띄었을 뿐, **모든 폭에서 같은 일이 일어나고 있었습니다.** 이 저장소의
`note-card` 테스트는 첫 줄에 이렇게 적혀 있습니다 — *"메모 카드는 생각의 내용을 잘못 전하면
안 된다."* 이미 적어 둔 성질이 지켜지지 않고 있던 자리입니다.

## 검증

되돌려서 확인했습니다. 양쪽 다 잡힙니다.

```
✘ 비워 둔 공간 제거        → 16 (기대 ≥33) 로 실패
✘ 적용하는 클래스 제거     → 16 (기대 ≥33) 로 실패
```

테스트는 **레이아웃 픽셀**로 잽니다. 캔버스에는 확대/축소 변환이 걸려 있어서
`getBoundingClientRect` 로 재면 축척된 값과 축척되지 않은 값을 섞게 되고, **없는 겹침을
있다고 보고합니다.** 실제로 이번에 제가 그 함정에 한 번 빠졌고, 고친 뒤에도 겹친다고
잘못 읽었습니다.

## 남겨 두는 것

휴대폰에서 44px 미만인 탭 대상이 21개 있습니다 (`메뉴 열기` 28×28, `메모 메뉴` 26×26 등).
플랫폼 권장치 아래는 맞지만, **모양을 건드리지 않고 터치 영역만 넓히는 일**은 이번 변경과
성격이 다릅니다. 재어 두었고, 별도로 다룹니다.
