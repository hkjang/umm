# v0.50.3 — 내보낸 파일을 두 번째로 골라도 읽습니다

바로 앞 릴리스(v0.50.2)에서 낸 구멍을 메웁니다. **제가 만든 것이고, 제가 찾았습니다.**

## 무엇이 잘못됐나

v0.50.2 는 문서가 내보내기인지를 **맨 위 여섯 줄**을 보고 판단했습니다. 내보낸 파일 하나만
고르면 맞습니다. 그런데 가져오기 화면은 고른 파일을 **입력란에 이미 있는 내용 뒤에 붙입니다.**

```js
setText((current) => [current, ...contents].filter(Boolean).join('\n\n---\n\n'));
```

그래서 이렇게 하면 v0.50.2 는 다시 예전처럼 동작했습니다.

```
생각을 하나 적는다 → 내보낸 파일을 고른다

  "오늘 떠오른 것"        먼저 적어 둔 생각
  "돌아오는 공간"        Exported from umm at …                ← 머리말이 다시 생각이 됨
  "Thought"             이어진 생각의 본문
                        - id: `bfe3a64a-…` - type: `thought`   ← 메타데이터가 다시 붙음
  "Thought"             제목이 없는 생각의 본문
  "Connections"         - `f254…` --related--> `bfe3…`
  "Lines of thinking"   - **되돌리기 실험** — adopted: …
```

고친 것이 **사람이 실제로 걷는 길에서는 여전히 고쳐지지 않은** 상태였습니다.

## 이제

머리말을 "문서 맨 위에 있는지"가 아니라 **한 구역 전체가 머리말인지**로 알아봅니다. 그
구역이 어디에 있든 상관없습니다.

```
생각을 하나 적는다 → 내보낸 파일을 고른다

  "오늘 떠오른 것"        먼저 적어 둔 생각
  (제목 없음)            이어진 생각의 본문
  "제목이 있는 생각"      제목이 있는 생각의 본문
  (제목 없음)            제목이 없는 생각의 본문
```

파일을 **두 개 고르는** 경우도 같은 이유로 함께 맞았습니다. 두 파일은 `---` 로 이어 붙으므로
한 문서 안에 내보내기가 둘 있는 셈인데, 이제 둘 다 내보내기로 읽습니다 — 생각 6개가 6개로.

**"구역 전체"라는 조건이 안전장치입니다.** 남의 노트가 그 문구를 인용할 수 있으니까요. 인용한
문장에는 다른 말도 함께 있고, 머리말 구역에는 머리말 한 줄뿐입니다.

## 검증

세 가지를 되돌려 봤습니다.

```
✘ 머리말을 맨 앞에서만 인정 (= v0.50.2)  → 새 시험 2개 실패
✘ 머리말이 구역 전체가 아니어도 인정      → "문구를 인용한 문서" 시험 실패
✘ 내보내기 표시가 구역마다 풀림           → 시험 6개 실패
```

**두 번째 되돌리기는 처음엔 아무 시험도 깨지 않았습니다.** 시험 문서가 `"Exported from umm
at"` 을 따옴표로 닫아 놓아서, 느슨해진 규칙조차 우연히 걸리지 않았던 것입니다 — 즉 그
안전장치를 **시험하고 있다고 생각만 했지 실제로는 시험하지 않고 있었습니다.** 문장을 실제
머리말 모양으로 고쳐 넣은 뒤에야 되돌리기가 잡혔습니다.

Go 쪽 계약 시험도 같은 이유로 고쳤습니다. 이제 "머리말이 여섯 줄 안에 있는가"가 아니라
**"머리말이 제 구역에 혼자 있는가"** 를 확인합니다 — 가져오기가 실제로 기대는 것이 그것이니까요.

```
내보내기가 머리말 옆에 "3 notes." 한 줄을 더 씀
  → something else joined the banner in its section 으로 실패
```
