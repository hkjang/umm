# v0.69.0 — 같은 그래프로 글의 차례를

발표를 만들 때 umm은 이미 순서를 정합니다. 그 순서는 추측이 아닙니다 — `follows` 사슬이면
**사람이 순서를 직접 말한 것**이고, 아니면 **캔버스에 늘어놓은 배치**이며 그것도 사람이 한
일입니다.

발표가 아니라 **글**을 쓰려는 사람도 딱 그 두 가지가 필요합니다. 이미 한 일이 물어본 적
없는 질문에 답합니다.

```
    내보내기 메뉴
    ├─ Markdown              ← 되돌리기용 백업 (id·좌표·연결)
    ├─ 문서 차례 (Markdown)  ← 새로 추가: 글의 차례
    ├─ Image (PNG)
    └─ PDF 다운로드
```

## 백업과 다른 파일입니다

| | Markdown | 문서 차례 |
| :--- | :--- | :--- |
| 답하는 질문 | "나중에 그대로 돌려줘" | "이걸 글로 쓰기 시작하고 싶다" |
| `- id:` `- canvas:` | 있음 (복원에 필요) | **없음** |
| `## Connections` | 있음 | **없음** |
| `Exported from umm at` | 있음 (자기 파일 표시) | **없음** |

백업 파일을 문서에 붙여 넣으면 읽는 사람이 건너뛸 것투성이입니다. 이 파일에는 **당신이 쓴
문장과 그 순서**만 있습니다.

## AI가 없습니다

새 지능도, 새 호출도, 게이트웨이 설정도 필요 없습니다. 이미 시험까지 끝난 `Compile` 을
그대로 쓰고, 쓰는 방식만 덱 소스 대신 마크다운입니다. 발표 미리보기를 읽은 사람은 자기가
무엇을 받을지 이미 알고 있습니다 — **같은 컴파일**이기 때문입니다.

## 부는 부답게

부로 나눈 발표는 부가 `##`, 그 안의 항목이 `###` 입니다. 제목 아래 한 단계씩 들어가므로
**큰 문서에 붙여 넣어도 주변 제목을 누르지 않습니다.**

## 시험이 못 잡는 시험이었습니다

부와 항목이 같은 단계로 뭉개지는 변형을 넣었는데 **통과했습니다.**

```go
strings.Contains(outline, "## 문제")   // "### 문제" 안에도 들어 있습니다
```

부분 문자열로 봐서, 한 단계 내려가도 못 잡는 단언이었습니다. 줄 단위로 정확히 보게 고치고,
**부 제목이 `###` 로 내려앉지 않았는지도** 함께 봅니다. 고친 뒤 같은 변형이 잡혔습니다.

## 확인한 것

```
✓ 그들의 문장이 그대로, 덱 소스 표시(@cover · 추적 주석)는 하나도 없이
✓ 배치와 follows 사슬이 다를 때 사슬을 따름
✓ 부는 ##, 항목은 ### — 줄 단위로 확인
✓ 제목을 본문에서 두 번 쓰지 않음
✓ 연결의 깊이가 들여쓰기로 남음
✓ 빈 공간은 빈 문서 (제목만 덩그러니 두지 않음)
✓ 브라우저에서 실제 .md 파일이 떨어지고, 백업용 기록이 하나도 없음
```

| 바꾼 것 | 잡은 것 |
| :--- | :--- |
| 부와 항목을 같은 단계로 | (처음엔 **못 잡음** → 시험을 고침) |
| 제목을 항목으로 다시 씀 | 같은 문장 두 번 |
| 깊이를 평평하게 | 연결이 표현한 층위가 사라짐 |
| 항목을 전부 버림 | 문장이 사라짐 |
| 제목을 버림 | 문서에 제목이 없음 |
