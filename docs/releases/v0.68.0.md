# v0.68.0 — 지운 생각이 로그에 남아 있었습니다

메모를 지우면 캔버스에서 사라집니다. **본문은 안 사라졌습니다.**

```
        메모 지움
            │
            ├─→ notes            deleted_at 표시됨   ✓
            ├─→ note_revisions   보관이 목적          ✓
            └─→ space_events     본문 그대로 남음     ✗  ← 정리 주기 없음
```

## 하나의 payload, 셋의 서로 다른 요구

`AppendSpaceEvent` 는 payload를 한 번 만들어 세 곳에 씁니다.

| 받는 쪽 | 본문이 필요한가 | 정리되는가 |
| :--- | :--- | :--- |
| 웹훅 전달 | **예** — 구독자가 그걸 구독했습니다 | 30일 |
| 멱등 응답 | **예** — 같은 HTTP 응답을 돌려줘야 합니다 | 24시간 |
| `space_events` | **아니오** | **안 됨** |

셋 중 **본문이 필요 없는 유일한 곳이, 유일하게 정리도 안 되는 곳**이었습니다.

결과적으로 모든 메모의 모든 판본이 무기한 쌓였습니다. 위치를 드래그할 때마다 한 벌씩 —
드래그는 `x`/`y` 를 바꾸는 메모 수정이고, 수정은 payload에 **본문을 포함한 메모 전체**를
싣기 때문입니다.

## 재고 주장했습니다

시험 DB 실측: **662행 중 629행이 본문을 담고 있었습니다.**

지운 메모는 직접 만들어 확인했습니다 — 메모를 쓰고, 고치고, soft delete 한 뒤:

```
note soft-deleted?                  true
its content still in space_events?  1
```

## payload는 한 번도 읽힌 적이 없습니다

이 표를 읽는 소비자는 SSE로 붙어 있는 캔버스 하나뿐입니다. 그 코드는 이렇습니다.

```
const data = JSON.parse(event.data);
if (data.actorId !== user?.id) void loadCanvas(true);
```

`actorId` 만 보고 다시 불러옵니다. **payload는 아예 안 봅니다.** 그러니 비우는 데 드는
비용이 0입니다.

## 그래서

- `space_events.payload` 는 이제 항상 `{}` 입니다. 무엇이 바뀌었는지는 `event_type` 과
  `resource_id` 가 말합니다
- 마이그레이션 026이 **기존 행의 payload도 비웁니다**
- **웹훅 구독자가 받는 본문은 그대로입니다.** 시험이 그쪽을 같이 봅니다 — 안 그러면 이
  수정은 그냥 기능 제거입니다

### down 마이그레이션이 없습니다

지운 내용은 복구할 수 없고, 컬럼을 되돌린다고 돌아오지도 않습니다. 되돌릴 수 있는 척하는
파일을 두느니 없는 이유를 적어 두는 쪽을 골랐습니다.

## 어쩌다 찾았나

`(5) 되감기(공간 타임랩스)` 를 만들려고 "엣지 이력이 없으니 그것부터"라고 말씀드렸는데,
확인해 보니 **`space_events` 에 이미 다 있었습니다.** 제 앞선 설명이 틀렸습니다. 그 표를
읽다가 정리 주기가 없다는 걸 봤고, 거기서 이게 나왔습니다.

같은 확인에서 `(3) 공간 사이로 생각 옮기기` 도 **이미 만들어져 있다**는 걸 알았습니다.
`POST /notes/{id}/move` 가 공간을 넘는 연결을 끊고 몇 개 끊었는지 알려 줍니다. 그것도
제가 틀렸습니다.

## 확인한 것

```
✓ 메모를 만들어도 로그에 본문이 없음
✓ 메모를 고쳐도 없음 (드래그마다 쌓이던 그 행)
✓ 웹훅 구독자는 본문을 그대로 받음
✓ 로그는 여전히 "무엇이, 누구에 의해 바뀌었다"를 기록함
✓ 기존 행의 payload도 비워짐
```

| 바꾼 것 | 잡은 것 |
| :--- | :--- |
| 로그에 본문을 다시 저장 | 사본이 다시 쌓임 |
| 웹훅 본문을 비움 | 구독자가 구독한 것을 못 받음 |
| 이벤트를 아예 안 씀 | 캔버스가 변경을 모름 |
