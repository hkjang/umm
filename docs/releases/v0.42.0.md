# v0.42.0 — Ptium 연결을 관리자 화면에서

Ptium 설정은 API로만 존재했습니다. 저장할 화면이 없으니 실제로는 **연결할 방법이
없었습니다.**

```
서비스 관리자 → Ptium 발표 자료

Base URL   http://ptium.internal:8080
API Key    ••••••••••••••••••••
템플릿      [ Ptium Plum Wash        ▾ ]
언어        ko            Timeout  30 초

[연결 테스트]                        [저장]
```

## 만들어 보기 전에 연결을 확인할 수 있습니다

`연결 테스트`는 Ptium의 **템플릿 목록을 읽습니다.** 인증이 필요한 읽기라서, 응답이 오면
세 가지가 한 번에 증명됩니다 — **주소가 응답하고, 그것이 Ptium이고, 키가 통합니다.**

이것이 없으면 주소나 키가 틀렸다는 첫 신호는 **누군가 발표 자료를 만들려다 받는 상태
코드**입니다.

고칠 방법이 다른 세 가지를 구분합니다.

| | |
| --- | --- |
| 주소가 비었을 때 | `Ptium 주소를 입력해 주세요.` |
| 주소 형식이 틀렸을 때 | `Ptium 주소가 올바르지 않습니다` |
| Ptium이 거절했을 때 | `Ptium 연결 실패:` + **Ptium이 한 말 그대로** |

## 템플릿은 이름으로 고릅니다

연결 테스트가 찾은 템플릿이 그대로 선택 목록이 됩니다. 다른 서비스에서 UUID를 복사해
붙여넣는 설정은 **저장된 것처럼 보이지만 아무것도 가리키지 않는** 종류입니다.

## 저장된 키는 다시 칠 필요가 없습니다

설정 화면은 저장된 비밀을 되돌려 보내지 않습니다. 바꾸지 않은 연결을 시험하려고 키를
다시 입력해야 한다면, 그건 시험이 아니라 재입력입니다.

## 짐작한 것이 틀렸고, 실제로 붙여 보고 알았습니다

Ptium의 템플릿 응답을 `{"data": {"templates": [...]}}`로 짐작했습니다. **실제로는 `data`가
배열 그 자체**입니다.

스텁 상대로는 깨끗하게 통과했고, **진짜 Ptium에 처음 붙이는 순간** 관리자가 아무것도 할 수
없는 unmarshal 오류로 실패했습니다.

## 관리자 화면만으로 끝까지 해 봤습니다

Ptium 1.11.11을 띄우고, 브라우저에서 주소와 키를 입력하고, 연결 테스트로 **템플릿 25개**를
찾고, 목록에서 `Ptium Plum Wash`를 고르고, 저장했습니다. 그다음 공간에서 발표 자료를 만들어
확인했습니다.

```
title:    관리자 설정 확인
template: Ptium Plum Wash | 79544750-…
slides:   3
```

**화면에서 고른 템플릿으로 실제 덱이 만들어졌습니다.**
