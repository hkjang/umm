# v0.59.0 — 붙여 넣은 설정 파일이 그대로 나가고 있었습니다

생각을 Dream에 보내기 전에 umm은 비밀번호·API 키·토큰을 지웁니다. 그 규칙이 **사람들이
실제로 붙여 넣는 두 가지 모양**을 놓치고 있었습니다.

```
password=hello                          → [민감정보 제거됨]      ✓
API_KEY: sk-test                        → [민감정보 제거됨]      ✓
{"api_key":"sk-live-abcdef"}            → {"api_key":"sk-live-abcdef"}     ✗
{"token": "sk-live-abcdef"}             → {"token": "sk-live-abcdef"}      ✗
Authorization: Bearer sk-live-abcdef    → Authorization: Bearer sk-live-abcdef  ✗
```

설정 파일 한 조각을 복사하면 이름과 콜론 사이에 **따옴표**가 들어갑니다. `curl` 명령을
복사하면 자격 증명이 **한 단어 뒤에** 있습니다. 규칙은 `이름: 값` 만 보고 있었습니다.

둘 다 게이트웨이로 그대로 나갔습니다.

## 고쳤습니다

```
{"api_key":"sk-live-abcdef"}            → {[민감정보 제거됨]"}
Authorization: Bearer sk-live-abcdef    → [민감정보 제거됨]
```

Authorization 은 **줄 끝까지** 지웁니다. 다음 공백까지만 지우면 `Bearer` 라는 단어를 지우고
토큰을 보내게 됩니다.

## 왜 못 잡았는가

시험이 이랬습니다.

```go
if strings.Contains(got, "hello") || strings.Contains(got, "sk-test") || … {
    t.Fatalf("secret was not redacted")
}
```

**비밀이 사라졌는지만 봅니다.** `redact` 가 빈 문자열을 돌려줘도 통과합니다. 실제로 그렇게
바꿔 보니 통과했습니다.

이건 안전한 실패가 아닙니다. redaction 은 **밖으로 나가는 생각 본문**에 걸리므로, 전부 지우면
Dream 은 아무것도 못 받고 엉뚱한 소리를 합니다. 그것도 이 시험은 못 봅니다.

## 세 개로 나눴습니다

```
✓ 비밀이 사라진다 (JSON·Authorization 포함)
✓ 비밀 주변의 생각은 남는다 ← 이게 없으면 "전부 지우기"가 정답이 됩니다
✓ 숨길 게 없는 글은 한 글자도 안 바뀐다
```

세 번째가 중요한 이유: redaction 이 평범한 글에서 잘못 터지면 설치된 모든 Dream 이 조용히
나빠지고, **아무것도 그걸 알려 주지 않습니다.** `토큰 한도를 4096으로 올렸다`,
`401 unauthorized` 같은 문장이 그대로인지 확인합니다.

## 확인한 것

변형 둘 다 잡혔습니다.

| 바꾼 것 | 잡은 시험 |
| :--- | :--- |
| `redact` 가 전부 지우게 | 주변 생각이 남는지 보는 시험 |
| **예전 규칙으로 되돌리기** | JSON 조각에서 `sk-live-abcdef` 가 살아남음 |

두 번째가 이 수정이 진짜라는 증거입니다.
