# v0.30.1 — 갈래를 만들 방법이 없었습니다

v0.24.0에서 갈래를 만들고, v0.25.0에서 렌즈를, v0.26.0에서 결정 기록을, v0.27.0에서 되짚기를,
v0.28.1과 v0.29.0과 v0.29.1에서 내보내기·MCP·검색까지 갈래를 실어 날랐습니다.

**그런데 갈래를 만들 방법이 없었습니다.**

## 무엇이 잘못됐나

갈래를 만들고 생각을 넣는 자리는 **연결 패널** 안에 있었습니다. 그 패널을 여는 방법은 메모의
**"관련 N" 칩** 하나뿐이었고, 그 칩은 **관련된 생각이 있을 때만** 그려집니다.

즉 새 캔버스에서 **처음 적은 생각**에는 칩이 없고, 칩이 없으면 패널이 안 열리고, 패널이 안 열리면
갈래가 없습니다.

브라우저로 확인했습니다. 빈 공간에 생각 하나를 적고 눌러 봤습니다.

```
notes on canvas: 1
related chips  : 0
note panel open: false
branch UI found: false
```

세 릴리스 동안 그 위에 쌓은 것 전부가 **닿을 수 없는 기능** 위에 있었습니다.

## 왜 못 봤나

만드는 내내 API로 확인했습니다. `POST /spaces/{id}/branches`는 처음부터 잘 됩니다. 통합 테스트도,
MCP 확인도, 내보내기 확인도 전부 API를 거쳤습니다.

**사람이 지나는 길만 지나지 않았습니다.**

## 고친 것

메모 메뉴(⋮)에 **연결과 갈래**를 넣었습니다. 관련된 생각이 있든 없든 항상 있습니다.

그리고 패널 여는 일과 **"관련 생각 모으기"를 분리**했습니다. 기존 경로는 패널을 열면서 관련
메모들을 이 메모 주위로 **재배치**합니다. 생각 하나를 갈래에 넣으려고 캔버스가 흐트러지는 걸
받아들여야 할 이유는 없습니다.

- `관련 N` 칩 → 예전처럼 모으기(재배치 포함)
- 메모 메뉴 → 패널만 열기(아무것도 안 움직임)

## 테스트

e2e에 넣었습니다. **생각 하나뿐이라 칩이 없는 상태**에서 메뉴로 패널을 열고 갈래를 만드는 데까지
갑니다. 이 기능이 닿을 수 있는지를 확인하는 유일한 방법은 브라우저입니다.

## 확인한 것

- 전체 Go 테스트 통과, 웹 53개 통과, **e2e 18개 통과**
- 빈 DB에 생각 하나 → 칩 0개 → 메뉴 → 패널 열림 → 갈래 생성 성공, 브라우저로 확인
