# v0.50.4 — 읽기 전용이라고 말해 놓고 편집기를 내주던 문제

병합 직후 main 의 CI 가 빨갛게 됐습니다. 조사해 보니 **테스트가 옳았고 제품이 틀렸습니다.**

## 무엇이 잘못됐나

읽기 전용 공간에서 화면은 이렇게 말합니다.

> 읽기 전용으로 공유된 공간입니다. 댓글은 남길 수 있습니다.

그런데 **그 안내 바로 아래 메모 카드는 계속 편집 가능**했습니다. 안내가 뜬 뒤로 15초를
기다려도 그대로였습니다. 잠깐의 경합이 아니라 **영영 그 상태**였던 것입니다.

원인은 한 줄입니다. 카드를 만드는 `useEffect` 가 `readOnly` 를 **쓰면서 의존성 목록에는
넣지 않았습니다.**

권한은 공간 목록과 함께 오고, 메모는 다른 요청으로 옵니다. 메모가 먼저 도착하면 카드는
"권한 모름 = 쓸 수 있음" 상태로 한 번 만들어지고, 뒤늦게 권한이 도착해도 **다시 만들어지지
않습니다.** 안내만 바뀌고 카드는 그대로입니다.

읽는 사람은 편집기에 글을 칠 수 있고, 저장은 거부됩니다. **화면이 되지 않을 일을 권하고
있었습니다.**

## 린터는 처음부터 알고 있었습니다

```
CanvasPage.tsx:814:11  react-hooks(exhaustive-deps):
  React Hook useEffect has missing dependencies: 'readOnly', ...
```

경고로만 떠 있었고 CI 는 경고로 실패하지 않습니다. 이 경고는 **사실을 말하고 있었습니다.**

## 재현

CI 에서는 열 번에 한 번쯤 나던 실패라 플레이크처럼 보였습니다. 어느 요청이 먼저 닿느냐가
기계 사정이기 때문입니다. 그래서 **순서를 테스트가 직접 정하도록** 바꿨습니다 — 공간 목록
응답을 일부러 늦춰, 메모가 항상 먼저 도착하게 합니다.

그러자 이 상자에서 **매번** 실패합니다. 플레이크가 아니라 재현 가능한 결함이었습니다.

```
고치기 전   ✘ says so instead of offering an editor that cannot save  (18.8s, 시간 초과)
고친 뒤     ✓ 같은 시험                                               (2.7s)
```

되돌려서 다시 확인했습니다. **되돌린 코드가 실제로 빌드됐고 번들 해시가 실제로 바뀐 것을
먼저 확인한 뒤에** 결과를 믿었습니다 — 빌드가 깨진 채 옛 번들이 서빙되면 시험은 아무것도
증명하지 않으니까요.

```
✘ 의존성에서 readOnly 제거  → 빌드 성공, 번들 해시 변경 확인, 시험 다시 실패 (19.7s)
```

## 무엇을 고쳤나

의존성 목록에 `readOnly` 를 넣었습니다. 권한이 도착하면 카드가 다시 만들어집니다.
