# v0.53.1 — 큰 공간도 자기 백업으로 돌아옵니다

왕복을 다 만들어 놓고 **정작 큰 공간에서는 쓸 수 없었습니다.**

가져오기에는 한 번에 200개라는 상한이 있습니다. 그런데 이 캔버스는 **2000개짜리 공간**을
염두에 두고 만들어졌습니다(`opening-view.ts` 에 그 측정이 그대로 적혀 있습니다). 즉 백업이
가장 중요한 크기의 공간이 **자기 백업으로 되돌아올 수 없었습니다.**

## 화면이 알려 주는 방법이 더 나빴습니다

상한에 걸리면 이렇게 말합니다.

> 한 번에 최대 200개의 생각을 가져올 수 있습니다. 입력을 나누어 다시 시도해 주세요.

**나누면 망가집니다.** 머리말은 첫 조각에만 들어갑니다. 두 번째 조각부터는 umm 의 파일로
보이지 않으므로, 지난 다섯 릴리스에서 고친 것이 전부 되돌아옵니다.

```
나눈 두 번째 조각을 읽으면

  "제목이 있는 생각"      제목이 있는 생각의 본문
                        - id: `f2543505-…`          ← 본문에 다시 붙음
  "Thought"             제목이 없는 생각의 본문       ← 제목이 다시 "Thought"
  "Connections"         - `f254…` --related--> …    ← 연결 목록이 생각이 됨
  "Lines of thinking"   - **되돌리기 실험** — …
```

## 상한은 남의 마크다운을 위한 것입니다

상한이 있는 이유는 **큰 보관함을 한 번에 쏟아붓지 않게** 하기 위해서입니다 — 읽어 본 적 없는
파일에서, 예상 못 한 개수가. umm 이 내보낸 파일은 둘 다 아닙니다. 그 안의 생각은 전부 이미
umm 공간에 있던 것이고, 되살리는 것은 **작정하고 하는 일**입니다.

이제 상한은 **umm 이 만든 파일이 아닐 때만** 적용됩니다. 남의 마크다운은 예전 그대로
200개에서 막히고, 같은 안내가 나옵니다.

## 검증

```
umm 내보내기 250개        →  isExport=true,  막히지 않음
평범한 마크다운 250개      →  isExport=false, 막힘
```

```
✘ 상한을 내보내기에도 적용 (= 이전 동작)  →  "자기 백업으로 돌아온다" 시험 실패
```

잘라 낸 조각이 **내보내기로 인식되지 않는다는 것**도 시험으로 고정했습니다 — 그게 바로
"나누세요" 가 잘못된 안내인 이유이기 때문입니다.

## 판단이 들어간 부분

안전장치를 한쪽에서 걷어낸 것이므로 적어 둡니다. 2000개짜리 공간을 되살리면 **요청이 2000번**
나갑니다. 진행 표시줄이 있어 진행 상황은 보이지만, 시간이 걸립니다. 상한을 그대로 두는 편이
낫다고 보시면 되돌리기 쉬운 한 줄입니다.
