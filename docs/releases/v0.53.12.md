# v0.53.12 — 검토 요청과 API 키에도 같은 규칙을

같은 것을 마지막 두 곳에서 끝냅니다.

## 검토 · 승인

`load()` 에 **`catch` 가 아예 없었습니다.** 실패하면 목록이 빈 채로 남고 화면은 이렇게
말합니다.

> 현재 검토 요청이 없습니다.

**남의 일을 붙잡고 있는 화면**에서 "기다리는 게 없다" 고 말하는 것은 가장 나쁜 방향의
오답입니다. 검토자는 안심하고 창을 닫습니다.

## 개인 설정 · API 키와 웹훅

세 요청을 `Promise.all` 로 묶고 실패를 `.catch(() => undefined)` 로 삼켰습니다. 그래서
**셋 중 하나만 실패해도 세 목록이 전부 비었습니다.**

```
/preferences 가 실패  →  "아직 만든 키가 없습니다"
                         "등록한 웹훅이 없습니다"
```

키가 살아 있는지 확인하러 온 사람에게 **"키가 없습니다"** 라고 답한 것입니다. 자격 증명을
다루는 화면에서요.

이제 `Promise.allSettled` 로 **각각** 불러오고, 각각이 도착했는지 따로 말합니다. 웹훅은 잘
왔는데 키 쪽에 "불러오지 못했습니다" 를 띄우는 것도 **반대 방향의 거짓말**이라, 실패한
쪽에만 붙습니다.

## 검증

```
✘ 승인 화면이 실패해도 "요청 없음" 카드 표시  →  시험 실패
✘ 설정이 실패해도 "키 없음" 표시              →  시험 실패
```

키 시험은 **웹훅 쪽에는 오류가 뜨지 않는 것**까지 확인합니다 — 한쪽 실패가 다른 쪽을
물들이지 않아야 하니까요.
