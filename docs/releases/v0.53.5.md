# v0.53.5 — "다른 기기는 없습니다" 라고 말하면 안 되는 순간

서버 쪽에서 "실패" 를 "없음" 으로 말하던 열두 군데를 v0.53.3·v0.53.4 에서 고쳤습니다.
같은 일이 **화면 쪽에도** 있었습니다. 그리고 그중 하나는 하필 **보안 화면**입니다.

## 개인 설정 · 로그인한 기기

목록을 불러오지 못하면 빈 배열로 두었습니다.

```ts
api<{ sessions: Session[] }>('/sessions', { silent: true })
  .then((value) => setSessions(value.sessions))
  .catch(() => setSessions([]));      // ← 실패를 빈 목록으로
```

빈 목록이면 화면은 이렇게 말합니다.

> 로그인 기기가 이 브라우저뿐입니다.

**"누가 내 계정에 들어와 있나" 를 확인하러 온 사람에게, 아무도 없다고 답한 것입니다.**
게다가 `silent: true` 라서 실패했다는 알림조차 뜨지 않습니다. 조용히, 안심시키는 거짓말을
했습니다.

## 이제

```
로그인한 기기를 불러오지 못했습니다. 다른 기기가 있는지 확인할 수 없습니다.   [다시 시도]
```

`다른 기기 모두 로그아웃` 버튼도 함께 잠급니다 — **보지도 못한 것을 끝내겠다고 제안하지
않습니다.**

**모르는 것과 없는 것은 다른 답이고, 안심되는 쪽은 하나뿐입니다.**

## 검증

```
✘ 실패를 다시 빈 목록으로  →  "확인할 수 없습니다" 가 사라져 시험 실패
```

되돌리기가 **빌드에 성공하고 번들이 실제로 바뀐 것**을 확인한 뒤에 믿었습니다.

## 함께 본 것들

`DecisionsPage` 는 이미 `setFailed(true)` 로 구분하고 있었습니다 — 옳은 방식이 이미
코드베이스 안에 있었습니다.

`QuickNavigator` 도 실패 시 빈 목록이 되지만, 이쪽은 조용하지 않아서(오류 알림이 뜹니다)
이번에는 두었습니다.

## 제 측정이 틀렸던 일

단위 시험 14개가 실패해서 잠깐 놀랐습니다. 원인은 제 변경이 아니라 **제가 붙인
`--environment=node`** 였습니다. `api.test.ts` 는 `localStorage` 와 `window` 가 필요합니다.
원래 환경에서는 16개 모두 통과합니다. 순수 로직 파일에만 쓸 수 있는 지름길이었습니다.
