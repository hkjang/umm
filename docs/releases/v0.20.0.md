# umm v0.20.0 — 기록해 둔 상충을 읽어 오기

umm은 v0.11.0부터 "이 둘은 서로 안 맞는다"를 **기록**할 수 있었습니다. 그런데 아무것도 그걸 읽어 오지 않았습니다. 캔버스에서 다른 연결과 똑같은 선으로 보일 뿐이라, 사람이 실제로 묻고 싶은 것 — **"여기서 뭐가 서로 안 맞지"** — 에 답이 없었습니다.

---

## 1. 탐지가 아니라 기록입니다

v0.16.0 릴리스 노트에 이렇게 썼습니다.

> 모순은 항목 자체가 없습니다. 만들지 않은 기능을 자리로 광고하지 않습니다.

지금 항목을 추가하면서 그 원칙을 어기지 않으려면, **다른 것을 세고 있다**는 게 분명해야 합니다.

umm은 여전히 두 노트를 읽고 모순이라고 **판단하지 않습니다.** 이건 사람이나 에이전트가 `contradicts` 연결로 **표시해 둔 것**을 읽어 오는 기능입니다.

### 그래서 0일 때는 표시하지 않습니다

"기록해 둔 상충 0"은 **"이 워크스페이스에 모순이 없다"**로 읽힙니다. 실제 뜻은 **"아무도 표시하지 않았다"**입니다.

없을 때는 숫자가 아니라 침묵이 맞습니다. API 문서와 MCP 도구 설명에도 같은 말을 적어 두었습니다 — 빈 결과는 "없음"이 아니라 "기록된 것 없음"입니다.

---

## 2. 어디서 볼 수 있나

| 경로 | 용도 |
| :--- | :--- |
| 아침 브리핑 | 개수와 함께 최대 3건, 누르면 해당 생각으로 |
| `GET /api/v1/contradictions` | 전체 (`?spaceId=`로 한 공간만) |
| MCP `find_contradictions` | 에이전트가 "내 기억에서 뭐가 충돌하지"를 물을 수 있게 |

각 항목은 **양쪽 생각과 누가 기록했는지**(사람 · 에이전트 · Dream)를 함께 싣습니다.

---

## 3. 테스트로 고정한 것

- **방향**: 상충에는 방향이 있습니다(A가 B를 반박). 나오는 길에 뒤바뀌면 누가 무엇을 반박하는지가 뒤집힙니다.
- **선택성**: `supports` 같은 다른 연결이 섞이지 않습니다.
- **아무도 기록 안 했으면 빈 결과** — 검사한 것처럼 보이면 안 됩니다.
- **삭제된 생각**은 제외 — 사라진 쪽과의 상충은 남아 있을 이유가 없습니다.
- **남의 공간**은 제외.

---

## 4. 순서에 대해

로드맵의 1순위는 Thought Agent인데, 그 에이전트가 호출할 도구부터 만들고 있습니다. `merge_thoughts`(v0.19.0)에 이어 `find_contradictions`가 두 번째입니다.

에이전트를 먼저 만들고 도구를 나중에 채우면, 도구가 각각 제대로 동작하는지 확인할 방법이 에이전트를 통해서밖에 없습니다. **도구가 단독으로 쓸모 있고 단독으로 검증되는 상태**로 존재한 뒤 에이전트가 그 위에 서는 편이 낫습니다.

## 업그레이드

스키마 변경이 없습니다. 이미지만 교체하면 됩니다.

```bash
docker run -d --name umm --restart unless-stopped \
  -p 8080:8080 \
  -e POSTGRES_DSN='postgres://umm:password@postgres.internal:5432/umm?sslmode=require' \
  -e BOOTSTRAP_ADMIN='admin' \
  -e BOOTSTRAP_ADMIN_PASSWORD='your-strong-password' \
  -e ENCRYPTION_KEY='your-32-char-random-encryption-key' \
  umm:v0.20.0
```

- 아침 브리핑 응답의 `contradictions`가 **개수에서 목록으로** 바뀌었습니다.
- 이미 `contradicts` 연결을 만들어 둔 배포라면 업그레이드 직후부터 보입니다.
