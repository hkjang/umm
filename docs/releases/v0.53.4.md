# v0.53.4 — 나머지 여섯 군데도 "없습니다" 대신 "못 했습니다"

v0.53.3 에서 여섯 군데를 고쳤습니다. 같은 방식이 **여섯 군데 더** 있었습니다.

```
관련 생각 불러오기 · 생각 군집 · 메모 기록
기록 복원 · API 키 회전 · 검토 요청 처리
```

## 그중 두 개가 특히 나쁩니다

**기록 복원.** 자기가 쓴 글을 되찾으려는 사람에게, 복원이 실패했을 뿐인데
`복원할 기록을 찾을 수 없습니다` 라고 말했습니다. 그러면 **그 버전이 아예 없다고 믿고
찾기를 멈춥니다.**

**API 키 회전.** 이건 전에 직접 보고해 주신 기능입니다. 회전 중 무슨 문제가 생기든
`회전할 활성 키를 찾을 수 없습니다` 였습니다. 정직하게 그렇게 말할 수 있는 것은 **맨 처음
조회 하나뿐**입니다 — 새 키를 만들고, 겹침 기간을 두고, 커밋하는 단계는 다른 이유로
실패하는데, 그걸 "그런 키 없습니다" 라고 하면 **목록에 버젓이 있는 키를 찾아 헤매게**
됩니다.

## 군집과 기록은 404 자체가 늘 틀렸습니다

`Clusters` 와 `NoteHistory` 는 없는 공간·볼 수 없는 공간에 대해 **빈 결과**를 돌려줍니다.
오류를 내지 않습니다. 그러니 그 자리에 도착한 오류는 **전부 진짜 실패**였고, "없습니다" 는
언제나 거짓이었습니다. 불러오기가 깨졌을 뿐인데 **텅 빈 캔버스를 답으로 보여 준** 셈입니다.

## 검증

여기서도 실패를 **실제로 만들었습니다.** 시험 전용 스키마의 `api_keys` 에 삽입을 거부하는
트리거를 걸어, 조회는 성공하고 그 다음 삽입이 진짜로 실패하게 했습니다.

```
✘ 예전처럼 모든 오류를 없음으로       →  404 "회전할 활성 키를 찾을 수 없습니다"
✓ 이제                              →  500 "키를 회전하지 못했습니다"
                                       그리고 원래 키는 여전히 active 입니다
```

없는 키를 회전하려 하면 **여전히 404** 입니다.

## 되돌리기가 처음엔 아무것도 증명하지 않았습니다

첫 되돌리기는 **컴파일되지 않았습니다** — 쓰지 않게 된 import 때문에 빌드가 깨졌고, 시험은
"FAIL" 이라고 나왔습니다. 그건 시험이 잡은 것이 아니라 빌드가 깨진 것입니다. 컴파일되는
형태로 다시 만든 뒤에야 진짜로 잡혔습니다.
