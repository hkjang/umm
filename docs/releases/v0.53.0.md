# v0.53.0 — 색까지 돌아옵니다. 왕복이 끝났습니다

메모 색은 사람이 고르는 것입니다 — 노랑·파랑·보라·초록·빨강·회색. 색으로 갈래를 나누는
캔버스에서 **색은 장식이 아니라 그 생각이 하는 말의 일부**입니다.

그런데 내보내기는 색을 **아예 적지 않았습니다.** 되살리면 전부 노랑이 됐습니다.

## 이제

내보내기가 색을 적고, 가져오기가 그대로 돌려놓습니다.

```
- id: `12fc168d-…`
- type: `question`
- source: `user`
- color: `blue`        ← 새로 적습니다
- canvas: `980, 720`
```

이걸로 왕복이 끝났습니다.

```
생각과 제목      ✓ v0.50.2·v0.50.3
자리             ✓ v0.51.0
연결             ✓ v0.51.0
갈래와 그 이유    ✓ v0.52.0
질문·아이디어     ✓ v0.52.1
색               ✓ 이번
```

## 어제 만든 장치가 오늘 저를 잡았습니다

v0.52.1 에서 **"내보내기가 가져오기가 모르는 항목을 쓰면 실패한다"** 는 계약 시험을 넣었습니다.
그게 만들어 낸 가짜 상황이 아니라 **진짜 변경에서 처음으로 작동했습니다.**

내보내기에 `- color:` 만 추가하고 가져오기는 그대로 둔 채 시험을 돌렸더니:

```
the export writes "color", which web/src/lib/markdown-import.ts does not strip;
a restored thought would carry it in its body
```

이 장치가 없었다면 되살린 생각마다 본문 끝에 ``- color: `blue` `` 가 한 줄씩 붙은 채로
릴리스됐을 것입니다.

## 시험이 스스로를 속이지 못하게

색 시험에는 함정이 하나 있습니다. 기본값이 노랑이므로, **내보내기가 색을 안 적어도**
"파랑이 돌아왔다" 는 시험이 통과할 수 있습니다 — 애초에 파랑이었던 메모라면요. 그래서
내보낸 파일 자체에 ``- color: `blue` `` 가 들어 있는지 **먼저 확인**합니다.

```
✘ 가져올 때 색을 무시  →  "blue" 자리에 "yellow" 가 나와 실패
```

## 적어 둘 것: 내보내기 형식이 바뀌었습니다

`- color:` 한 줄이 늘었습니다. 사람이 읽기에도, 지금 가져오기에도 문제 없습니다. 다만 **예전
버전 umm 으로 가져가면** 그 줄을 메타데이터로 알아보지 못해 본문에 남습니다.
