# v0.64.0 — 시간이 정해져 있으면 분량을 맞춥니다

생각 2,000개는 묶어도 286장입니다. 발표는 20분입니다.

```
          제한 없음              20장
      ━━━━━━━━━━━━━━      ━━━━━━━━━━━━━━━━━━
      슬라이드 1           슬라이드 1
      슬라이드 2           슬라이드 4      ← 다섯이 떠받치는 주장
      슬라이드 3           슬라이드 7      ← 표시해 둔 맞섬
      ...                  ...
      슬라이드 286         슬라이드 281
                          ─────────────────
                          들어가지 못한 생각 수를 표시
```

## AI를 안 씁니다. 못 해서가 아니라 그게 맞아서입니다

이번 것만은 모델을 호출하지 않습니다. 이유가 세 가지, 중요한 순서로:

**1. 언제나 같은 답이 나옵니다.** 미리보기가 읽을 만한 이유가 이것입니다. 모델이 정하면
만들 때마다 달라지고, 그러면 **미리 본 것과 만들어진 것이 다릅니다.**

**2. 게이트웨이가 없어도 됩니다.** 대부분의 설치가 그렇습니다.

**3. 설명할 수 있습니다.** "연결이 하나도 없어서 빠졌습니다"는 사람이 반박하고 고칠 수 있는
문장입니다. "모델이 이걸 골랐습니다"는 아닙니다.

무엇을 남길지는 **이미 사람이 그려 둔 그래프**가 답을 갖고 있습니다 — 다섯이 떠받치는
주장은 아무도 연결하지 않은 생각보다 무겁고, 누군가 굳이 기록해 둔 맞섬은 **같은 메모를
요약해서는 절대 나오지 않는 슬라이드**입니다. 추측이 아니라 사람이 그린 것입니다.

글자는 하나도 읽지 않습니다.

### 못 하는 것도 적어 둡니다

모델이라면 주제와 견줘 무게를 달 수 있고, 그래프는 못 합니다. **이건 그걸 안 합니다.**
다만 손실은 생각보다 작습니다 — 사람은 이미 `선택한 생각만` 으로 무엇으로 만들지 직접 고를
수 있고, 그게 모델이 의도를 추측하는 것보다 나은 답입니다.

## 순서는 안 건드립니다

**무엇이 들어갈지를 정하는 것이지, 어떤 순서일지를 정하는 게 아닙니다.**

그 순서는 `follows` 사슬이거나 캔버스에 늘어놓은 배치이고, 둘 다 사람이 한 일입니다.
남은 슬라이드는 원래 있던 자리 순서 그대로 갑니다. v0.63.0에서 부 나누기가 재배치를 뺀 것과
같은 이유입니다.

## 부 제목도 슬라이드입니다

20장을 골랐는데 24장을 받으면 **고른 분량이 아닙니다.**

그래서 분량은 두 번 적용됩니다: 컴파일 직후 한 번, 부 제목이 끼어든 **뒤에** 한 번 더.
두 번째에서는 부 제목과 맞섬이 일반 슬라이드보다 앞서므로, **부로 나누면 내용 슬라이드가
그만큼 줄어듭니다.** 분량을 정한다는 게 그런 뜻입니다.

분량을 12장 미만으로 잡으면 부 나누기는 아예 동작하지 않습니다 — 짧은 발표는 나눌 필요가
없고, 분량이 먼저 적용되기 때문입니다. 시험을 쓰다가 확인했습니다. 처음엔 8장으로 시험을
썼는데, `sectioning never ran, so this proves nothing about headings under a cap` 이
걸렸습니다. **아무것도 증명하지 않는 시험**이었습니다.

## 빠진 건 세어서 말합니다

남의 공간에서 생각을 조용히 빼는 것, 이것만은 하면 안 됩니다.

`Trimmed` 는 `Excluded` 와 **따로 둡니다.** 뜻이 다르고 대처도 다르기 때문입니다 —
제외는 작성자가 분석에서 빼 둔 것이라 아무것도 되돌리지 못하고, 이건 **분량을 늘리면 그대로
돌아옵니다.** 둘을 합쳐 세면 제외하지 않은 생각을 제외했다고 말하는 셈이고, 정작 사람이
할 수 있는 조치는 화면에서 사라집니다.

만들어진 덱에도 `trimmed_count` 로 남습니다. 나중에 목록을 볼 때 다시 컴파일해서 알아내면
**그 덱에 대한 질문에 오늘에 대한 사실로 답하는 것**이 되기 때문입니다.

## 세 개의 숫자가 나란히 갑니다

`thought_count`, `excluded_count`, `trimmed_count` — 뜻이 다른 정수 세 개가 인자로 붙어
있으면 자리가 바뀌어도 컴파일러가 안 잡습니다. 그래서 통합 시험이 **셋을 서로 다른 값
(3 / 1 / 7)** 으로 넣고 읽어 옵니다. 변형으로 저장을 0으로 바꿔 봤더니 잡혔습니다.

## 확인한 것

```
✓ 떠받치는 게 많은 슬라이드가 남고 혼자인 슬라이드가 빠짐
✓ 남은 슬라이드는 원래 순서 그대로
✓ 맞섬 슬라이드는 1장만 남겨도 그게 남음
✓ 빠진 생각이 전부 보고되고, 남은 생각은 보고되지 않음
✓ 분량 없음 / 0 / 음수 / 슬라이드보다 큰 값 → 아무 일도 안 함
✓ 두 번 돌려 같은 결과, 동점은 앞선 슬라이드가 이김
✓ 부 제목이 끼어도 총 장수는 고른 분량 그대로
✓ 미리보기와 만들기가 같은 분량을 보냄
✓ 세 개의 count 가 서로 섞이지 않고 저장·복원됨
```

| 바꾼 것 | 잡은 것 |
| :--- | :--- |
| 맞섬 보호 제거 | 맞섬 슬라이드가 먼저 잘림 |
| 생각 수를 안 셈 | 아무 슬라이드나 남음 |
| 동점을 뒤 슬라이드에 | 두 번 돌리면 다른 발표 |
| 순위대로 출력 | 발표 순서가 재배치됨 |
| 빠진 생각 기록 안 함 | 조용히 사라짐 |
| 잘린 장수 안 셈 | 화면이 0이라고 말함 |
| `Compile` 이 분량 무시 | 분량이 아무 효과 없음 |
| 부 나눈 뒤 재적용 제거 | 20장 요청에 24장 |
| 만들기에서 분량 누락 | 미리 본 것과 다른 덱 |
| 미리보기에서 분량 누락 | 고른 분량이 화면에 안 보임 |
| 빠진 생각 안내 숨김 | 조용히 사라진 걸 화면도 모름 |
| 저장할 때 `trimmed_count` 를 0으로 | 되돌려 읽으면 0 |
