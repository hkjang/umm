# v0.65.0 — 왜 이었는지

연결 종류는 **어떤** 연결인지를 말합니다. **왜** 이었는지는 아무것도 말해 주지
않았습니다. 여섯 달 뒤에 남는 질문은 그쪽이고, 가장 먼저 사라지는 것도 그쪽입니다.

```
        전                              후
    ━━━━━━━━━━━━━━━━━            ━━━━━━━━━━━━━━━━━━━━━━━━━━━
    A --뒷받침함--> B             A --뒷받침함--> B
                                   왜: 지난 두 분기 회고록이
                                       같은 안건을 다시 올렸다
```

## 그을 때 묻지 않습니다

선을 그을 때 사람은 대개 **이유를 아직 말할 수 없습니다.** 두 생각이 붙는다는 건 먼저
알고, 이유는 그 뒤에 옵니다. 그 순간에만 물으면 둘 중 하나입니다 — 손을 멈추게 하거나,
질문을 채우려고 쓴 문장만 쌓이거나.

그래서 `PUT /edges/{id}/reason` 은 만들기와 **별개 호출**이고, 화면에서도 생각 패널의
`직접 연결 · 백링크` 목록에서 나중에 적습니다. 나중에 못 적으면 **애초에 안 적힙니다.**

## 010이 지운 것과는 다릅니다

`relation` 에서 자유 텍스트를 빼낸 건 v0.10.0이었습니다. 그때 문제는 **한 컬럼이 의미와
출처 둘을 담고 있었던 것**입니다 — 아무나 `relation='dreamed'` 를 보내 umm이 찾은 척할 수
있었고, 5,000자 문자열이 모든 화면에 렌더링됐습니다. 이유를 적으면 안 된다는 판정이
아니었습니다.

그래서 **자체 컬럼**입니다. 의미는 검사되는 어휘로 남고, 문장은 문장으로 남습니다.

## 비어 있는 게 정상입니다

대부분의 연결에는 이유가 없고, 그건 **안 적었다는 뜻이지 빠졌다는 뜻이 아닙니다.**
빈 자리를 결함처럼 보이게 하면 남의 그래프 전체가 할 일 목록이 됩니다. 화면은 아무것도
말하지 않습니다.

## 자르지 않고 거절합니다

200자입니다. 넘으면 400과 함께 **얼마까지인지** 알려 줍니다. 210자를 친 사람은 몇 자를
줄여야 하는지 알아야 하고, **남의 문장을 반만 저장하는 것은 안 하는 것보다 나쁩니다.**

길이는 **글자 수**로 셉니다. 바이트로 세면 한국어 허용량이 조용히 3분의 1이 됩니다.
SQL `char_length` 와 Go `utf8.RuneCountInString` 이 같은 것을 셉니다.

## 함께 막은 권한 구멍

세 번째 문을 내다가 앞의 둘을 봤습니다.

| 경로 | v0.64.0까지 |
| :--- | :--- |
| `POST /spaces/{id}/edges` | `notes:write` 검사 있음 |
| `DELETE /edges/{id}` | **없음** |
| `POST /edges/{id}/accept` | **없음** |

**`notes:read` 만 가진 API 키가 남이 그은 연결을 지울 수 있었고, umm이 추측한 연결을
채택해 그래프에 넣을 수도 있었습니다.** 셋 다 막았고, 시험이 **네 문을 전부** 걷습니다 —
한 문만 빠뜨리는 것이 이 결함이 계속 돌아오는 모양이기 때문입니다.

## 브라우저가 잡은 것

Go 시험 10개가 전부 통과하는 상태에서 e2e가 떨어졌습니다. **저장은 됐는데 화면에 안
나왔습니다.**

`reason` 을 공간 읽기(`ListNotes`)와 쓰기에는 넣고, **연결 패널이 실제로 쓰는
`Backlinks` 에는 안 넣었습니다.** 적으면 나타났다가 다시 열면 사라졌습니다. 같은 실수가
`AcceptSuggestion` 과 Dream 발전 조회에도 있었습니다 — **한 컬럼을 읽기 경로 하나에만
추가하는 것**, 위의 권한 구멍과 같은 모양입니다.

시험을 "경로 하나"가 아니라 **"모든 경로"** 로 다시 썼습니다. 브라우저 없이는 못 잡았을
버그입니다 — API도 DB도 내내 옳았습니다.

## 확인한 것

```
✓ 쓰고, 읽고, 나중에 적고, 지움
✓ ListNotes · Backlinks · AcceptSuggestion 전부에서 돌아옴
✓ 한국어 200자 통과, 201자 거절 (SQL·Go 양쪽)
✓ 거절된 이유는 저장되지 않음
✓ 편집 권한 없으면 못 씀, 소유자는 씀
✓ 네 개의 연결 쓰기 경로 전부 notes:write 요구
✓ 내보내기에 실리고, 가져오기가 같은 형태로 읽음
✓ (origin) 은 읽고 지나감 — 파일이 출처를 주장할 수 없음
✓ 맞섬 슬라이드에 그대로 올라가고, 반대로 그어도 마찬가지
✓ 읽기 전용 공간에는 쓰기 수단을 안 보여 줌
✓ 저장 실패해도 친 문장이 남음
✓ 브라우저에서 적고, 새로 고치고, 다시 열어도 있음
```

| 바꾼 것 | 잡은 것 |
| :--- | :--- |
| 만들 때 이유 안 저장 | 왕복에서 사라짐 |
| 읽을 때 이유 안 가져옴 | 왕복에서 사라짐 |
| 권한 검사 제거 | 남의 공간에 씀 |
| 길이를 바이트로 | 한국어 66자에서 거절 |
| 공백을 이유로 저장 | 공백으로 된 이유 |
| 맞섬 슬라이드에서 제거 | 슬라이드가 이유를 잃음 |
| 한 방향만 색인 | 반대로 그으면 이유 사라짐 |
| `DELETE` 권한 검사 제거 | 읽기 키가 연결 삭제 |
| `accept` 권한 검사 제거 | 읽기 키가 추측을 채택 |
| 내보내기에서 이유 제거 | 백업이 왜를 잃음 |
| 가져오기에서 이유 무시 | 되돌려도 왜가 안 옴 |
| 재시도 초안에서 이유 제거 | 두 번째 시도에서 왜가 사라짐 |
| `(origin)` 을 이유로 읽음 | 출처가 이유로 둔갑 |
| 화면이 이유 안 보냄 | 적어도 저장 안 됨 |
| 저장 결과가 패널에 안 감 | 적어도 화면이 그대로 |
| 실패 시 초안 비움 | 친 문장이 사라짐 |
