# v0.56.0 — 떠난 사람이 남긴 공간이 보입니다

관리 기능 고도화, 두 번째입니다.

계정을 **비활성화해도 그 사람이 가진 것은 그대로 남습니다.** 소유한 공간은 계속 그 사람
것이고, 공유받은 사람만 들어갈 수 있고, **넘길 방법이 없었습니다.** 관리 화면은 공간 개수만
세면서 아무 문제 없다는 얼굴을 하고 있었습니다.

## 이제 보입니다

`관리 → 공간과 참여자`

```
공간            소유자              참여자   생각
분기 회고       hyunji  [비활성]      3      412
```

**떠난 사람이 소유한 공간만** 을 켜면 그것만 남습니다. 퇴사 처리에서 실제로 막히던 지점이
바로 이것입니다.

참여자 숫자를 누르면 **누가 어떤 권한으로 들어와 있는지** 펼쳐 봅니다. 비활성 계정은
참여자 목록에서도 표시됩니다.

## 넘기기

활성 사용자에게 소유권을 넘깁니다. 규칙은 셋입니다.

- **이전 소유자가 아직 활성이면 관리 권한으로 남습니다.** 관리자가 공간을 옮겼다고 해서
  쓰던 사람에게서 조용히 빼앗아서는 안 됩니다.
- **비활성이면 아무것도 남기지 않습니다.** 이게 이 기능이 존재하는 이유입니다.
- **수집함은 넘길 수 없습니다.** 사람마다 하나씩 있는 개인 공간이고, 넘기면 남의 서랍을
  건네주는 동시에 그 사람이 다음에 적을 생각이 갈 곳을 없애는 일입니다.

받는 사람이 이미 참여자였다면 그 참여 기록은 지웁니다 — 소유는 참여가 아니고, 남겨 두면
사실보다 약한 말을 하게 됩니다.

넘긴 일은 감사 로그에 `space.transfer` 로 남습니다. 어제 만든 필터로 바로 찾을 수 있습니다.

## 검증

```
✓ 비활성 소유자의 공간만 골라내기
✓ 참여자와 권한 목록
✓ 수집함 넘기기 거부
✓ 넘긴 뒤 소유자가 바뀌고, 받는 사람의 참여 기록은 사라지고,
  떠난 이전 소유자에게는 권한을 주지 않음
✓ 활성 이전 소유자는 manage 로 남음
```

## OpenAPI 드리프트 시험에 걸렸습니다

새 경로 세 개를 `docs/openapi.yaml` 에 넣지 않아 **시험이 실패했습니다.** 문서와 라우트가
어긋나는 것을 잡으라고 있는 시험이고, 제대로 잡았습니다. 감사 로그의 새 질의 문자열도 같이
적었습니다.
