# v0.53.8 — 정리 버튼이 "옮겼습니다" 라고 거짓말하지 않습니다

읽기 전용 공간에서 **캔버스 정리**가 그대로 열려 있었습니다.

```
생각 군집 · 겹침 정리 · 연결한 생각 모으기      (툴바 3개)
생각 군집 모으기 · 연결한 생각 모으기            (메뉴 2개)
카드의 `관련 N` 칩                              (1개)
```

여섯 군데가 전부 메모 위치를 **저장**합니다. 읽기로 초대받은 사람이 누르면

1. 화면에서 메모가 움직이고
2. `겹친 생각 3개만 옮겼습니다` 라고 **성공했다고 말하고**
3. 저장은 전부 거절당합니다

**되지 않은 일을 됐다고 말하는 것**이라, 지금까지 고친 것들 중 가장 나쁩니다.

## 버튼만 숨기지 않았습니다

여섯 군데를 각각 막으면 일곱 번째가 생길 때 또 빠집니다. 그래서 **모든 정리가 지나가는
한 곳**(`applyPlacements`)에서 먼저 막고, 그 위에 버튼도 숨겼습니다.

## 키보드에는 숨길 버튼이 없습니다

- `Delete` — 읽기 권한인데도 **"선택한 생각 3개를 삭제할까요?"** 라고 물었습니다. 버튼이
  없으니 **그 질문 자체가 제안**이었습니다. 이제 묻지 않습니다.
- `Ctrl+Z` — 되돌리기도 위치를 저장합니다. 지금은 스택이 빌 테지만, **우연히 비어 있는 것은
  방어가 아닙니다.**

## v0.50.4 와 같은 실수를 또 할 뻔했습니다

키보드 핸들러의 의존성 목록에 `readOnly` 가 없었습니다. 권한은 이 핸들러가 묶인 **뒤에**
도착하므로, 넣지 않으면 옛 답을 쥔 채 계속 삭제를 제안합니다 — v0.50.4 에서 카드가 편집
가능한 채로 남았던 것과 **똑같은 원인**입니다.

되돌리기로 확인했습니다: 의존성만 빼도 시험이 실패합니다. 이론이 아니라 실제로 늦게
도착합니다.

## 시험이 처음엔 아무것도 증명하지 않았습니다

`Delete` 시험을 처음 썼을 때, **가드를 빼도 통과했습니다.** 카드를 클릭하면 그 안의
textarea 에 눌려 노드가 **선택되지 않았고**, 핸들러는 가드에 닿기도 전에
`selected.length === 0` 으로 돌아갔습니다.

빈 캔버스를 클릭하고 `Ctrl+A` 로 실제 선택한 뒤(`.selected` 가 1개인 것을 확인하고) 눌러야
비로소 가드에 닿습니다. 그제서야 되돌리기 두 개가 모두 잡혔습니다.
