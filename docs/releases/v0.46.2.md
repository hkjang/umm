# v0.46.2 — 생각을 고쳐도 캔버스가 그 생각을 숨기지 않습니다

지난 릴리스에서 **원인을 모른 채 열어 둔 문제**가 있었습니다. E2E가 CI에서만 흔들렸고,
로컬에서는 열두 번을 돌려도 통과했습니다. 이번에 재현했고, **테스트 문제가 아니라 제품
문제**였습니다.

## 재현

CI 러너는 느립니다. 그래서 느리게 만들었습니다 — CPU를 40개 루프로 포화시키고 돌렸습니다.

```
평소                        6/6 통과
CPU 포화                    5/6 실패   ← 재현
```

CI가 남긴 것과 **같은 줄, 같은 메시지**였습니다.

## 원인

포커스 이벤트를 전부 기록했더니 이렇게 나왔습니다.

```
focusin  textarea[생각 내용]                    커서가 도착합니다
ATTR     .react-flow__node visibility: hidden   ★ 노드가 숨겨집니다
focusout textarea -> null                       커서가 사라집니다
ATTR     .react-flow__node visibility: visible  다시 보이지만, 커서는 안 돌아옵니다
```

`sameNode=true`, `present=true`. **DOM에서 사라진 게 아니라 숨겨진 것**이고, 요소를 숨기면
브라우저가 포커스를 떼어냅니다.

왜 숨겨지느냐 — 생각이 하나라도 바뀌면 캔버스는 노드를 **처음부터 다시 만듭니다**. 새로
만든 노드에는 크기 측정값이 없으니 React Flow가 다시 재려고 **숨깁니다**.

크기는 바뀌지 않았습니다. 조금 전과 같은 메모입니다. 그러니 **재던 값을 그대로 넘겨주면**
숨길 이유가 없어집니다.

```
되돌린 채로  4/4 실패
고친 뒤      0/8 실패      (CPU 포화 동일 조건)
전체 스위트  65/65 통과    (CPU 포화 상태)
```

## 사람에게 무슨 일이었나

제목을 붙이고 Enter를 누르면 커서가 본문으로 갑니다 — 이름을 짓던 사람이 어차피 가려던
곳이니까요. 그런데 저장이 끝나면서 노드가 숨겨졌다 나타나고, **커서는 그때 사라졌습니다.**
느린 기기에서는 거의 매번입니다.

깜빡임도 같은 원인입니다. 메모를 고칠 때마다 캔버스의 모든 노드가 숨겨졌다 다시 나타나고
있었습니다.

## 검증

되돌려서 확인했습니다. 새 테스트는 **부하 없이도** 실패합니다.

```
✘ 측정값을 다시 버리게 되돌림 → 숨김 3회 기록, 기대 0회로 실패
```

원인을 검사합니다. 커서가 사라지는지가 아니라 **노드가 숨겨지는지**를 봅니다 — 숨김은 저장할
때마다 일어나고, 그게 커서보다 빠른지는 기기가 얼마나 바쁜지에 달려 있기 때문입니다. 원인을
검사해야 확실히 실패합니다.

## 남겨 두는 것

`arrange.spec.ts:62` 도 CI에서 한 번 흔들렸습니다. 고친 코드를 되돌린 채로 부하를 걸고 네 번
돌렸지만 **네 번 다 통과**했습니다. 이 수정이 그것까지 고쳤다는 증거가 없으므로, **고쳤다고
적지 않고 열어 둡니다.**
