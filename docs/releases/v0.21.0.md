# umm v0.21.0 — 질문과 답, 그리고 검증되지 않던 칸 하나

지난 릴리스에서 `find_open_questions`를 만들려다 **정직하게 만들 수 없어서 멈췄습니다.** 생각을 "질문"으로 표시할 방법이 없어서 `?`로 끝나는지 보는 휴리스틱에 기대야 했고, 상충을 "탐지가 아니라 기록"이라고 그렇게 구분해 놓고 여기서 얕은 추론을 쓰는 건 앞뒤가 안 맞습니다.

우회하는 대신 **표시할 방법을 만들었습니다.**

---

## 1. 파 보니 `kind`가 예전 `relation`과 같은 상태였습니다

`notes.kind`는 요청 본문에서 **검증 없이** 들어오고 있었습니다. 실측:

```
{"kind":"totally-made-up"}   → 저장됨
{"kind":"KKKK…5000자"}       → 저장됨
```

v0.11.0 이전의 `relation`과 정확히 같은 결함입니다. **아무것도 읽어 오지 않아서 아무도 몰랐습니다.**

(같이 확인한 `source`는 서버가 정하고 있어서 `"source":"dream"` 위조는 막혀 있었습니다.)

이제 어휘가 있습니다: `thought` · `question` · `idea`. 어휘 밖의 값은 조용히 바꾸지 않고 **거부**하며 가능한 목록을 알려 줍니다 — 사람이 말하지 않은 종류로 생각을 분류하면 실수가 감춰집니다.

어휘를 작게 둔 것도 의도입니다. umm이 아무것도 하지 않는 종류를 위한 자리는 **없는 기능을 광고하는 것**입니다.

### 쓰는 곳을 전부 고쳤습니다

만들기 경로만 검증하면 **수정 경로가 우회로로 남습니다.** 검증되지 않은 필드가 "고쳐진 뒤에도" 살아남는 방식이 정확히 그것이라, 네 군데를 모두 확인했습니다.

---

## 2. `answers` — 질문을 닫는 관계

열린 질문은 **답이 기록되지 않은 질문**인데, 그래프에 "이 생각이 저 질문에 답한다"고 말할 방법이 없었습니다.

`supports`나 `refines`가 가깝지만 **질문을 닫지는 않습니다.** 그중 하나를 답으로 취급하면 논쟁만 한 노트가 질문을 해결한 것처럼 보이게 됩니다. 테스트로 고정했습니다 — 질문을 둘러싼 네 개의 다른 연결이 있어도 질문은 열린 상태입니다.

### `attempts`

질문을 가리키지만 답은 아닌 연결의 수입니다. **아무도 건드리지 않은 질문**과 **한참 논쟁했는데 결론이 안 난 질문**은 다른 상황이고, 무엇을 먼저 볼지가 달라집니다.

---

## 3. 양쪽 다 표시입니다

umm은 노트를 읽고 "이건 질문이군"이라고 판단하지 않습니다. 물음표로 끝나는 문장이 질문이 아닌 경우도, 물음표 없는 질문도 많습니다. 답도 마찬가지입니다.

그래서 빈 결과는 **"다 답했다"가 아니라 "열린 것으로 표시된 게 없다"**입니다. 상충과 같은 규칙이고, 0일 때 화면에 숫자를 띄우지 않습니다.

포스트잇 메뉴에서 **질문으로 표시**를 누르면 됩니다.

## 5. 드릴 스크립트를 고쳤습니다

`graph-migration-drill.sh`가 010을 **건너뛰고** 나머지를 전부 적용하고 있었습니다. 010이 마지막 마이그레이션이던 동안에는 "010 이전까지"와 같은 뜻이었는데, 이번에 015가 같은 relation 어휘를 좁히면서 **010 없이 015를 적용한 상태에는 010 이전 데이터를 넣을 수 없게** 됐습니다.

주석에는 처음부터 "up to but not including 010"이라고 쓰여 있었고, 코드가 그걸 따라가지 못하고 있었습니다. 이제 010에서 멈춥니다.

## 업그레이드

**마이그레이션이 있습니다** (015).

```bash
docker run -d --name umm --restart unless-stopped \
  -p 8080:8080 \
  -e POSTGRES_DSN='postgres://umm:password@postgres.internal:5432/umm?sslmode=require' \
  -e BOOTSTRAP_ADMIN='admin' \
  -e BOOTSTRAP_ADMIN_PASSWORD='your-strong-password' \
  -e ENCRYPTION_KEY='your-32-char-random-encryption-key' \
  umm:v0.21.0
```

- 어휘 밖의 `kind`가 저장돼 있었다면 `thought`로 옮겨지고 **원래 값은 `legacy_kind`에 보존**됩니다. 원래 검증되지 않던 칸이라 값이 있을 수 있습니다.
- API나 MCP로 임의의 `kind`를 보내던 클라이언트는 이제 **400과 `allowedKinds`**를 받습니다.
- 롤백하면 `answers` 연결이 **삭제**됩니다. 옛 어휘에 같은 뜻의 관계가 없어서, 비슷한 것으로 바꾸면 아무도 하지 않은 주장을 기록하게 됩니다.
