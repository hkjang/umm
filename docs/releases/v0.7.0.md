# umm v0.7.0 — 생각을 다시 만나고, 안전하게 협업하기

v0.7.0은 캔버스에 생각을 모으는 단계에서 한 걸음 더 나아가, 매일 다시 검토하고 팀과 논의하며 자동화에 연결하는 흐름을 완성한 릴리스입니다. 오프라인 환경에서도 변경을 잃지 않도록 동기화 계층을 보강하고, AI 품질·관측성·키 회전·복구·공급망 검증까지 운영 기반을 함께 강화했습니다.

## 주요 변화

### Today 리뷰와 온보딩

- 로그인 후 `/today`에서 다시 볼 생각, 14일 이상 검토하지 않은 생각, 연결되지 않은 생각, 대기 중인 Dream, 최근 댓글을 한 번에 확인합니다.
- 사용자별로 독립된 검토 완료, 1~365일 다시 보기, 중요 항목 고정을 지원해 공유 메모에서도 서로의 리뷰 상태를 덮어쓰지 않습니다.
- 공간 만들기 → 생각 붙이기 → 연결하기 → Dream 확인하기가 실제 데이터에 따라 완료되는 맥락형 온보딩을 추가했습니다.

### 검색과 생각 맥락

- 외부 임베딩 서비스 없이 로컬 192차원 feature hashing과 키워드 점수를 결합하며, 전체 접근 가능 corpus의 오래된 키워드 일치와 2,000자 이후 본문 일치까지 보존하는 하이브리드 검색을 추가했습니다. 광범위한 검색어도 PostgreSQL에서 관련도 순 후보를 제한해 API 메모리·CPU 사용량이 corpus 크기에 따라 무제한 증가하지 않습니다.
- 공간·종류·수정 시각 필터, 결과 점수와 추천 이유, opaque cursor 페이지네이션을 제공합니다.
- 포스트잇의 실제 incoming/outgoing 백링크와 의미 기반 관련 생각을 한 패널에서 확인할 수 있습니다.

### 댓글·멘션·실시간 협업

- 포스트잇 댓글, 답글 parent, 이메일·비ASCII OIDC 사용자명을 포함한 `@username` 멘션, 해결·재개, 권한 기반 삭제를 지원합니다.
- 멘션·댓글 알림은 해당 공간과 포스트잇으로 바로 이동하며 metadata와 전체 미읽음 수를 제공합니다.
- 공간에서 제거된 사용자는 이전에 작성한 생각에 새 댓글이 달려도 접근할 수 없는 알림을 받지 않으며, 삭제된 생각의 댓글은 Today 활동에서 제외합니다. 삭제된 생각으로만 이어진 링크는 남은 생각을 고아 목록에서 숨기지 않고, 댓글 해결·재개는 공간 편집 권한 이상으로 제한합니다.
- 댓글과 멤버·Dream 채택 이벤트도 SSE와 웹훅 이벤트 흐름에 포함됩니다.
- 열린 SSE 연결도 매 event batch마다 같은 PostgreSQL snapshot에서 공간 접근 권한을 다시 확인해, 멤버 제거 직후의 댓글 본문을 전송하지 않고 스트림을 종료합니다.

### 오프라인 동기화와 충돌 병합

- PWA service worker와 manifest를 추가하고, 네트워크 단절 시 mutation을 로컬 queue에 보관합니다.
- 생성 요청에는 자동 `Idempotency-Key`를 부여하고 서버가 사용자별 advisory lock, 요청 fingerprint 기반 24시간 pending 예약과 성공 응답을 기록해 중복 생성을 막습니다.
- 같은 메모의 연속 PUT은 마지막 상태로 합치며 재연결 시 자동 replay합니다.
- 400·404처럼 다시 시도해도 적용할 수 없는 변경은 사유를 알리고 queue에서 제거하며, 409 충돌과 일시 오류만 안전하게 보존합니다.
- 댓글 저장 중 DB·commit·webhook outbox의 일시 오류는 5xx로 구분해 오프라인 queue가 변경을 영구 거절로 오인해 삭제하지 않습니다.
- 메모 삭제와 생각 연결도 유효성·접근 오류만 4xx로 반환하고 DB·commit·outbox 일시 오류는 5xx로 유지해 재연결 queue의 변경 유실을 막습니다.
- 409 충돌은 RFC 9457 Problem Details에 최신 서버 메모를 포함하고, UI에서 내 버전·서버 버전·병합 버전을 비교해 선택할 수 있습니다.

### 접근성과 프런트엔드 성능

- 선형 생각 목록, 키보드 focus와 화살표 이동, 명확한 focus ring, 최소 44px 터치 영역, reduced-motion을 추가했습니다.
- Today·Canvas·관리자 등 주요 route를 lazy load하고 PNG 내보내기 라이브러리를 필요할 때만 로드해 초기 bundle을 분리했습니다.

### 서명 웹훅

- 개인 설정에서 `space.updated`, `note.*`, `comment.*`, `member.*`, `dream.accepted` 등의 HTTPS webhook subscription을 관리합니다.
- payload에 delivery UUID와 timestamp를 포함하고 `X-Umm-Signature-256` HMAC-SHA256 서명을 적용합니다.
- 등록과 연결 시점 모두 DNS를 확인하며 사설·loopback·link-local·문서·benchmark·reserved IP와 443 외 포트를 차단합니다.
- 도메인 변경, SSE log, 구독별 webhook outbox를 하나의 PostgreSQL 트랜잭션으로 커밋한 뒤 워커가 `FOR UPDATE SKIP LOCKED`로 처리합니다. 성공 응답과 outbox 사이의 유실 구간을 없애고 프로세스 재시작이나 순간적인 이벤트 폭주에도 대기 항목을 복구하며, 처리 중 중단된 항목은 lease 만료 후 다시 가져옵니다.
- queue 대기 중 구독 소유자가 비활성화되거나 공간 접근 권한을 잃으면 외부 전송 직전에 다시 차단합니다.
- 일시 실패는 최대 세 번 재시도하고 연속 10회 실패 시 subscription을 자동 중지합니다.
- 전달 시도는 at-least-once 방식이므로 수신 측은 `X-Umm-Delivery` UUID로 중복 요청을 멱등 처리해야 합니다.
- 성공·실패가 확정되면 복사된 payload를 즉시 비우고, terminal delivery metadata도 30일 뒤 자동 삭제합니다.

### AI 품질과 관측성

- 관리자가 입력 생각, 기대 단어, 금지 단어를 저장하고 현재 Dream gateway/prompt를 회귀 평가할 수 있습니다.
- grounding·기대/금지 단어·구체성 점수, 모델, prompt version, token, latency와 오류 run을 보존합니다.
- `/api/v1/metrics`에 Prometheus request count, route latency histogram, in-flight, build info를 제공합니다.
- 표준 `OTEL_EXPORTER_OTLP_ENDPOINT` 또는 `OTEL_EXPORTER_OTLP_TRACES_ENDPOINT`가 있을 때만 OpenTelemetry OTLP HTTP trace exporter를 활성화합니다.

### 보안·키 회전·복구

- AES-256-GCM 암호문을 `v2.<key-id>.<payload>` keyring 형식으로 갱신하고 legacy v1 읽기를 유지했습니다.
- `ENCRYPTION_KEY_PREVIOUS` fallback과 관리자 회전 화면으로 OIDC/AI secret, 암호화 prompt, webhook signing secret을 한 트랜잭션에서 재암호화합니다.
- 브라우저의 로그인 및 인증된 write에서 `Origin`·`Sec-Fetch-Site`를 확인하고 API key 호출은 scope 경계로 분리합니다.
- 관리자·개인 설정·API key 관리 작업은 대화형 브라우저 세션으로 제한해 제한 key의 자격 증명 및 role 기반 권한 상승을 차단합니다.
- `notes:read`만 가진 key의 Today 집계에서는 Dream 본문과 개수를 제거해 `dreams:read` 경계를 유지합니다.
- API key와 웹훅 서명 key의 일회 공개 응답은 멱등 캐시에서 제외해 평문 자격 증명이 DB에 남지 않도록 했습니다.
- 댓글 write는 `notes:write`, metrics는 `metrics:read`, webhook 관리는 `webhooks:write` scope를 사용합니다.
- CI에 Go 취약점 검사, npm high audit, PostgreSQL 17 통합 시험, 실제 dump→별도 DB restore 리허설을 추가했습니다.

### 검증 가능한 릴리스

- offline Docker image archive와 함께 SPDX JSON SBOM, `SHA256SUMS`를 게시합니다.
- image archive에 GitHub artifact provenance와 SBOM attestation을 발급합니다.
- OpenAPI 3.1 계약을 v0.7.0 endpoint, RFC 9457 오류, cursor와 모든 operation ID에 맞춰 갱신했습니다.

## 업그레이드 안내

1. 현재 PostgreSQL과 `ENCRYPTION_KEY`를 백업합니다.
2. `umm-v0.7.0.tar.gz`를 load하고 기존 네 필수 환경변수로 실행합니다. `006_service_improvements` migration은 시작 시 자동 적용됩니다.
3. `/readyz`, 로그인, `/today`, 기존 공간과 Dream 검토함을 확인합니다.
4. master key를 바꾸는 경우에만 새 키를 `ENCRYPTION_KEY`, 기존 키를 `ENCRYPTION_KEY_PREVIOUS`에 넣고 관리자 → 보안에서 회전을 완료한 뒤 이전 키를 제거합니다.
5. trace가 필요하면 표준 `OTEL_EXPORTER_OTLP_*`를, listen 주소 변경이 필요하면 `UMM_HTTP_ADDR`를 선택적으로 설정합니다. 필수 환경변수는 계속 네 개입니다.

기존 REST 성공 응답과 `error` 문자열은 호환됩니다. 오류 Content-Type은 `application/problem+json`으로 표준화되었고 목록 API 일부는 `nextCursor`를 추가했지만 기존 배열 필드는 유지됩니다.

## 릴리스 자산 검증

```bash
sha256sum -c SHA256SUMS
gh attestation verify umm-v0.7.0.tar.gz --repo hkjang/umm
gzip -dc umm-v0.7.0.tar.gz | docker load
docker image inspect umm:v0.7.0
```

첨부 파일:

- `umm-v0.7.0.tar.gz` — 폐쇄망 반입용 multi-stage build Docker image archive
- `umm-v0.7.0.spdx.json` — SPDX JSON SBOM
- `SHA256SUMS` — archive와 SBOM 무결성 checksum
