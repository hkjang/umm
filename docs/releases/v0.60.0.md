# v0.60.0 — 발표 만들기가 실패하면 무엇을 해야 하는지 알려 줍니다

Ptium으로 발표를 만들다 실패하면 이런 게 떴습니다.

```
발표 자료를 만들지 못했습니다. ptium is unreachable: Post
"http://ptium.internal:8080/api/v1/presentations": dial tcp 10.0.3.7:8080:
connect: connection refused
```

```
발표 자료를 만들지 못했습니다. ptium status 401: api key is invalid or expired
```

```
발표 자료를 만들지 못했습니다. ptium returned something that is not the documented
response: json: cannot unmarshal array into Go value of type presentation.deckEnvelope
```

셋 다 **무슨 일이 있었는지는 말하고, 무엇을 해야 하는지는 말하지 않습니다.** 게다가 셋 다
같은 502라서 화면도 구분하지 못했고, 슬라이드를 만들려던 사람에게 **내부 서버 주소**와
**Go 타입 이름**을 보여 줬습니다. 하나는 SQL 제약 이름까지 그대로 나왔습니다.

## 이제 이렇게 나옵니다

```
⚠ Ptium이 umm의 자격 증명을 거부했습니다

Ptium이 umm의 API 키를 받아들이지 않았습니다. 키가 만료됐거나 잘못 설정된
것이며, 여기서 고칠 수 있는 것이 아닙니다. 서비스 관리자에게 Ptium 키를
다시 설정해 달라고 알려 주세요.
```

```
⚠ Ptium이 이 발표 구성을 받아들이지 않았습니다

Ptium이 이 발표 구성을 슬라이드로 만들 수 없다고 답했습니다. 아래 Ptium의
설명이 어느 슬라이드가 문제인지 알려 줍니다. 생각을 줄이거나 나눈 뒤 다시
시도해 보세요.

  Ptium이 보낸 설명
  slide 3: layout "two-column" is not in template basic
```

## 상태 코드가 아니라 **누가 고칠 수 있는가**로 나눴습니다

| 화면에 뜨는 말 | 누구 일인가 | 다시 시도 버튼 |
| :--- | :--- | :---: |
| Ptium에 연결하지 못했습니다 | 아무도 — 서버가 돌아올 때까지 | ✓ |
| Ptium이 제때 답하지 않았습니다 | 아무도 (관리자가 제한 시간을 늘릴 수는 있음) | ✓ |
| Ptium이 umm의 자격 증명을 거부했습니다 | 관리자 | ✗ |
| 그 주소에 Ptium API가 없습니다 | 관리자 | ✗ |
| **Ptium이 이 발표 구성을 받아들이지 않았습니다** | **작성자 본인** | ✗ |
| Ptium 쪽에서 오류가 났습니다 | Ptium 쪽 | ✓ |
| Ptium이 예상과 다른 응답을 보냈습니다 | 관리자 (버전) | ✗ |
| Ptium에는 만들어졌지만 umm이 기록하지 못했습니다 | 확인이 먼저 | ✗ |

**API 키가 틀렸는데 "다시 시도"를 권하지 않습니다.** 될 리 없는 걸 권하는 건 화면이
거짓말하는 것입니다.

마지막 줄이 특히 중요합니다. 덱은 **Ptium에 실제로 만들어져 있고** umm이 그 사실만 저장하지
못한 상태입니다. 그대로 다시 누르면 덱이 하나 더 생깁니다. 그래서 "다시 시도"가 아니라
"먼저 확인해 주세요"라고 합니다.

## 보여 주면 안 되는 것들

```
✗ http://ptium.internal:8080/api/v1/presentations   내부 주소
✗ presentation.deckEnvelope                          Go 타입 이름
✗ presentation_links_space_id_..._key (SQLSTATE 23505)  SQL 제약 이름
✗ <html><title>502 Bad Gateway</title>…nginx/1.24.0    프록시 오류 페이지
```

앞의 셋은 이제 **`admin` 역할에게만** `technical` 로 갑니다. 화면에서는 "기술 정보
(관리자에게만 보입니다)" 아래에 접혀 나옵니다. 고칠 수 있는 사람에게는 필요하고, 나머지에게는
읽을 수도 쓸 수도 없는 것이니까요.

네 번째는 아무에게도 안 갑니다. 프록시가 Ptium 대신 답한 HTML 페이지를 **"Ptium이 보낸
설명"이라고 붙여 놓는 건 두 번 틀립니다** — 프록시는 Ptium이 아니고, 그 페이지는 상태
코드가 이미 말한 것 말고는 아무것도 말하지 않습니다.

## 지난 실패도 읽을 수 있습니다

발표 목록의 **실패** 배지 툴팁이 저장된 Go 오류를 그대로 띄우고 있었습니다. 이제 같은
분류가 뜹니다. 그러려면 분류를 저장해야 해서 `presentation_links.failure_kind` 를
추가했습니다 — 원본 오류는 `error` 에 그대로 남습니다. **고칠 사람에게는 그게 필요하고,
읽을 사람에게는 분류가 필요합니다.**

v0.60.0 이전에 기록된 행은 분류가 비어 있고, 그때는 저장된 원본을 보여 줍니다. 아무것도 없는
것보다는 낫습니다.

## 확인한 것

```
✓ 여섯 가지 실패가 각각 다른 type·failure 로 나옴
✓ 자격 증명 거부에 Ptium의 키 메시지를 옮기지 않음
✓ 422 만 Ptium의 설명을 그대로 옮김 (어느 슬라이드인지 알려 주는 유일한 경우)
✓ 프록시 HTML 은 설명으로 취급하지 않음
✓ 일반 사용자 응답에 technical 없음 / 관리자 응답에는 있음
✓ 연결 실패 메시지에 시도한 주소가 없음
✓ 실패한 덱이 목록에 분류와 함께 남고, 원본 오류도 함께 보존됨
```

변형 셋 다 잡혔습니다.

| 바꾼 것 | 잡은 것 |
| :--- | :--- |
| 예전처럼 502 하나에 Go 오류 붙이기 | 키 메시지와 `ptium status` 가 사용자에게 도달 |
| `technical` 을 모두에게 보내기 | 일반 사용자가 원본 오류를 받음 |
| 프록시 HTML 을 설명으로 넘기기 | `nginx` 가 사용자에게 도달 |
