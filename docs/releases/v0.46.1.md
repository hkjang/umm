# v0.46.1 — 결정 기록의 날짜가 내가 고른 언어를 따릅니다

`결정 기록`의 날짜 한 줄만 **브라우저에게** 무슨 언어를 쓸지 묻고 있었습니다. 앱 전체에서
여기 한 곳뿐이었습니다.

## 한 제품, 같은 날짜, 두 언어

umm을 **English**로 두고, 브라우저는 한국어인 채로 잰 값입니다.

| 화면 | 표시 | 무엇을 따랐나 |
| --- | --- | --- |
| Dreams | `August 25, 2026` | **내가 고른 언어** |
| 결정 기록 | `2026. 8. 25.` | **브라우저 언어** |

같은 날짜입니다. 설정에서 English를 골랐는데 이 줄만 그 선택을 무시하고 있었습니다.

```
src/pages/DecisionsPage.tsx:95
  new Date(point.at).toLocaleDateString()   ← 인자가 없으면 브라우저 로케일
```

앱의 다른 여섯 파일은 모두 i18n의 `formatDate`를 씁니다. 이제 이 줄도 그렇습니다.

## 한국어 화면은 한 글자도 바뀌지 않았습니다

고치면서 형식을 길게 바꾸면, **한쪽 문제를 다른 쪽 문제와 맞바꾸는** 셈이 됩니다. 숫자
형식을 그대로 두어 한국어 사용자가 보던 모습을 유지했습니다.

```
앱 ko:  2026. 8. 25.     ← 이전과 동일
앱 en:  8/25/2026        ← 고쳐짐
```

## 검증

되돌려서 양쪽 방향으로 확인했습니다.

```
✘ 다시 브라우저에게 묻게          → en 에서 "2026. 8. 25." 이 나와 실패
✘ 긴 형식(month: long)으로 바꿈   → ko 가 "2026년 8월 25일" 로 바뀌어 실패
```

두 번째가 중요합니다. **고치는 김에 모양까지 바꾸지 않았다**는 걸 지키는 테스트입니다.
테스트 내내 브라우저는 한국어로 고정되어 있습니다 — 날짜가 브라우저를 따랐다면 두 확인
모두 한국어를 봤을 테니, 그게 이 테스트가 성립하는 조건입니다.

## 덧: E2E 스위트가 CI에서 간헐적으로 흔들립니다

이 변경을 올리는 동안 CI가 이렇게 움직였습니다.

```
1차                    실패   note-card:289 (toBeFocused)
2차                    실패   note-card:289
새 테스트만 skip        통과
테스트를 가볍게 고침     통과
릴리스 노트만 수정       실패   arrange.spec.ts:62  ← 마크다운 한 파일
```

마지막 줄이 결론을 뒤집었습니다. **마크다운 파일 하나가 테스트를 깨뜨릴 수는 없습니다.**
그러니 앞의 실패들도 이 변경 탓이라고 볼 근거가 없습니다 — `skip 하니 통과`를 인과로 읽은
건 **한 번의 실행을 증거로 삼은 제 잘못**이었습니다. 흔들리는 스위트에서 한 번의 통과는
아무것도 증명하지 않습니다.

로컬에서는 전부 통과합니다 — 전체 스위트를, 빈 데이터베이스로, CI와 같은 순서로 돌려도요.
지금까지 흔들린 것은 둘입니다.

| 테스트 | 성격 |
| --- | --- |
| `note-card:289` | Enter 뒤 포커스 (`toBeFocused`) |
| `arrange.spec.ts:62` | 정리 후 좌표 비교 |

**이건 따로 다뤄야 할 문제로 남겨 둡니다.** 이번 릴리스에 끼워 고칠 만큼 작지 않고,
원인을 모른 채 재시도 횟수만 늘리는 건 고치는 게 아니라 가리는 것입니다.

한편 테스트를 가볍게 고친 것은 그대로 둡니다. 원인과 무관하게 더 나은 코드이기 때문입니다.
언어는 계정 설정이라 브라우저에서만 바꿀 수 없는데 — `auth-context`가 로드할 때마다 계정
설정을 로컬 저장소에 덮어씁니다 — 처음에는 `signIn`을 두 번 더 불러 바꿨습니다. 워커 하나로
도는 스위트에서 로그인 두 번은 페이지 로드 여러 번입니다. 이제 **언어를 바꾸는 그 요청
하나**로 바꾸고, 끝나면 되돌립니다.

`가장 최근 120개` 상한은 그대로 둡니다. 페이지가 이미 더 있다고 말하고 있고, 그 상한은
`maxTurningPoints` 에 이유와 함께 적힌 의도된 선택입니다.
