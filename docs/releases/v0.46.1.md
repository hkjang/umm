# v0.46.1 — 결정 기록의 날짜가 내가 고른 언어를 따릅니다

`결정 기록`의 날짜 한 줄만 **브라우저에게** 무슨 언어를 쓸지 묻고 있었습니다. 앱 전체에서
여기 한 곳뿐이었습니다.

## 한 제품, 같은 날짜, 두 언어

umm을 **English**로 두고, 브라우저는 한국어인 채로 잰 값입니다.

| 화면 | 표시 | 무엇을 따랐나 |
| --- | --- | --- |
| Dreams | `August 25, 2026` | **내가 고른 언어** |
| 결정 기록 | `2026. 8. 25.` | **브라우저 언어** |

같은 날짜입니다. 설정에서 English를 골랐는데 이 줄만 그 선택을 무시하고 있었습니다.

```
src/pages/DecisionsPage.tsx:95
  new Date(point.at).toLocaleDateString()   ← 인자가 없으면 브라우저 로케일
```

앱의 다른 여섯 파일은 모두 i18n의 `formatDate`를 씁니다. 이제 이 줄도 그렇습니다.

## 한국어 화면은 한 글자도 바뀌지 않았습니다

고치면서 형식을 길게 바꾸면, **한쪽 문제를 다른 쪽 문제와 맞바꾸는** 셈이 됩니다. 숫자
형식을 그대로 두어 한국어 사용자가 보던 모습을 유지했습니다.

```
앱 ko:  2026. 8. 25.     ← 이전과 동일
앱 en:  8/25/2026        ← 고쳐짐
```

## 검증

되돌려서 양쪽 방향으로 확인했습니다.

```
✘ 다시 브라우저에게 묻게          → en 에서 "2026. 8. 25." 이 나와 실패
✘ 긴 형식(month: long)으로 바꿈   → ko 가 "2026년 8월 25일" 로 바뀌어 실패
```

두 번째가 중요합니다. **고치는 김에 모양까지 바꾸지 않았다**는 걸 지키는 테스트입니다.
테스트 내내 브라우저는 한국어로 고정되어 있습니다 — 날짜가 브라우저를 따랐다면 두 확인
모두 한국어를 봤을 테니, 그게 이 테스트가 성립하는 조건입니다.

`가장 최근 120개` 상한은 그대로 둡니다. 페이지가 이미 더 있다고 말하고 있고, 그 상한은
`maxTurningPoints` 에 이유와 함께 적힌 의도된 선택입니다.
