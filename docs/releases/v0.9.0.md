# umm v0.9.0 — 임베딩을 측정하고, 어떤 백엔드에서도 맞게 만들기

v0.9.0에는 새 화면이 없습니다. 대신 **"의미"라고 부르던 것이 실제로 무엇을 재고 있었는지 측정하고, 제대로 된 임베딩 모델을 붙여도 기능이 무너지지 않도록** 판정 기준을 고쳤습니다.

Memory Graph·Dream 2.0·Ask My Memory 같은 다음 단계는 전부 "비슷한 생각을 찾는다"는 연산 위에 서 있습니다. 그 연산이 지금 무엇을 하고 있는지 모르는 채로 위에 무엇을 쌓아도, 쌓은 만큼만 틀립니다.

---

## 1. 기본 임베딩이 무엇을 재고 있었나

한국어·영어 22쌍을 네 종류로 라벨링해 측정했습니다. 패러프레이즈(같은 뜻, 다른 말), 관련(같은 주제, 다른 주장), 어휘 함정(단어만 겹치고 뜻은 무관), 무관.

| | 로컬 문자 n-gram | bge-m3 |
| :--- | ---: | ---: |
| 패러프레이즈 | 0.193 | 0.702 |
| 관련 | 0.155 | 0.566 |
| **어휘 함정** | **0.443** | 0.623 |
| 무관 | 0.177 | 0.361 |
| **판별력** (패러프레이즈 − 어휘함정) | **−0.250** | **+0.079** |
| **쌍별 정확도** (패러프레이즈 > 함정) | **4.2%** | **83.3%** |

기본 알고리즘은 패러프레이즈 8개 × 어휘함정 6개 = 24회 비교에서 **1번만** 옳은 순서를 매깁니다. `무관`(0.177)이 `관련`(0.155)보다 높게 나와 순서 자체가 무너져 있습니다.

`PostgreSQL 백업 주기` ↔ `PostgreSQL 로고 색상`은 하나의 주제로 묶이고, `외부 API 없이 사내망에서만` ↔ `폐쇄망 내부 GPU로 추론`은 연관 생각에조차 잡히지 않습니다. 192차원 FNV 문자 n-gram 해싱은 **어휘 지문**이지 의미 벡터가 아닙니다.

### 가중치 조정으로는 해결되지 않습니다

1-gram 제거, 단어 가중치 상향, 단어별 n-gram 정규화, 차원 확대(512/1024), sublinear 스케일링 등 11가지 변형을 같은 데이터셋으로 측정했습니다. **전부 음수였습니다.** 최선(−0.188)조차 개선의 대부분이 패러프레이즈 점수를 함께 무너뜨려(0.193 → 0.066) 얻은 것입니다.

`사내망`과 `폐쇄망` 사이에는 표면 기반 방법이 찾을 수 있는 공통 신호가 없습니다. 동의어는 학습된 분포 지식에서만 나옵니다.

## 2. 그래서 더 급한 문제: 좋은 모델을 붙이면 오히려 망가졌습니다

측정 표를 코드의 하드코딩된 임계값에 대입하면 결과가 분명합니다.

| 임계 | 용도 | bge-m3에서 |
| :--- | :--- | :--- |
| `>= 0.22` | 연관 생각 | 무관한 쌍(0.361)도 통과 → **모든 메모가 서로 연관** |
| `>= 0.34` | 군집 | 무관한 쌍도 통과 → **전부 한 덩어리** |
| `>= 0.28` | "의미상 유사" 라벨 | 모든 검색 결과에 붙음 |
| `< 0.18` | 키워드 미일치 결과 제외 | 한 번도 발동하지 않음 |
| `bridge` 정점 `0.35` | Dream 페어 선택 **가중치 55%** | 유사도 0.70 이상이면 **정확히 0** |

마지막 항목이 특히 나쁩니다. Dream이 페어를 고르는 주 신호가 의미적으로 가까운 쌍에서 통째로 사라져, 위치와 시간과 중심성만 남습니다.

즉 v0.8.1까지는 **관리자가 제대로 된 임베딩 모델을 설정하는 순간 연관 생각·군집·검색 라벨·Dream 선택이 조용히 전부 무너지는** 상태였습니다. 로드맵이 전제하는 바로 그 행동이 제품을 망가뜨렸습니다.

## 3. 고친 방식: 절대 컷오프 → 분포 상대 기준

"이 점수가 상수보다 높은가"를 묻던 것을 **"이 후보 집합에서 이 점수가 유난히 높은가"**로 바꿨습니다. 기준을 평균 위 표준편차 단위로 표현하면 어떤 백엔드가 만든 숫자든 같은 의미를 갖습니다.

`internal/intelligence/scale.go`:

```go
scale := intelligence.NewSimilarityScale(observedScores)
cutoff := scale.ThresholdOr(intelligence.BandRelated, legacyRelatedCutoff)
```

적용한 곳 다섯:

- **연관 생각** — 그 메모가 놓인 분포에서 판정
- **군집** — 공간 전체 페어 분포에서 하나의 컷오프 (씨앗별로 뽑으면 이웃 없는 메모가 자기 기준을 끌어내려 아무나 합류시킵니다)
- **캔버스 연관 수 배지** — 군집과 같은 기준
- **검색의 의미 라벨과 제외 컷오프** — 결과 집합이 다 모인 뒤 2단계로 판정
- **Dream bridge** — 고정 정점 0.35 대신 **관측된 중앙값과 최고값의 중간**을 정점으로

표본이 4개 미만이거나 분포에 퍼짐이 없으면 예전 상수로 물러섭니다. 메모가 두세 개뿐인 공간의 동작은 그대로입니다.

### 실제 백엔드로 확인

bge-m3를 붙인 6개 메모 공간(보안 주제 3 + 자전거 주제 3):

```
군집:        2 그룹, 크기 [2 2]      (이전: 전부 1 그룹)
연관 생각:   5개 중 1개              (이전: 5개 중 5개)
```

이 테스트는 게이트웨이가 설정된 경우에만 실행되며, **폴백으로 로컬 알고리즘이 쓰였으면 실패**합니다. 그렇지 않으면 엉뚱한 백엔드를 측정하면서 통과할 수 있기 때문입니다.

## 4. 측정 하네스

`internal/intelligence/quality_test.go`가 CI에서 매번 표를 출력하고, 판별력이 나빠지면 실패합니다.

후보 모델을 같은 데이터셋으로 비교할 수 있습니다:

```bash
UMM_EMBEDDING_TEST_URL=http://127.0.0.1:11434 \
UMM_EMBEDDING_TEST_MODEL=bge-m3 \
go test ./internal/intelligence -run Gateway -v
```

기본 알고리즘의 한계는 주석이 아니라 **깨질 수 있는 단언**으로 적어 두었습니다. `TestOfflineDefaultRanksVocabularyAboveMeaning`은 언젠가 기본 임베딩이 개선되면 실패하며, 하한을 올리라고 알려줍니다.

## 5. 남은 결정: 의미 임베딩을 기본으로 만들 것인가

측정이 끝난 지금, 선택지는 셋이고 각각 대가가 분명합니다.

| 방식 | 품질 | 대가 |
| :--- | :--- | :--- |
| 게이트웨이 안내 (현재) | 설정하면 최고 | 기본 설치는 여전히 어휘 지문 위에서 동작 |
| 정적 서브워드 벡터 테이블 번들 | 동의어 상당 개선, 문맥 없음 | 순수 Go 유지, 이미지 +30~50MB, 사전 구축 파이프라인과 라이선스 검토 |
| ONNX 런타임 번들 | 최고 | **`CGO_ENABLED=0` 정적 단일 바이너리 보장이 깨짐**, 아키텍처별 빌드, +120MB |

세 번째의 대가는 처음 권고할 때 과소평가했던 부분입니다. 현재 Dockerfile은 완전 정적 빌드이고, 그것이 "단일 이미지 오프라인 배포"의 근거입니다.

v0.9.0은 **셋 중 무엇을 고르든 그 위에서 제품이 올바르게 동작하도록** 바닥을 고쳐 둔 것입니다. 선택은 다음 버전의 몫입니다.

## 업그레이드

스키마 변경이 없습니다. 이미지만 교체하면 됩니다.

```bash
docker run -d --name umm --restart unless-stopped \
  -p 8080:8080 \
  -e POSTGRES_DSN='postgres://umm:password@postgres.internal:5432/umm?sslmode=require' \
  -e BOOTSTRAP_ADMIN='admin' \
  -e BOOTSTRAP_ADMIN_PASSWORD='your-strong-password' \
  -e ENCRYPTION_KEY='your-32-char-random-encryption-key' \
  umm:v0.9.0
```

알아 두면 좋은 것:

- 기본(로컬) 임베딩만 쓰는 배포에서는 연관 생각과 군집의 결과가 **미세하게 달라질 수 있습니다.** 판정이 고정 0.22/0.34가 아니라 각 공간의 분포에서 나오기 때문입니다. 메모가 4개 미만인 공간은 예전과 동일합니다.
- 이미 임베딩 모델을 설정해 둔 배포라면 **연관 생각과 군집이 이번에 크게 좁아집니다.** 이전에는 사실상 전부를 반환하고 있었기 때문이며, 좁아진 쪽이 맞는 동작입니다.
- Dream 페어 선택도 같은 이유로 달라집니다. 임베딩 모델을 쓰는 배포에서는 bridge 항이 되살아나므로 선택 품질이 올라갑니다.
