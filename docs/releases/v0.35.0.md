# v0.35.0 — 정렬이 배치를 부수지 않습니다

캔버스에는 정렬이 둘 있었습니다. **Thought Gravity**(연결된 생각을 둘레에 모으기)와
**생각 군집**(묶음별 재배치).

둘 다 문제가 하나씩 있었고, 공통으로 더 큰 문제가 있었습니다.

## 되돌릴 수 없었습니다

되돌리기는 `onDragStop`에서만 기록하고 있었습니다. 즉 **직접 끌어서 옮긴 것만** 기록됩니다.

정렬을 누르면 생각 수십 개가 한 번에 움직이는데, `Ctrl+Z`는 그중 아무것도 되돌리지 못합니다.
운이 나쁘면 **한참 전에 손으로 옮긴 메모 하나**가 대신 되돌아갑니다.

**위치가 곧 기억인 캔버스에서, 되돌릴 수 없는 정렬은 되돌릴 수 없는 결정입니다.**

이제 한 번의 정렬이 **한 번의 되돌리기**입니다. 브라우저에서 확인했습니다 — 겹친 생각 6개를 펼친
뒤 `Ctrl+Z` 한 번에 여섯 개가 모두 원래 좌표로 돌아갔습니다.

## 겹쳤습니다

Gravity는 한 바퀴를 개수로 나눠 **고정 반지름**에 놓았습니다. 연결이 여덟 개면 서로 포개집니다.
군집은 `270×205` **고정 격자**라, 크게 늘려 둔 메모가 옆 메모를 덮었습니다.

이제 둘 다 **메모의 실제 크기**를 보고, 자리가 모자라면 바깥 고리로 넘깁니다.

고리 계산에서 실수를 하나 했는데 테스트가 잡았습니다. 원 위에서 이웃 사이의 거리는 **호가 아니라
현**입니다. 호 길이로 계산하면 열두 개가 들어간다고 나오지만 실제로는 겹칩니다.

```
chord = 2r·sin(Δθ/2) ≥ step   ⇒   Δθ ≥ 2·asin(step / 2r)
```

## 새로 생긴 것: 겹침 정리

기존 둘은 배치를 **다시 만듭니다.** 새 도구는 배치를 **지킵니다.**

겹친 것만 **최소 거리로** 떼어 놓고, 자리가 넉넉한 생각은 **한 개도 옮기지 않습니다.**

```
전  100,100  112,109  124,118  136,127  148,136  160,145   멀리: 2000,1400
후  100,100  112,296  124,492  136,688  148,884  160,1080  멀리: 2000,1400
```

x 좌표가 그대로인 것이 요점입니다. 쌓인 것을 세로로만 풀었고, 멀리 있던 생각은 건드리지
않았습니다. 생각을 여러 개 고른 뒤 누르면 **고른 것들 안에서만** 정리합니다.

## 군집도 덜 부숩니다

전에는 공간의 **모든** 메모를 계산된 격자로 옮겼습니다. 이제 **묶음에 속한 것만** 옮기고, 어느
묶음에도 없는 생각은 그대로 둡니다 — 그 생각들이야말로 가장 의도적으로 놓인 것들입니다.

몇 개를 옮겼고 몇 개를 그대로 뒀는지 말해 줍니다.
