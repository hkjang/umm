# v0.49.1 — 읽기 전용 공간에서 할 수 없는 것은 내놓지 않습니다

지난 릴리스에서 **이름만 적어 두고 고치지 않은 두 가지**가 있었습니다. 그걸 마저 합니다.

## 메모 메뉴가 되지 않을 일을 계속 권하고 있었습니다

읽기 전용 공간에서도 메뉴는 소유자와 같았습니다. **하나하나 API 가 거절하는 것들입니다.**

```
소유자    색상 · 제목 붙이기 · 질문으로 표시 · Dream 분석에서 제외
          연결과 갈래 · 댓글과 멘션 · 이전 버전 복원 · 지우기

읽기 전용  연결과 갈래 · 댓글과 멘션          ← 실제로 되는 것만
```

**할 수 없는 일이 적힌 메뉴는 짧은 메뉴보다 나쁜 답입니다.**

남는 둘은 진짜로 동작합니다. 특히 댓글은 읽기 전용 멤버도 남길 수 있습니다 — **고칠 수
없다고 해서 이야기까지 못 할 이유는 없습니다.**

## 오프라인용 문구가 온라인에서 나왔습니다

```
전:  "이 공간의 편집 권한이 없어 오프라인 변경을 적용할 수 없습니다."
후:  "이 공간의 편집 권한이 없어 변경을 저장하지 못했습니다."
```

이 경로는 **방금 타이핑한 사람과 보관함에서 재시도된 변경을 똑같이** 처리합니다. 그러니
문구가 둘 중 하나를 단정하면 안 됩니다. 메모를 찾지 못한 경우도 같이 고쳤습니다.

## 검증

되돌려서 확인했습니다.

```
✘ 노드에 readOnly: false 를 넘김   → 읽기 전용에서 8개가 다 나와 "색상 is still offered" 로 실패
✘ 문구에 "오프라인" 복원           → "the read-only message assumes an offline change" 로 실패
✓ 소유자 메뉴 8개 그대로           → 함께 검사
```

### 되돌리기가 실제로 먹혔는지부터 봤습니다

첫 시도는 `!data.readOnly &&` 를 삼항으로 바꿨는데, 결과가 `{조건 ? true : (<JSX/>)}` 가
되어 **읽기 전용에서 여전히 숨겨졌습니다.** 테스트는 통과했고, 하마터면 "이 테스트는 못
잡는다"고 적을 뻔했습니다.

그래서 되돌린 상태에서 **메뉴를 실제로 찍어 봤습니다.**

```
읽기 전용 -> ["색상","제목 붙이기",...,"지우기"]   ← 되돌리기가 먹혔다는 증거
그 다음에야 테스트가 실패하는 것을 확인
```

이번 세션에서 되돌리기가 헛돈 게 **네 번째**입니다(컴파일 실패 두 번, 무의미한 치환 두 번).
**되돌린 코드가 정말 달라졌는지 먼저 보고, 그 다음에 테스트를 믿습니다.**

## 로컬 유닛 테스트는 CI 기준입니다

이 기기에서 vitest 워커가 시작되지 못하는 일이 반복됐습니다 — 매번 **다른 파일**이고
`Timeout waiting for worker to respond` 입니다. 메모리가 1.4GB 까지 떨어진 상태의 자원
문제이지 코드 문제가 아니며, 이번 변경은 유닛 테스트가 있는 모듈을 건드리지 않습니다.
