# v0.40.0 — 에이전트도 생각을 발표로 만들 수 있습니다

MCP 도구 세 개가 늘었습니다.

| 도구 | 필요한 권한 | |
| --- | --- | --- |
| `preview_presentation` | `notes:read` | 공간이 어떤 발표가 될지, 아무것도 만들지 않고 |
| `make_presentation` | **`notes:write`** | Ptium에 실제로 생성 |
| `list_presentations` | `notes:read` | 만든 발표와 낡은 슬라이드 수 |

이제 이 흐름이 umm 안에서 끝납니다.

```
umm.search_notes
      ↓
umm.get_connections
      ↓
umm.preview_presentation
      ↓
umm.make_presentation
```

## 읽을 수 있다고 만들 수 있는 건 아닙니다

읽기만 되는 키가 **주인의 생각을 다른 서비스로 보내서 무언가를 만들 수 있으면** 안 됩니다.
그래서 보는 것은 `notes:read`, 만드는 것은 `notes:write`입니다.

말로만 두지 않고 **실제 MCP로 키 두 개를 만들어** 확인했습니다.

```
preview_presentation  (읽기 전용)  → 슬라이드 2장
make_presentation     (읽기 전용)  → API key requires notes:write scope
make_presentation     (쓰기 가능)  → ptium is not configured
```

## 이게 요약기가 아니라는 걸 도구 설명이 말합니다

에이전트는 설명을 읽고 도구를 고릅니다. **이게 요약기가 아니라는 걸 알 방법이 없으면**
요약이 필요한 자리에 쓰게 되고, 그건 이 도구가 하지 않는 유일한 일입니다.

설명에서 "본인이 쓴 문장 그대로"라는 말이 사라지면 테스트가 실패합니다.

## 지난주 버그를 다시 내지 않았습니다

MCP 인자를 `fmt.Sprint(args["title"])`로 읽으면, 없는 키가 **문자열 `"<nil>"`** 이 됩니다.
v0.37.1에서 게이트웨이 주소가 없는데 "URL이 올바르지 않습니다"로 거부되던 그 함정입니다.

없는 것을 없는 것으로 읽는 헬퍼를 통과시켰습니다.
