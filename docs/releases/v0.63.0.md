# v0.63.0 — 긴 발표를 부로 나눕니다

286장짜리 덱은 모양이 없는 한 줄입니다. 부(部)가 모양을 줍니다 — 어디서 새 부분이
시작되는지, 그 부분이 무엇에 관한 것인지.

```
                        전                    후
                    ━━━━━━━━━━━━        ━━━━━━━━━━━━━━━━━━
                    슬라이드 1           ▸ 문제
                    슬라이드 2             슬라이드 1
                    ...                    슬라이드 2
                    슬라이드 286           ...
                                        ▸ 대안
                                          슬라이드 9
                                          ...
```

## 슬라이드를 더하고, 옮기지 않습니다

이게 설계의 전부입니다.

덱의 순서는 umm의 추측이 아닙니다. `follows` 사슬이면 **사람이 순서를 직접 말한 것**이고,
아니면 **캔버스에 늘어놓은 배치**이며 그것도 사람이 한 일입니다. 모델이 그걸 재배치하는 건
**사람이 한 말을 뒤집는 것**입니다.

어디서 부가 시작되는지 묻는 건 그 순서를 **읽는 것**이고, 재배치는 그 순서와 **다투는
것**입니다.

그래서 부 제목은 사람의 문장을 하나도 담지 않는 **새 슬라이드**이고, 원래 슬라이드는 자리,
내용, 출처 생각이 **전부 그대로**입니다.

### `(나)` 중 순서 재배치는 뺐습니다

제안드릴 때 "순서/섹션 제안"이라고 묶어서 말씀드렸는데, **순서 쪽은 빼는 게 맞습니다.**
위 이유입니다. 조용히 빼지 않고 적어 둡니다.

## 답이 어긋나면 통째로 버립니다

제목과 다른 규칙입니다. **부는 서로 독립적이지 않습니다.**

제목은 하나가 못 쓰게 나와도 버리면 그만이고 옆 슬라이드는 그대로입니다. 경계는 그렇지
않습니다 — 9번에서 시작하는 부를 버리면 **4번에서 시작한 부의 범위가 조용히 9번까지
늘어납니다.** 그렇게 만들어진 구성은 모델이 제안한 적도, 사람이 검토한 적도 없는 것입니다.

시험을 쓰다가 이걸 발견했습니다. 처음엔 못 쓰는 항목만 걸러 냈는데, 시험이 **"순서가 뒤섞인
답을 받아들였다"** 고 잡았습니다.

```
✗ 순서 뒤섞임          ✗ 범위 밖        ✗ 음수
✗ 같은 슬라이드 두 번   ✗ 1장짜리 부     ✗ 0번에서 안 시작
✗ 제목이 문장          ✗ 부가 하나뿐    ✗ 40개 제안
```

전부 → **안 나눕니다.**

## 위치가 밀려도 출처는 그대로

부 제목이 끼면 뒤 슬라이드 위치가 전부 밀립니다. 출처 지도는 그 **뒤에** 같은 목록으로
만들어지므로 "이 슬라이드가 어느 생각을 인용했는가"는 그대로 답합니다. 시험이 위치마다
직접 확인합니다.

변형으로 **살아 있는 목록에 끼워 넣게** 바꿔 봤더니, 첫 번째 삽입 때문에 두 번째 부가
**엉뚱한 슬라이드 앞에 붙는 것**이 잡혔습니다. 원본을 순회하며 새 목록을 만드는 이유입니다.

## 확인한 것

```
✓ 원래 슬라이드가 전부, 순서대로, 내용과 출처 생각까지 그대로 남음
✓ 부 제목은 어떤 생각도 인용하지 않음
✓ 경계가 지목한 그 슬라이드 앞에 정확히 붙음
✓ 삽입 후에도 위치→생각 지도가 맞음
✓ 12장 미만은 모델을 호출조차 안 함
✓ 호출 실패 / sectioner 없음 → 덱 그대로
✓ 어긋난 제안은 통째로 거부, 제대로 된 제안은 수용
```

| 바꾼 것 | 잡은 것 |
| :--- | :--- |
| 살아 있는 목록에 삽입 | 두 번째 부가 엉뚱한 슬라이드 앞에 |
| 부 제목이 다음 슬라이드 생각을 인용 | 제목이 인용을 주장 |
