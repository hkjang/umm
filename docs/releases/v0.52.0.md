# v0.52.0 — 갈래와 그 이유까지 되살립니다

v0.51.0 에서 생각과 자리와 연결이 돌아왔습니다. 남은 것이 하나 있었습니다. **생각의 갈래**
입니다.

```
내보낸 것                                  v0.51.0 에서 돌아온 것
────────────────────────────────────      ──────────────────────
생각, 자리, 연결                            ✓
"되돌리기 실험" 갈래                         ✗
그 갈래가 abandoned 이라는 사실               ✗
"플러그인 호환 부담이 더 컸습니다"              ✗
```

갈래 이름표가 사라지면 **접어 둔 생각과 지금 가는 생각이 똑같아 보입니다.** 그리고 접어 둔
이유는 사람들이 가장 먼저 잃는 절반입니다. 기록을 옮기는 그 순간에 잃는 건 최악입니다.

## 이제

내보내기는 이미 다 적고 있었습니다.

```
- line: `되돌리기 실험` (abandoned)          ← 생각마다, 어느 갈래였는지

## Lines of thinking
- **되돌리기 실험** — abandoned: 플러그인 호환 부담이 더 컸습니다
```

가져오기가 갈래를 다시 만들고, 그 갈래에 속했던 생각을 도로 넣고, **끝난 상태와 이유까지**
그대로 닫습니다. 아직 가는 중(`open`)인 갈래는 열린 채로 둡니다 — 없는 이유를 지어내지
않습니다.

> 2개의 생각과 1개의 연결, 1개의 갈래를 되살렸습니다.

## 검증

화면을 통한 왕복 e2e 를 넓혔습니다. 원본 공간에 갈래를 만들고, 생각 하나를 넣고, 이유와 함께
접어 둔 다음, **다른 공간으로** 가져와서 확인합니다.

```
✘ 갈래를 다시 만들지 않음      →  갈래 1개가 0개로 나와 실패
✘ 상태와 이유를 닫지 않음      →  "abandoned" 자리에 "open" 이 나와 실패
✘ 생각을 갈래에 넣지 않음      →  소속이 undefined 로 나와 실패
```

갈래에 속하지 않았던 생각이 **끌려 들어가지 않는지**도 함께 봅니다. 되살리기는 있던 것을
돌려놓는 일이지 없던 것을 만드는 일이 아닙니다.

## 되돌리기 하나가 헛돌았던 일

`for (const line of [])` 로 되돌렸더니 타입 오류가 나서 빌드가 멈췄고, 번들은 그대로였습니다.
번들 파일 이름이 바뀌었는지 보는 장치가 **"결과 의미 없음"** 이라고 먼저 알려 줬습니다.
`lines.slice(0, 0)` 으로 바꾸니 컴파일되고, 그제서야 시험이 실패했습니다.
