# v0.33.2 — 긴 페이지가 스크롤되지 않았습니다

`오늘의 리뷰`에서 스크롤이 안 된다는 제보를 받고, 짧은 창(1100×520)으로 재현했습니다.

```
오늘의 리뷰   본문 2272px   창 520px   스크롤 불가
```

**1,750픽셀이 닿을 수 없었습니다.**

## 원인

`html`·`body`·`#root`에 `overflow: hidden`이 걸려 있습니다. 캔버스가 무한히 밀고 당기는 고정
화면이어야 해서 그렇게 둔 것인데, **나머지 페이지도 전부 같이 잘렸습니다.**

본문(`main`)은 잘리지 않고 2272px까지 자라 있었습니다. 다만 그걸 담은 뿌리가 화면 밖을 감췄고,
스크롤할 방법이 없었습니다.

## 고친 방법

스크롤을 **문서가 아니라 셸의 본문 영역**이 갖게 했습니다.

- `.app-main` — 높이는 화면 전체, `overflow-y: auto`
- 캔버스는 이제 그 본문 영역의 **100%**를 채웁니다(전에는 화면 높이를 직접 계산했습니다)

이렇게 하면 **캔버스는 여전히 스크롤되지 않고**, 나머지 페이지는 전부 스크롤됩니다.

그리고 **앞으로 추가되는 페이지도 자동으로** 적용됩니다. 모든 라우팅된 페이지가 이 요소 안에서
그려지기 때문에, 페이지마다 따로 해 줄 것이 없습니다.

### 인라인 높이를 걷어냈습니다

`<AppShell.Main h="100%">`의 인라인 높이가 스타일시트를 이깁니다. 그것 때문에 본문이 **내용만큼
자라 버리고** 높이가 잡히지 않았습니다. 첫 시도에서 `overflow-y: auto`만 넣었을 때 아무 변화가
없던 이유가 이것이었습니다.

## 휴대폰 하단 탭도 함께

모바일 탭 바는 화면 아래에 고정입니다. `.settings-page`처럼 아래 여백을 직접 챙긴 페이지도
있었지만 `오늘의 리뷰`·`결정 기록`은 아니어서, 스크롤이 되더라도 **마지막 46픽셀이 탭 바 밑**에
깔렸습니다.

여백을 스크롤 컨테이너에 두어 **모든 페이지가 한 번에** 탭 바를 피하게 했습니다.

```
390×700 · 맨 아래까지 스크롤
마지막 카드 하단 542px · 탭 바 상단 638px  → 가려지지 않음
```
