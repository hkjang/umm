# v0.25.0 — 한 갈래만 보기

v0.24.0은 접어 둔 갈래를 **AI가 답할 때만** 표시했습니다. 정작 사람이 자기 생각을 읽는 곳 —
캔버스 — 에서는 접어 둔 생각과 현재 생각이 여전히 똑같이 생겼습니다.

## 캔버스에도 표시합니다

접어 둔 갈래에 속한 생각에는 **`접어 둠`** 표가 붙습니다. 마우스를 올리면 어느 갈래인지 나옵니다.

숨기지 않습니다. 여전히 본인이 쓴 생각이고 다시 읽고 싶을 수 있습니다. 다만 **현재 방침으로
읽히면 안 될 뿐**입니다.

## 한 갈래만 보기

도구 모음의 초점 버튼에서 갈래를 고르면 그 갈래만 선명해지고 나머지는 흐려집니다. 생각을 하나
고른 상태라면 **연결 1~3걸음**으로도 좁힐 수 있습니다.

```
젠킨스로 이전   2개에 집중 · 1개는 흐리게 두었습니다   [전체 보기]
```

**흐리게 두되 숨기지 않습니다.** 사라진 생각은 지워진 생각으로 읽힙니다. 그리고 **몇 개를
흐리게 두었는지 항상 말합니다** — 그러지 않으면 캔버스가 실제보다 단출해 보입니다.

## 왜 의미가 아니라 구조로 좁히나

"비슷한 것끼리" 보여 주는 렌즈는 뒤에 있는 임베딩만큼만 좋습니다. umm의 기본 임베딩은 글자
n-gram이라 **단어가 겹치는 생각을 묶고는 주제라고 부릅니다.**

갈래와 연결은 사람이 직접 그은 것입니다. 그래서 이 렌즈는 **그 사람이 만든 구조만큼 정확하고,
백엔드가 약하다고 조용히 나빠지지 않습니다.**

## 확인했다고 생각했지만 확인하지 못한 것

흐리게 만드는 코드를 넣고 브라우저에서 확인했습니다. DOM을 읽었더니 `opacity: 0.22`.
통과라고 판단했습니다.

**틀렸습니다.**

`.postit`에는 `animation: note-land ... both`가 걸려 있습니다. `fill-mode: both`는 애니메이션의
마지막 키프레임(`opacity: 1`)을 **영구히 유지**하고, CSS 캐스케이드에서 **애니메이션은 인라인
스타일을 이깁니다.**

즉 흐려짐은 **한 번도 화면에 그려진 적이 없습니다.** 제가 읽은 것은 인라인 속성이었고, 브라우저가
실제로 계산한 값이 아니었습니다. **DOM에 값이 있는 것과 화면에 보이는 것은 다릅니다.**

e2e 테스트가 `toHaveCSS`로 **계산된 스타일**을 읽으면서 잡았습니다. 흐림 처리를 애니메이션이 없는
노드 바깥 요소로 옮겨 고쳤고, 테스트는 계산된 스타일만 봅니다 — 속성을 읽는 검사는 그리지도 않는
효과를 통과시킵니다. 실제로 그랬습니다.

## 테스트가 자기 공간을 갖습니다

이 테스트를 단독 실행하면 통과하고 전체 실행하면 실패했습니다. 앞선 줌 테스트가 같은 공간에
28개를 남기고, 25개를 넘으면 캔버스가 개별 메모 대신 묶음을 보여 주기 때문입니다. 테스트가 자기
공간을 만들도록 고쳤습니다 — 순서에 기대는 테스트는 언젠가 순서가 바뀌면 거짓말을 합니다.
