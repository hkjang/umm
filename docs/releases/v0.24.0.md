# v0.24.0 — 생각의 갈래

시도해 봤다가 접어 둔 생각은, 검색해서 다시 만났을 때 **현재 방침과 똑같이 생겼습니다.**

문제는 어수선함이 아닙니다. **이미 버린 선택지를 다시 집어드는 것**입니다.

## 무엇이 달라지나

캔버스에서 생각을 고르면 연결 패널에 **생각의 갈래**가 생겼습니다. 시도해 본 방향에 이름을 붙이고,
관련된 생각을 그 갈래에 넣고, 나중에 **채택** 또는 **접어 둠**으로 정리합니다.

정리할 때는 **이유가 필수**입니다. 이유 없이 접어 둔 갈래는 이 기능이 막으려는 망각이 한 단계 뒤로
미뤄진 것일 뿐입니다 — 버렸다는 건 알지만 왜 버렸는지는 모르는 상태.

```
POST /api/v1/branches/{id}/resolve  {"status":"abandoned","resolution":"  "}
→ 400  이유를 적어 주세요
     왜 채택했는지 또는 왜 접어 두는지를 남기지 않으면, 나중에 결정만 남고 이유는 사라집니다.
```

## 접어 둔 갈래는 어디에 나타나도 그렇게 말합니다

검색, `/ai/ask`의 근거, 조력자의 조회 — 세 경로 모두에서 접어 둔 갈래의 생각에는 표시가 붙습니다.
**연결을 따라 도달한 생각**도 포함합니다. 오히려 그쪽이 더 중요합니다. 아무도 그걸 보겠다고 고르지
않았으니까요.

같은 질문, 같은 데이터, 실제 모델(`qwen3.6`)로 측정했습니다.

**갈래를 만들기 전:**
> 배포를 젠킨스로 옮기면 파이프라인을 직접 통제할 수 있게 됩니다[1].

현재 방침으로 읽힙니다. 실제로는 검토한 뒤 버린 안이었습니다.

**갈래를 접어 둔 뒤:**
> 사용자는 젠킨스로 배포를 옮기는 것을 검토했지만, **플러그인 호환성 부담이 직접 통제 방식보다
> 크다고 판단하여 채택하지 않기로 결정**했습니다[1].

결정과 **그 이유**가 같이 나옵니다.

## 만들면서 낸 결함: 표시 문구가 반대로 읽혔습니다

처음 문구는 `[보류된 갈래]`였습니다. 실제 모델에 물어보니 이렇게 답했습니다.

> 젠킨스 이전 건들은 **아직 최종 결정되지 않고 보류되어 있습니다.**

정반대입니다. 사용자는 **결정했습니다** — 하지 않기로. 한국어 "보류"는 *아직 안 정함*으로 읽히고,
모델은 정확히 그렇게 읽었습니다.

표시를 `[접어 둔 갈래(검토 후 채택하지 않기로 함)]`로 바꾸고 **이유를 함께 실었습니다.** 이유가 없으면
모델은 "왜?"라는 질문을 스스로 메꾸거나, 결정이 안 났다고 얼버무립니다.

테스트는 문구를 바꾼 게 아니라 **"보류"라는 단어를 금지**합니다. 다시 손볼 때 가장 손이 가는 단어가
그것이기 때문입니다.

이 결함은 단위 테스트로는 절대 나오지 않습니다. 코드는 정확히 지시한 대로 동작했습니다. **실제
모델에 물어봐야만** 보였습니다.

## 추론하지 않습니다

한 달 동안 아무것도 안 적은 갈래를 umm이 알아서 접지 않습니다. **침묵은 결정이 아닙니다.** 그렇게
처리하면 잠시 멈춰 둔 일이 조용히 묻힙니다.

`상충`과 `질문`이 그랬듯, 갈래도 **사람이 표시하는 것**입니다.

## 지워도 생각은 남습니다

갈래를 지우면 그 선을 더 이상 추적하지 않는다는 뜻이지, 그 안에서 한 생각이 없던 일이 되는 게
아닙니다. 스키마도 `ON DELETE SET NULL`로 그렇게 되어 있고, 테스트가 지킵니다.

## 왜 `Note`에 컬럼을 붙이지 않았나

생각을 읽는 경로가 17군데입니다. 거기에 필드를 하나 더하면 **한 군데를 빠뜨리는 순간** v0.11.0에서
실제로 낸 결함이 재현됩니다 — `Backlinks`가 `origin`과 `confidence` 없이 엣지를 돌려주던 그것,
한 릴리스 내내 아무도 몰랐습니다.

그래서 갈래 정보는 필요한 곳에 **따로 붙입니다.** 조회 결과에 한 번, 캔버스 목록에 한 번.

## API

```
GET    /api/v1/spaces/{id}/branches      갈래 목록 + 생각→갈래 매핑
POST   /api/v1/spaces/{id}/branches      갈래 만들기
POST   /api/v1/branches/{id}/resolve     채택 / 접어 둠 (이유 필수)
POST   /api/v1/branches/{id}/reopen      다시 열기 (이유는 지웁니다)
DELETE /api/v1/branches/{id}             갈래만 삭제
PUT    /api/v1/notes/{id}/branch         생각을 갈래에 넣기 / 빼기
```

다시 열면 이유를 지웁니다. 더 이상 유효하지 않은 결정을 설명하던 문장이고, 남겨 두면 현재 상태처럼
읽힙니다.

## 확인한 것

- 전체 Go 테스트 통과(`-p 1`), 웹 46개 통과, 타입·린트·i18n 통과
- 두 조회 경로(직접 일치, 연결로 도달) 모두에서 표시가 붙는지 통합 테스트로 고정
- 편집 권한 없는 구성원은 갈래를 만들거나 정리할 수 없고, 읽기는 됩니다
- 갈래는 공간을 넘지 않습니다 — 뿌리 생각도, 소속 생각도
- 실제 모델로 3단계 비교(갈래 없음 → 잘못된 문구 → 고친 문구)
