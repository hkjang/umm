# v0.28.0 — 아무것도 안 하는 설정을 없애고, 중요한 설정은 실행 가능하게

설정 61개를 하나씩 대조해 **Go 코드가 한 번도 읽지 않는 것**을 찾았습니다. 하나 있었습니다.

## `embedding_dimensions` — 007부터 있었고, 아무도 읽지 않았습니다

마이그레이션 007이 `ai_gateway.embedding_dimensions`를 심어 두었고 그 뒤로 **어떤 코드도 이 값을
읽지 않습니다.** 설정 API는 계속 돌려주고 있었습니다.

실행 중인 인스턴스에서 확인했습니다. 모델이 1024차원 벡터를 주는 상태에서 이 값을 **256으로
바꿔도** 벡터는 1024 그대로였고 측정값도 그대로였습니다(쌍별 83.3%).

**설정 API에 보이면서 아무 일도 하지 않는 손잡이는, 없는 것보다 나쁩니다.** 배포를 손보던 사람이
이걸 지렛대로 읽고, 돌려 보고, 자기가 바꾸려던 것이 원래 중요하지 않다고 결론 내립니다.

구현하는 쪽도 검토했고 더 나빴습니다. OpenAI API는 `dimensions` 파라미터를 받고 **ollama는
무시합니다.** 그러면 백엔드에 따라 되기도 하고 조용히 안 되기도 하는, 같은 문제의 다른 얼굴이
됩니다.

나머지 60개는 전부 실제로 읽힙니다.

## 무엇이 잘못됐는지만 말하고 어떻게 고치는지는 안 말하고 있었습니다

기본 임베딩이 의미를 못 잰다는 경고는 이렇게 끝났습니다:

> …임베딩 모델을 설정하면 해결됩니다.

맞는 말이지만, **이 경고를 볼 사람은 대개 compose 프로파일이 있다는 걸 모르는 자체 호스팅 사용자**
입니다. 그 사람을 있던 자리에 그대로 두는 문장입니다.

이제 명령이 함께 나옵니다.

```
docker compose --profile embeddings up -d
docker compose exec embeddings ollama pull bge-m3
```

그리고 게이트웨이를 `http://embeddings:11434`, 모델을 `bge-m3`으로 저장하라고 말합니다. 한 번
받아 두면 네트워크 없이 동작한다는 것도요.

이 차이는 작지 않습니다. 기본 임베딩에서는 **연관 생각·군집·중복·연결 추천·접어 둔 결정 되짚기가
전부 꺼집니다.** 실측으로 쌍별 정확도 4.2% 대 83.3%입니다.
