# v0.57.0 — 어느 웹훅이 실패하고 있는지 보입니다

관리 기능 고도화, 세 번째입니다.

운영 현황에는 숫자가 하나 있었습니다. **최근 웹훅 실패: 12.**

어느 웹훅인지, 누구 것인지, 수신 쪽이 뭐라고 답했는지는 **전부 데이터베이스에 있었습니다.**
아무것도 보여 주지 않았을 뿐입니다. 그 숫자는 뭔가 잘못됐다는 사실만 알려 주고 어디를
봐야 할지는 알려 주지 않았습니다.

## 이제 보입니다

`관리 → 웹훅 상태`

```
웹훅              주인            보내는 곳                연속 실패  24시간  마지막 전송
배포 알림         jaeho          https://hooks.slack.com/…    7        12    3일 전
  dial tcp: connection refused
주간 요약         hyunji [비활성] https://example.org/…        0         0    2시간 전
```

나쁜 것부터 옵니다. 연속 실패 횟수, 최근 24시간 실패, 마지막 전송 시각, **수신 쪽이 마지막으로
돌려준 오류**, 소유자와 그 계정의 활성 여부, 아직 큐에 남아 있는 전달 수가 한 줄에 있습니다.

**실패한 것만** 을 켜면 실패가 기록된 것만 남습니다.

## 주소는 host 까지만 보여 줍니다

Slack 과 Discord 의 incoming hook 은 **주소의 경로 자체가 자격 증명입니다.**

```
https://hooks.slack.com/services/T00000/B00000/XXXXXXXXXXXXXXXX
                                └─────── 이걸 아는 사람은 누구든 보낼 수 있습니다
```

관리자는 전달이 **어디로 가는지** 알아야 하고, **그 주소로 직접 보낼 수 있을** 필요는
없습니다. 그래서 scheme 과 host 까지만 적고 경로는 `…` 로 끝냅니다. 통합 시험이 응답
어디에도 경로가 나타나지 않는 것을 확인합니다.

## 멈추기

`active` 만 내립니다. 주소, 서명 키, 이벤트 목록은 **그대로 남습니다.** 소유자가 개인
설정에서 다시 켤 수 있습니다. 지우는 것이 아니라 멈추는 것이고, 남의 설정을 관리자가
대신 없애지 않습니다.

이 조치는 `webhook.pause` 로 감사 로그에 남습니다. 이미 멈춘 웹훅을 다시 멈춰도 오류가
아닙니다 — 두 관리자가 같은 장애를 동시에 보는 일은 흔합니다.

## 확인한 것

```
✓ 서명 키가 응답 어디에도 나타나지 않음
✓ 주소는 host 까지만
✓ 실패한 웹훅이 맨 위에, 이유와 주인과 함께
✓ 실패한 것만 → 멀쩡한 것은 빠짐
✓ 멈춘 뒤에도 url 과 secret_ciphertext 가 그대로
✓ 두 번 멈춰도 200, 없는 id 는 404
✓ 화면에서 멈추면 소유자의 개인 설정에서도 꺼져 있음
```

시험이 실제로 실패하는지도 확인했습니다. `destination()` 이 전체 주소를 돌려주게
바꾸자 **경로가 새어 나오는 것을 잡았고**, 멈추기가 아무것도 하지 않게 바꾸자 **`멈춤`
표시가 없는 것을 잡았습니다.** 두 번 다 이진 파일을 다시 빌드해 바뀐 것이 실제로 돌아가는지
확인한 뒤였습니다.

## 시험 하나가 자기 자신의 흔적에 걸렸습니다

두 번째 변형 시험이 엉뚱한 줄에서 실패했습니다. 앞선 실행들이 웹훅을 데이터베이스에 남겨
두어서, **주소를 화면 전체에서 찾던 단언이 남의 웹훅에 답을 얻고 있었습니다.** 이 표는
설치된 모든 웹훅을 담기 때문에 화면 전체에 대고 물으면 안 됩니다. 이제 이 웹훅의 줄 안에서만
읽습니다.
