# v0.50.1 — 템플릿 조회가 안 돼도 Ptium 연동은 됩니다

보고해 주신 두 가지입니다.

## 1. 템플릿 조회가 연동 전체를 좌우하고 있었습니다

연결 테스트가 하는 일은 **템플릿 목록을 불러오는 것 하나**였습니다. 그래서 템플릿 쪽에서
무슨 일이 생기든 결과는 `Ptium 연결 실패` 였습니다.

말씀하신 대로 템플릿은 **있으면 좋은 것**이지 필수가 아닙니다. 템플릿 없이도 덱은
만들어집니다. 이제 Ptium 이 **답을 했는지**를 보고 판단합니다.

```
템플릿 정상        연결됨 · 템플릿 1개
템플릿 404         연결됨 · "템플릿 목록은 가져오지 못했습니다"   ← 이전엔 연결 실패
응답 모양이 다름    연결됨 · 같은 안내                          ← 이전엔 연결 실패
템플릿 500         연결됨 · 같은 안내                          ← 이전엔 연결 실패
키를 거부함(401)    "Ptium이 API 키를 거부했습니다"              ← 연결 실패와 구분됨
닿지 않음          "Ptium 연결 실패"                           ← 진짜 실패
```

키를 거부당한 것은 **연결됨으로 뭉개지 않습니다.** Ptium 이 거절한 키는 작동하는 연동이
아닙니다. 반대로 404·500·모양 불일치는 주소와 키가 **맞다는 증거**이므로, 그걸 연결 실패라고
말하면 멀쩡한 곳을 뒤지게 만듭니다.

## 2. "테스트는 됐는데 리프레시하면 안 되는" 이유

재현했습니다. 저장하지 않은 키로도 테스트가 **성공합니다.**

```
1. 키를 입력하고 연결 테스트   → 성공  (입력한 키를 씀)
2. 리프레시 후 연결 테스트     → 실패  (저장된 옛 키를 씀)
3. 저장한 뒤 테스트            → 성공
```

화면은 아무것도 달라지지 않았는데 결과만 바뀝니다. 이제 1번에서 이렇게 말합니다.

> 다만 이 키는 아직 저장되지 않았습니다 — 저장해야 실제 연동에 쓰입니다.

그리고 2번은 이제 `Ptium이 API 키를 거부했습니다` 라고 나오므로, 어디를 봐야 하는지 바로
알 수 있습니다.

## 검증

되돌려서 확인했습니다.

```
✘ 템플릿 실패를 다시 연결 실패로  → 404·모양 불일치가 400 으로 나와 실패
✘ 거부된 키를 연결됨으로 뭉갬     → "키 문제로 보고되지 않음" 으로 실패
✘ 저장 안 됨 경고 제거            → "저장되지 않은 키가 보고되지 않음" 으로 실패
```

테스트는 보고해 주신 순서를 **그대로 재연**합니다 — 엉뚱한 키가 저장된 상태에서 올바른 키를
입력해 테스트하고, 리프레시하고, 저장하고, 다시 테스트합니다.

## 덧: 오래 열려 있던 arrange 플레이크의 정체

v0.46.2 부터 열어 둔 그 플레이크가 이번에 두 번 나왔고, 이번에는 **재실행 전에 증거를 먼저
복사**했습니다.

```
겹침-1 이 112,109 에서 안 움직였다고 실패
```

원인은 테스트가 **클라이언트 신호를 보고 서버 상태를 읽는** 것이었습니다. `겹침 정리` 는
새 좌표를 계산하자마자 안내를 띄우고, 저장은 메모마다 따로 날아갑니다. 안내 직후 서버를
읽으면 아직 옛 좌표가 나옵니다 — 화면에서는 이미 움직였는데요.

이제 서버가 반영할 때까지 기다립니다. **다만 정직하게 적어 둡니다: 이 경합을 마음대로
재현하지는 못했습니다.** 코드가 그렇게 동작한다는 것(안내가 저장보다 먼저)이 근거이지,
실패를 불러내서 고친 것이 아닙니다.

같은 조사에서 `ORDER BY created_at` 에 타이브레이커가 없는 것도 발견했지만, **그것이 이
플레이크의 원인이라는 증거는 없었고** 사용자 보고와도 무관하므로 이번 릴리스에 끼워 넣지
않았습니다.
