# v0.67.0 — 내 생각이 어디로 갔는지

umm은 메모별 AI 제외, 공간별 제외, 게이트웨이 본문 미전송, 호출 직전 권한 재확인까지
만들었습니다. 전부 **약속**입니다. 그런데 그 약속을 **본인이 확인할 화면이 없었습니다.**

```
        전                              후
    ━━━━━━━━━━━━━━━━━            ━━━━━━━━━━━━━━━━━━━━━━━━━━━
    관리자만 볼 수 있음            /settings 에서 본인이
    "gpt-4o  success"             "AI Assist · 9월 3일 10:14"
    (얼마 들었나)                  (무엇을 위해 나갔나)
```

## 기록에 "무엇을 위해"가 없었습니다

`ai_calls`는 운영자를 위해 쓰였습니다 — 모델, 상태, 토큰, 비용, 지연. 그건 "얼마가
드는가"에 답하고 그 이상은 못 합니다. 프롬프트 안에 자기 글이 들어간 사람의 질문은
다릅니다. **언제, 무엇을 위해 밖으로 나갔는가.**

`gpt-4o success` 열두 줄로는 Dream인지, AI Assist인지, 덱 제목을 지은 것인지 구분되지
않습니다.

그래서 **호출할 때 기록합니다.** 나중에 모델 이름과 시각으로 되짚는 건, 이 화면이 없애려던
바로 그 종류의 답이기 때문입니다.

## 타입을 줬습니다

`recordAICall` 은 이미 인자가 열 개였고, `purpose` 는 바로 옆 `model` 과 같은 문자열입니다.
자리가 바뀌어도 컴파일러가 안 잡습니다. 그래서 `store.Purpose` 라는 **자체 타입**입니다 —
바꿔 넣으면 컴파일이 안 됩니다.

어휘가 `store` 에 있는 이유도 있습니다. CHECK 제약이 붙은 테이블을 그 패키지가 소유하고,
**호출하는 쪽(`dream`)과 덱을 만드는 쪽(`presentation`)이 서로를 몰라도** 용도를 부를 수
있어야 하기 때문입니다.

### 공유 문에는 호출자가 이름을 붙입니다

`Complete` 는 v0.59.1에서 redaction 을 한곳에 모으려고 만든 공유 진입점이고, 지금 호출자가
**둘**입니다(덱 묶음 제목, 덱 부 나누기). 거기서 용도를 하나로 붙이면 오늘은 맞고 내일은
틀립니다. 그래서 **호출자가 넘깁니다** — `origin` 을 request body에서 받지 않는 것과 같은
이유입니다.

## 이 화면이 거짓말할 수 있는 두 가지

**하나. 비어 있는 목록이 "아무 일도 없었다"로 읽힙니다.**
기록은 보존 기간이 지나면 삭제됩니다. 그래서 화면은 **보존 기간을 항상 함께** 말합니다 —
"최근 30일 동안 기록된 호출이 없습니다. 기록은 90일 뒤 삭제되므로, 그보다 오래된 일은
여기에 남지 않습니다."

**둘. 모델 호출 목록이 "전부"로 읽힙니다.**
검색·연결용 임베딩도 게이트웨이로 나갑니다. 그런데 그건 **배치**로 가고, 공유 공간에서는
**여러 사람의 메모가 한 배치에 섞입니다.** 한 사람에게 귀속시키면 추측이 됩니다.

그래서 세지 않고, 대신 **지금 이 설치가 본문을 밖으로 보내는지 아닌지**를 목록 위에
적습니다. 그건 추측이 아니라 **사실**입니다. 설정값이 아니라 런타임이 쓰는 같은
resolver에서 읽으므로, "설정된 것"이 아니라 "실제로 일어나는 것"입니다.

## 실패한 호출도 목록에 있습니다

실패해도 **프롬프트는 이미 나갔습니다.** 빼면 글자는 게이트웨이로 갔는데 기록은 안 갔다고
말하는 셈입니다.

## 세션으로만 읽습니다

남의 글이 어디로 갔는지는 스크립트에 발급한 키가 읽을 것이 아닙니다. 라우트를 세션 전용
그룹에 걸었고, e2e가 **키로 403을 받는 것과 같은 키가 다른 곳에서는 200을 받는 것**을 함께
확인합니다 — 그러지 않으면 "키가 그냥 잘못됐다"와 구분이 안 됩니다.

## 확인한 것

```
✓ 남의 호출은 목록에도 집계에도 없음 (쿼리에서 걸러냄, 사후 필터 아님)
✓ 실패한 호출도 나옴
✓ 집계는 창(window) 전체, 목록은 그 한 페이지 — 페이지에서 합계를 읽지 않음
✓ 창 밖 호출은 빠지고, 창을 넓히면 나타남
✓ 최신순
✓ 기록되지 않은 용도는 빈 채로 화면까지 — 없는 이름을 붙이지 않음
✓ Go 어휘 7개가 전부 SQL CHECK 를 통과하고, 어휘 밖은 거부됨
✓ 실제 호출 경로(Assist · Ask · 덱 제목 · 덱 부)를 몰아서 돌린 뒤 기록을 되읽음
✓ 용도 없이 기록된 호출이 하나도 없음
```

| 바꾼 것 | 잡은 것 |
| :--- | :--- |
| 사용자 범위 제거 | 남의 기록이 보임 |
| 집계 범위 제거 | 남의 호출이 집계됨 |
| 기간 조건 제거 | 30일에 1년치가 나옴 |
| "더 있음" 표시 제거 | 잘린 걸 화면이 모름 |
| 합계를 페이지에서 계산 | 바쁜 달이 축소됨 |
| 용도를 빈 값으로 저장 | 실제 경로에서 용도가 안 남음 |
| 보존 기간 문구 제거 | 빈 목록이 "아무 일 없음"으로 읽힘 |
| 임베딩 정책을 항상 "로컬" | 나가는데 안 나간다고 말함 |
| 기록 없는 용도에 이름 붙임 | 없던 이름이 생김 |
| 실패를 성공으로 표시 | 나간 호출이 성공으로 보임 |
| 잘림 안내 제거 | 412번 중 1번만 보여 주고 말 안 함 |
| 고른 기간을 서버에 안 보냄 | 7일을 골라도 30일이 옴 |

열두 개 전부 검출.

## 하지 않은 것

**임베딩 호출을 사람별로 세지 않았습니다.** 배치가 여러 사람의 메모를 담기 때문이고,
귀속시키면 화면이 확인해 주지 못하는 것을 확인해 준다고 말하게 됩니다. 정책을 말하는
쪽을 골랐습니다. 조용히 빼지 않고 적어 둡니다.
