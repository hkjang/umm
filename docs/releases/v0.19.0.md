# umm v0.19.0 — 찾아 놓은 중복을 실제로 합치기

v0.16.0에서 아침 브리핑이 **겹쳐 보이는 생각**을 찾아 보여 주기 시작했습니다. 그런데 거기서 할 수 있는 일이 없었습니다. 문제 목록만 있고 버튼이 없었습니다.

제가 열어 놓고 닫지 않은 구멍이라 먼저 막았습니다.

---

## 1. 합치기는 조용히 데이터를 잃는 연산입니다

노트를 참조하는 테이블이 **여덟 개**입니다.

| 테이블 | 합칠 때 |
| :--- | :--- |
| `note_edges` | 남는 쪽으로 이동 |
| `note_comments` | 남는 쪽으로 이동 |
| `dream_sources` | 남는 쪽으로 이동 |
| `dream_notes` | 남는 쪽에 없을 때만 이동(`note_id`가 유니크) |
| `link_dismissals` | 삭제 — 짝이 바뀌었으므로 |
| `note_embeddings` | 남는 쪽 것도 삭제 |
| `note_reviews` | **따라가지 않음** |
| `note_revisions` | **따라가지 않음** |

캐스케이드에 맡기면 옮기지 않은 것은 노트와 함께 사라집니다. 하나씩 명시적으로 처리했습니다.

뒤의 두 개는 일부러 남깁니다. **복습 일정은 그 사람이 본 카드에 대한 회상 타이밍이고, 리비전은 사라질 행의 역사입니다.** 옮기면 살아남은 생각에게 일어나지 않은 일을 기록하게 됩니다.

임베딩을 지우는 이유는 내용이 바뀌었기 때문입니다. 남겨 두면 이후 모든 비교가 **더 이상 없는 문장**을 기준으로 판단합니다.

---

## 2. 합쳐진 문구는 umm이 정하지 않습니다

두 노트가 거의 같다는 건 umm이 압니다. **어느 표현을 남기고 싶은지는 모릅니다.** 이어 붙이면 같은 말을 두 번 하는 노트가 됩니다.

그래서 `content`를 호출자가 넘깁니다. 브리핑에서 누르면 **먼저 적은 쪽의 문구**로 합치고, 직접 고르고 싶으면 생각을 열어 정리하라고 안내합니다.

먼저 적은 쪽이 남는 이유는 그게 **원래 생각**이고, 이미 그것을 가리키고 있던 것들이 계속 실재하는 대상을 가리키게 되기 때문입니다.

---

## 3. 거부하는 경우들

합치기는 되돌릴 수 없으므로, 무엇을 거부하는지가 무엇을 하는지만큼 중요합니다.

- 자기 자신과 합치기
- 존재하지 않는 노트
- 빈 내용 — 살아남은 생각이 아무 말도 안 하게 됩니다
- **쓰기 권한 없는 공간의 노트** — 합치기가 남의 생각을 지우는 수단이 되어서는 안 됩니다
- **다른 공간의 노트** — 연결은 양 끝이 같은 공간에 있어야 하므로, 허용하면 연결을 버리거나 생각을 저자가 두지 않은 곳으로 옮기게 됩니다

각각을 테스트로 고정했고, 거부 후에도 아무것도 파괴되지 않았는지 함께 확인합니다.

같은 쌍을 반대 방향에서 동시에 합치는 두 요청이 교착하지 않도록, 두 행을 **고정된 순서로** 잠급니다.

---

## 4. 실제로 확인한 경로

```
중복 1건 발견
  → 합치기 (새 것을 먼저 적은 것으로)
     movedEdges 1 · droppedEdges 0 · movedComments 1
  → 중복 0건
  → 남은 생각: 연결 1개, 댓글 1개
```

연결과 댓글이 따라왔고, 브리핑에서 항목이 사라졌습니다.

로드맵의 최우선은 Thought Agent지만, 착수해 보니 **에이전트가 쓸 도구 중 상당수가 아직 없습니다**(`merge_thoughts`, `find_contradictions`, `find_open_questions`). 에이전트를 먼저 만들고 도구를 채우는 것보다, 도구가 **각자 단독으로 쓸모 있는 상태**로 존재한 뒤 그 위에 에이전트가 서는 편이 낫다고 판단했습니다. 이번 릴리스가 그중 첫 번째입니다.

## 업그레이드

스키마 변경이 없습니다. 이미지만 교체하면 됩니다.

```bash
docker run -d --name umm --restart unless-stopped \
  -p 8080:8080 \
  -e POSTGRES_DSN='postgres://umm:password@postgres.internal:5432/umm?sslmode=require' \
  -e BOOTSTRAP_ADMIN='admin' \
  -e BOOTSTRAP_ADMIN_PASSWORD='your-strong-password' \
  -e ENCRYPTION_KEY='your-32-char-random-encryption-key' \
  umm:v0.19.0
```

- 합쳐진 노트는 **soft delete**입니다. 데이터베이스에서 사라지지 않습니다.
- 중복 탐지 자체는 임베딩이 의미를 판별할 때만 동작합니다(v0.16.0). 설정하지 않은 배포에서는 브리핑이 확인하지 않았다고 표시합니다.
