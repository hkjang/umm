# v0.37.0 — 보이는 것보다 안 보이는 것이 더 많았습니다

메모 카드를 열어 보기 전에 **먼저 쟀습니다.** 기본 크기 메모 하나에서 나온 숫자입니다.

| | |
| --- | ---: |
| 적어 둔 글자 | 179자 |
| 카드 높이 | 168px |
| **화면 밖에 있던 높이** | **169px** |

보이는 것보다 **안 보이는 쪽이 더 큽니다.** 화면에서는 "새로 온 사람이 사"에서 글자 중간에
끊기고, 더 있다는 표시가 카드 어디에도 없었습니다.

텍스트 영역은 원래 스크롤됐으니 **읽을 수는 있었습니다.** 문제는 읽을 수 있다는 걸
*알 방법이 없었다*는 것입니다. 자기가 쓴 생각을 기억하려고 만든 캔버스에서, 카드가 자기 내용을
조용히 잘못 말하는 것보다 나쁜 일은 없습니다.

이제 카드가 **몇 줄이 남았는지** 말합니다 — `+7줄`. 글자는 가장자리에서 흐려져 끊긴 자리가
끊겨 보입니다.

`+7줄`을 누르면 생각 전체가 들어갈 때까지 카드가 넓어집니다. **누를 때만입니다.** 메모 크기는
그 사람이 정한 것이고, 이 캔버스는 사람이 배치한 것을 그 사람 것으로 둡니다 — 그래서 글이
넘치는 순간 제멋대로 커지는 대신, 더 있다고 말하고 기다립니다.

## 표시했는데 표시가 안 보였습니다

메모 메뉴에는 **질문으로 표시**와 **Dream 분석에서 제외**가 있습니다. 둘 다 눌러도 카드에
아무 흔적이 남지 않았습니다. 확인하려면 메뉴를 다시 열어야 했습니다.

umm의 규율은 *표시하되 지어내지 않는다*입니다. 질문인지 아닌지는 사람이 정합니다 —
물음표로 끝나는 문장이 질문이 아닌 경우도, 물음표 없는 진짜 질문도 흔하니까요.

**그런데 표시한 결과가 보이지 않으면, 그건 표시한 사람만 기억하는 표시입니다.** 규율의 절반만
지킨 셈입니다.

이제 카드에 `질문` · `분석 제외` 배지가 붙습니다. `접어 둠`까지 셋이 한 줄에 나란히 놓입니다 —
전에는 각각 같은 모서리에 절대 위치로 고정돼 서로 겹쳤습니다.

## 색상 스와치는 멀쩡했습니다

메뉴의 색상 견본이 `var(--note-yellow, #ddd)`를 쓰길래 변수가 없으면 전부 회색이겠다고
의심했는데, **확인해 보니 변수는 실제로 있었습니다.** 고칠 것이 없었습니다.

단정하기 전에 확인해서 멀쩡한 코드를 건드리지 않았습니다.

## 통과하는 테스트는 아직 아무것도 증명하지 않습니다

새 테스트 다섯 개를 통과시킨 뒤 **구현을 되돌려 다시 돌렸습니다.**

```
✘ 안 보이는 분량이 몇 줄인지 말한다
✘ 생각 전체가 들어갈 때까지 넓히고, 그 크기를 유지한다
✘ 사람이 붙인 표시를 카드에 보여 준다
✘ 질문으로 표시하면 카드에 바로 나타난다
✓ 다 들어가는 생각은 아무 말도 하지 않는다  — 없음을 확인하는 테스트라 전에도 옳았습니다
```

되돌리는 과정에서 **테스트 자체의 결함 둘**도 드러났습니다.

`textarea[value^="…"]`로 카드를 찾고 있었는데, React는 제어 중인 값을 DOM 속성에 반영하지
않습니다. 선택자가 **아무것도 못 찾고 있었고**, 그래서 그 단언은 공허하게 통과하고 있었습니다.
카드의 접근성 이름으로 바꿨습니다.

그리고 카드 높이를 화면 픽셀로 비교했는데, 캔버스는 열 때마다 배율을 다시 맞춥니다. 같은 메모가
새로고침 전 `1091px`, 후 `642px`로 측정됐습니다 — 저장된 높이는 그대로인데도요. 이제 저장된
값을 비교합니다.
