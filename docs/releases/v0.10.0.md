# umm v0.10.0 — 임베딩 품질을 보이게, 그리고 고칠 수 있게

v0.9.0은 기본 임베딩이 의미가 아니라 어휘를 재고 있다는 것을 **측정**했고, 좋은 모델을 붙여도 기능이 무너지지 않도록 임계값을 고쳤습니다.

하지만 그 사실은 여전히 소스 코드와 릴리스 노트에만 있었습니다. 운영자는 제품 어디에서도 지금 자기 배포가 의미를 재고 있는지 알 수 없었고, 모델을 설정했는데 오타가 나 로컬로 폴백 중이어도 **아무 경고가 없었습니다.**

v0.10.0은 그 두 가지를 고칩니다.

---

## 1. 보이게: 임베딩 품질 측정 패널

관리자 → **AI Gateway** 하단에 패널이 생겼습니다. 지금 설정된 백엔드로 라벨링된 한/영 문장쌍 22개를 직접 임베딩해 점수를 냅니다.

```
판별력  −0.250    쌍별 정확도  4.2%    최근접 동일 주제  18.8%    umm-local-chargram-v1

문장쌍 종류            평균 유사도   개수
같은 뜻, 다른 표현        0.193       8
같은 주제, 다른 주장      0.155       4
단어만 겹침 (함정)        0.443       6
무관                     0.177       4
```

`단어만 겹침`이 `같은 뜻, 다른 표현`보다 높다는 것이 한눈에 보입니다. 이 상태에서 연관 생각·군집·검색의 "의미상 유사"는 실제로는 **어휘 유사**입니다.

세 가지 상태를 구분해 보여 줍니다.

| 표시 | 뜻 |
| :--- | :--- |
| 🟡 어휘가 겹치는 정도만 재고 있습니다 | 모델 미설정 (기본값) |
| 🔴 **설정한 모델이 쓰이지 않고 있습니다** | 모델은 설정됐지만 벡터는 로컬에서 나옴 |
| 🟢 의미 기반으로 동작합니다 | 표현이 달라도 같은 뜻을 알아봄 |

### 조용한 실패가 처음으로 드러납니다

가운데 항목이 이번 릴리스에서 가장 중요합니다. 모델 이름에 오타가 나거나 게이트웨이가 죽으면 umm은 **조용히 로컬 임베딩으로 폴백**합니다. 에러도, 로그 배너도, 화면 표시도 없었습니다. 운영자 입장에서는 잘 동작하는 배포와 구별할 방법이 전혀 없었습니다.

실제 배포에서 확인한 결과입니다.

```
모델명을 "model-that-was-never-pulled"로 저장

algorithm  umm-local-chargram-v1     ← 벡터는 로컬에서 나옴
model      model-that-was-never-pulled ← 설정된 것은 이것
fellBack   true                       ← 이제 경고가 뜹니다
```

측정은 백엔드별로 10분 캐시되므로 설정 화면을 열 때마다 추론 서버를 두드리지 않습니다. **다시 측정**을 누르면 갱신됩니다.

`GET /api/v1/admin/embedding-quality`로도 같은 값을 받을 수 있어 배포 후 점검에 넣을 수 있습니다.

## 2. 고칠 수 있게: 오프라인 임베딩 서버 프로파일

v0.9.0에서 남겨 둔 결정입니다. 셋 중 어느 것도 만족스럽지 않았습니다 — 게이트웨이 안내는 기본 설치를 고치지 못하고, 정적 벡터 테이블은 품질이 불확실하며, ONNX 번들은 `CGO_ENABLED=0` 정적 단일 바이너리 보장을 깨뜨립니다.

네 번째 길을 택했습니다. **모델을 umm 안에 넣지 않고 옆에 세웁니다.** 이미지는 그대로 56MB 정적 바이너리이고, 폐쇄망에서도 모델을 한 번만 반입하면 됩니다. 어차피 PostgreSQL도 옆에 두고 쓰는 구조입니다.

```bash
docker compose --profile embeddings up -d
docker compose exec embeddings ollama pull bge-m3
```

AI Gateway를 `http://embeddings:11434` / `bge-m3`로 저장하면 끝입니다. 빈 스택에서 시작해 실제로 확인한 결과입니다.

```
설정 전:  판별력 −0.250   정확도  4.2%   최근접 동일 주제 18.8%   semantic=false
설정 후:  판별력 +0.079   정확도 83.3%   최근접 동일 주제 75.0%   semantic=true
```

### 후보 모델 측정 결과 — 그리고 측정끼리 어긋난 지점

| 모델 | 크기 | 판별력 | 쌍별 정확도 | 주제 분리 | 최근접 동일 주제 | umm 종단 테스트 |
| :--- | ---: | ---: | ---: | ---: | ---: | :---: |
| 내장 로컬 (문자 n-gram) | 0 | −0.250 | 4.2% | −0.023 | 18.8% | ✗ |
| **bge-m3** | 1.2GB | +0.079 | 83.3% | +0.105 | 75.0% | **✓** |
| bona/bge-m3-korean | 1.2GB | **+0.146** | 81.2% | +0.101 | 68.8% | ✓ |
| paraphrase-multilingual | **562MB** | +0.115 | **85.4%** | **+0.223** | **87.5%** | ✗ |

작업 도중 `paraphrase-multilingual`을 기본 권장으로 정할 뻔했습니다. 라벨 데이터 네 지표에서 모두 1위이고 크기도 절반 이하였기 때문입니다.

그런데 v0.9.0에서 만들어 둔 종단 테스트가 막았습니다. 보안 3 + 자전거 3으로 이뤄진 공간에서 이 모델은 두 주제를 한 덩어리로 합칩니다. `인증 토큰 만료 시간을 24시간으로 정했다`의 최근접 이웃으로 같은 주제의 `세션 쿠키...`(0.23)가 아니라 `라이딩이 끝나면 스트레칭을 꼭 한다`(0.32)를 고르기 때문입니다.

**한 문장이 틀렸을 뿐인데 6개 메모 공간에서는 그것으로 충분했습니다.** 집계 점수가 높다고 특정 워크스페이스에서 더 나은 군집이 나오는 것은 아닙니다. 모델마다 틀리는 문장이 다르고, 메모 수가 적을수록 한 번의 실수가 결과를 지배합니다.

그래서 기본 권장은 라벨 지표가 중간이더라도 **umm이 실제로 단언하는 동작을 통과하는 `bge-m3`** 입니다. 디스크가 빠듯하면 `paraphrase-multilingual`도 실용적이지만, 위 한계를 알고 실제 공간에서 눈으로 확인하시길 권합니다.

## 3. 주제 분리 측정이 추가됐습니다

이 어긋남을 발견하고 나서, 원래 데이터셋이 **연관 생각과 군집이 실제로 하는 일을 재고 있지 않다**는 것이 분명해졌습니다. 문장쌍 22개는 "이 둘이 같은 뜻인가"를 묻지만, 화면의 기능은 "이 공간의 것들 중 무엇이 무엇과 묶이는가"를 묻습니다.

라벨된 4개 주제 16문장을 추가하고 두 지표를 함께 보고합니다.

- **주제 분리** — 같은 주제끼리의 평균 유사도에서 다른 주제와의 평균을 뺀 값
- **최근접 동일 주제** — 각 문장의 가장 가까운 이웃이 같은 주제인 비율

내장 알고리즘은 18.8%(우연 수준), 실제 임베딩 모델은 68.8~87.5%로 간격이 넓고 분명합니다. `semantic` 판정에 이 지표를 포함시켜, 문장쌍만 잘 맞히고 주제를 섞는 백엔드가 통과하지 못하게 했습니다.

처음에는 이 기준을 100%로 잡았습니다. 측정해 보니 **어떤 모델도 도달하지 못하는 값**이었고, 실측 분포에 맞춰 60%로 내렸습니다.

---

## 4. 측정 코드가 테스트 밖으로 나왔습니다

v0.9.0에서 `quality_test.go`에 있던 데이터셋과 채점 로직을 `internal/intelligence/quality.go`로 옮겼습니다. CI가 매번 출력하던 표와 관리자 화면이 **같은 코드, 같은 데이터셋**을 씁니다.

`Semantic` 판정은 테스트로 고정돼 있습니다. `TestOfflineDefaultIsNotASemanticBackend`는 기본 알고리즘이 스스로를 의미 백엔드라고 보고하면 실패합니다 — 그 순간 운영자에게 뜨던 경고가 사라지기 때문입니다.

통합 테스트 세 개가 화면이 구분해야 하는 세 상태를 각각 고정합니다: 미설정, 설정했지만 폴백 중, 정상 동작. 두 번째는 죽은 포트를 가리켜, 세 번째는 의미를 아는 스텁 게이트웨이로 재현합니다.

## 업그레이드

스키마 변경이 없습니다. 이미지만 교체하면 됩니다.

```bash
docker run -d --name umm --restart unless-stopped \
  -p 8080:8080 \
  -e POSTGRES_DSN='postgres://umm:password@postgres.internal:5432/umm?sslmode=require' \
  -e BOOTSTRAP_ADMIN='admin' \
  -e BOOTSTRAP_ADMIN_PASSWORD='your-strong-password' \
  -e ENCRYPTION_KEY='your-32-char-random-encryption-key' \
  umm:v0.10.0
```

올린 뒤 **관리자 → AI Gateway → 임베딩 품질 측정**을 한 번 확인해 보시길 권합니다. 이미 모델을 설정해 둔 배포에서 🔴가 뜬다면, 그동안 설정한 모델이 실제로는 쓰이지 않고 있었다는 뜻입니다.
