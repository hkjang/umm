# v0.43.0 — 메모가 담고 있던 것을 보여 줍니다

메모를 실제로 써 보고 두 가지를 찾았습니다. 둘 다 **이미 메모 안에 있는데 보이지 않던
것**입니다.

## 문서를 가져오면 제목이 사라졌습니다

마크다운을 가져오면 `# 제목`이 메모의 제목이 됩니다. **처음부터 그랬습니다.**

측정해 보니:

| | |
| --- | --- |
| 저장된 것 | `title: "배포 파이프라인 이전"` + 본문 |
| 화면에 보인 것 | 본문만 |

그 제목은 **데이터베이스에 있고, 검색이 찾고, 발표 자료의 슬라이드 제목이 되고, 스크린
리더가 읽습니다.** 정작 쓴 사람이 보는 그 한 곳에만 없었습니다.

제목을 붙이거나 뗄 방법도 없었습니다.

이제 제목이 있으면 생각 위에 보이고, 메모 메뉴의 **`제목 붙이기`** 로 붙일 수 있습니다.
붙이면 커서가 바로 그 자리에 갑니다 — 메뉴를 누르고 어디에 쓰는지 다시 찾는 게 아니라요.
Enter를 누르면 생각 본문으로 넘어갑니다.

**첫 줄을 제목으로 삼지 않습니다.** 생각의 첫 문장은 보통 그 생각 자체이지 이름이 아니고,
승격시키면 아무도 의도하지 않은 제목이 모든 메모에 붙습니다. 표시하는 것이지 추론하는 게
아닙니다.

이름 없는 메모에는 빈 칸도 생기지 않습니다. 종이가 있어야 할 자리에 양식을 두는 셈이니까요.

## 메모 안의 주소가 죽은 글자였습니다

`참고 자료: https://…` 라고 적힌 메모에서 **가장 쓸모 있는 부분에 닿을 수 없었습니다.**
본문은 고쳐 쓸 수 있어야 해서 textarea이고, textarea 안의 글자는 그냥 글자입니다. 손으로
복사하는 게 유일한 방법이었습니다.

이제 메모 메뉴가 **`링크 열기`** 를 제공합니다. 카드에 다시 그리지 않는 이유는 같은 주소가
카드에 두 번 나오게 되고, 카드는 이미 자리가 빠듯하기 때문입니다.

- 문장 끝의 마침표는 **주소가 아니라 문장의 끝**이므로 뺍니다
- 같은 사이트의 두 페이지가 구분되도록 경로를 **뒤에서** 남깁니다 (어느 페이지인지는 끝이 말합니다)
- `http`와 `https`만 엽니다. 메모에는 무엇이든 적힐 수 있고, 아무 글자나 열 수 있게 만드는 것이 `javascript:`나 `file:`이 "링크"가 되는 경로입니다

## 둘 다 실패시켜 확인했습니다

제목을 숨기면 새 테스트 넷이 실패합니다. 다섯 번째는 **없음을 확인하는 테스트**라 전에도
옳았습니다.

링크 쪽에서 배운 것도 있습니다. 정규식과 파싱 후 프로토콜 재확인 중 **하나만 없애면 아무
일도 일어나지 않습니다** — 서로가 서로를 덮습니다. **둘 다 없애야** `file://`이 통과하고
테스트가 실패합니다. 겹쳐 둔 두 겹이지, 하나가 군더더기인 게 아닙니다.
