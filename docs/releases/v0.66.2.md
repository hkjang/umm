# v0.66.2 — 내보내기를 브라우저에서 걸어 봤습니다

v0.66.0에서 PDF 내보내기가 들어갔습니다. **브라우저에서 한 번도 안 걸어 봤습니다.**
그래서 깨진 걸 릴리즈 직전에야 알았습니다.

## 노트북에서는 되고 Docker에서는 안 됐습니다

jsPDF는 `.html()` 메서드용으로 `html2canvas`를 import합니다. umm은 그걸 안 씁니다 —
jsPDF를 부를 때 캔버스는 이미 PNG이고 `addImage`만 씁니다.

문제는 `html2canvas`가 jspdf의 **optional 의존성**이라는 것입니다.

```
개발자 node_modules      → 있음   → 빌드 성공
npm ci --ignore-scripts  → 없음   → 빌드 실패
                                    ↑ 릴리즈 경로
```

번들러는 **실행되지 않는 import도 해석합니다.** 그래서 빌드가 어느 기계에서 도는지에
결과가 달렸습니다. `external`로 "이 import는 절대 실행되지 않는다"를 명시했고(v0.65.0 PR에
포함), `html2canvas`를 디스크에서 치운 상태로 양방향 확인했습니다 — 없이는 CI와 똑같은
에러, 있으면 성공, 그리고 실제 `docker build` 통과.

## 그런데 이걸 잡은 건 무엇도 아니었습니다

단위 시험도, 타입 검사도, 린터도 전부 통과했습니다. **어느 것도 그 라이브러리를 불러오지
않기 때문입니다.** `docker build`가 잡았고, 그건 릴리즈 워크플로의 마지막 단계입니다.

그래서 이번 릴리즈는 기능이 아니라 **그 구멍을 메웁니다.**

## 내보내기 메뉴를 전부 걷습니다

| 항목 | 전 | 후 |
| :--- | :--- | :--- |
| Markdown | e2e 있음 | 그대로 |
| Image (PNG) | **없음** | 파일이 떨어지고 PNG 매직 바이트 확인 |
| PDF 다운로드 | **없음** | 파일이 떨어지고 `%PDF-` 확인 |

파일이 "왔다"만 보지 않습니다. 빈 파일도, HTML 오류 페이지도, PNG도 전부 다운로드로는
똑같이 도착합니다. 그래서 **앞머리 바이트**와 **내용이 들어 있는 크기**를 봅니다.

## 아무것도 확인하지 않는 단언을 고쳤습니다

처음 쓴 시험은 이랬습니다.

```
클릭
expect('내보내기 실패').toHaveCount(0)   ← 실패가 뜨기 전에 통과
await download                            ← 60초 기다리다 죽음
```

**실패가 화면에 뜨기 전에 통과하는 단언**이었습니다. 변형 시험에서 셋이 전부 이유 없는
타임아웃으로 잡히는 걸 보고 알았습니다. 지금은 다운로드와 오류 메시지를 **경주**시켜서
먼저 오는 쪽이 답입니다 — 깨지면 60초가 아니라 몇 초 만에, 화면에 뜬 문장과 함께
알려 줍니다.

## 확인한 것

```
✓ PDF: 다운로드가 실제로 떨어지고, %PDF- 로 시작하고, 20KB 넘음
✓ PNG: 다운로드가 실제로 떨어지고, PNG 매직 8바이트로 시작하고, 20KB 넘음
✓ 실패는 타임아웃이 아니라 화면 문장으로 보고됨
✓ 실제 바이너리 · 실제 번들로 확인
```

| 바꾼 것 | 잡은 것 |
| :--- | :--- |
| 저장을 안 함 | 다운로드가 안 옴 |
| jspdf를 external로 (라이브러리 미로드) | 화면에 "내보내기 실패" |
| 이미지를 안 넣음 | PDF가 20KB 미만 |
| 내보내기가 던짐 | 화면에 "내보내기 실패" |
| PNG 앵커 클릭 제거 | 다운로드가 안 옴 |
| 이미지 배율을 1/150로 | PNG가 20KB 미만 |

여섯 개 전부 검출.
