# umm v0.13.0 — 그래프를 읽을 수 있게

v0.11.0에서 연결에 뜻과 출처를 기록하기 시작했고, v0.12.0에서 umm이 직접 연결을 제안하기 시작했습니다. 그런데 **에이전트 입장에서 그 그래프는 쓰기 전용이었습니다.** MCP로 연결을 만들 수는 있어도, 무엇이 무엇과 어떻게 이어져 있는지 읽을 방법이 없었습니다.

---

## 1. `get_connections` — 에이전트가 그래프를 걷습니다

MCP에 도구가 하나 늘었습니다. 한 생각에 붙은 연결들을 방향·뜻·출처와 함께 돌려줍니다.

```json
{
  "connections": [
    {
      "content": "임베딩 모델을 바꾸면 다시 계산해야 한다",
      "direction": "incoming",
      "relation": "supports",
      "origin": "agent",
      "inferred": false,
      "note_id": "cd689fbd-…"
    }
  ]
}
```

기존 `get_related_notes`와는 다릅니다. 그쪽은 **비슷해 보이는** 생각을 임베딩으로 찾고, 이쪽은 **실제로 기록된** 연결을 돌려줍니다. 누가 만들었는지(`origin`)와 umm이 추측한 것인지(`inferred`)가 함께 나오므로, 에이전트는 자기가 쓴 부분과 사람이 그은 부분을 구별할 수 있습니다.

응답은 일부러 평평하게 만들었습니다. 읽는 쪽에 필요한 것은 "이 생각과 저 생각이 이런 관계이고 누가 그렇게 말했다"이지, 중첩된 엣지 객체를 푸는 일이 아니기 때문입니다.

MCP 도구 목록 테스트도 고쳤습니다. 개수만 세던 것을 **이름 전체를 명시**하도록 바꿨습니다. 개수는 "뭔가 바뀌었다"만 말하지만, 이름은 무엇이 바뀌었는지 말하고 실수로 사라진 도구도 똑같이 잡아냅니다.

## 2. v0.11.0에서 제가 넣은 결함

`Backlinks` 쿼리가 `origin`과 `confidence`를 **선택하지 않고 있었습니다.**

v0.11.0에서 `Edge` 구조체에 두 칸을 추가하면서 읽는 곳을 전부 고쳤다고 생각했는데, 이 하나를 빠뜨렸습니다. 아무것도 실패하지 않았습니다 — 필드가 그냥 빈 값으로 도착했을 뿐입니다.

결과적으로 캔버스의 **직접 연결 · 백링크** 패널에서 모든 연결에 의미 없는 구분자가 붙어 나왔습니다. v0.11.0에서 "출처를 화면에 보여 준다"고 적어 놓고, 정작 그 값이 오지 않고 있었습니다.

OpenAPI 명세는 처음부터 옳았습니다. `Backlink.edge`는 `Edge`를 참조하고 `Edge`는 `origin`을 필수로 요구합니다. **명세가 맞고 구현이 틀렸는데 아무도 확인하지 않았습니다.**

엣지를 읽는 모든 경로가 출처를 싣는지 확인하는 테스트를 넣었습니다. 고치기 전 상태에서 실패하는 것을 확인했습니다.

```
graph_integration_test.go:234: backlinks returned an edge with no origin;
                               the interface cannot say who made it
```

## 3. 테스트 스위트가 원래 불안정했습니다

작업 중 Dream 테스트가 관계없는 이유로 실패했습니다. 원인을 좇아가 보니 제 코드가 아니라 **스위트 자체의 문제**였습니다.

통합 테스트는 하나의 PostgreSQL을 공유하고, `app_settings`의 `ai_gateway`는 **전역 행 하나**입니다. `go test ./...`는 패키지를 병렬로 돌리므로, `internal/store`의 테스트가 스텁 게이트웨이를 꽂아 두면 동시에 도는 `internal/dream`이 그것을 집어 듭니다.

측정한 결과입니다.

| | 실패한 실행 |
| :--- | ---: |
| 병렬 (기본) | 3회 중 **2회** |
| 직렬 (`-p 1`) | 3회 중 **0회** |

이번 작업에서 세 번 겪은 "재현되지 않는" 실패가 전부 이것이었습니다. 백엔드가 조용히 로컬로 닫히거나, 워크스페이스가 엉뚱한 임베딩으로 채점되거나, Dream이 죽은 게이트웨이를 보거나.

CI를 `-p 1`로 바꿨습니다. 느린 작업은 어차피 데이터베이스가 직렬화하므로 **비용은 3%**(116초 → 120초)입니다.

## 업그레이드

스키마 변경이 없습니다. 이미지만 교체하면 됩니다.

```bash
docker run -d --name umm --restart unless-stopped \
  -p 8080:8080 \
  -e POSTGRES_DSN='postgres://umm:password@postgres.internal:5432/umm?sslmode=require' \
  -e BOOTSTRAP_ADMIN='admin' \
  -e BOOTSTRAP_ADMIN_PASSWORD='your-strong-password' \
  -e ENCRYPTION_KEY='your-32-char-random-encryption-key' \
  umm:v0.13.0
```

- 백링크 패널의 출처 표시가 이번에 실제로 동작합니다.
- MCP 클라이언트는 `tools/list`를 다시 읽으면 `get_connections`가 보입니다. 필요한 scope는 `notes:read`입니다.
