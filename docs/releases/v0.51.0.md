# v0.51.0 — 공간을 되살립니다. 문장 목록이 아니라

v0.50.2·v0.50.3 에서 내보낸 파일을 다시 읽게 만들었습니다. 그런데 **되살아나는 것은 글자뿐**
이었습니다.

```
내보낸 것                     다시 가져온 것
─────────────────────────    ─────────────────────────
생각 2개                      생각 2개            ✓
40,60 과 980,720 의 자리       나란한 격자          ✗
둘을 잇는 연결                  없음                ✗
```

umm 은 **공간** 기억입니다. 생각이 어디에 놓여 있는지, 무엇과 이어져 있는지가 사람이 손으로
만든 것의 대부분입니다. 그걸 빼고 돌려주면 백업이 아니라 인쇄물입니다.

## 이제 자리와 연결이 함께 돌아옵니다

내보내기는 처음부터 필요한 걸 다 적고 있었습니다. 읽지 않았을 뿐입니다.

```
- id: `12fc168d-…`        ← 그 공간에서 이 생각의 이름
- canvas: `40, 60`        ← 앉아 있던 자리

## Connections
- `12fc168d-…` --related--> `316ef126-…`
```

가져오기는 이제 각 생각의 옛 이름을 기억해 두었다가, 새로 만들어진 생각끼리 **연결을 다시
잇습니다.** 자리도 그대로 돌아갑니다.

> 2개의 생각과 1개의 연결을 되살렸습니다.

남의 마크다운은 그대로입니다. 지나온 적이 없는 생각에는 자리도 옛 이름도 없으니, 예전처럼
격자로 놓입니다.

## 검증

화면을 통해 확인했습니다 — 파서만이 아니라 **내보내기 → 입력란 → 가져오기 → 캔버스 → 서버**
전체를 한 번에 지나가는 e2e 입니다. 원래 공간과 다른 새 공간으로 가져와서, 원본이 비쳐
보이는 일이 없게 했습니다.

```
✘ 내보낸 자리를 무시하고 격자로  →  "40,60" 자리에 "-98,114" 가 나와 실패
✘ 연결을 다시 잇지 않음          →  연결 1개가 0개로 나와 실패
```

두 되돌리기 모두 **빌드가 실제로 성공했고 번들 파일 이름이 실제로 바뀐 것을 확인한 뒤에**
결과를 믿었습니다.

## 이번에 걸린 함정 하나

첫 e2e 가 "연결 0개" 로 실패했습니다. 원인은 코드가 아니라 **번들이었습니다.** `npm run
build` 는 `tsc -b && vite build` 인데, 제가 고치다 만 모달 시험 하나가 타입 오류를 내서
`tsc -b` 에서 멈췄고, `dist` 는 한 시간 전 것 그대로였습니다. 시험은 옛 번들을 보고
있었습니다.

`npx tsc --noEmit` 은 통과했습니다. 보는 범위가 다릅니다. **`dist` 의 시각을 확인하지
않았다면 "연결 복원이 안 된다" 고 결론 내렸을 것입니다.**
