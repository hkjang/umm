# v0.59.1 — Dream 발전시키기만 가리개를 안 쓰고 있었습니다

어제 v0.59.0에서 redaction 규칙을 고치면서 이렇게 썼습니다.

> 규칙은 `이름: 값` 만 보고 있었습니다.

규칙을 고쳤으니, **그 규칙을 어디에 쓰고 있는지** 도 세어 봤습니다. 게이트웨이로 프롬프트를
보내는 곳이 넷인데, **하나가 안 쓰고 있었습니다.**

| 보내는 곳 | redaction |
| :--- | :--- |
| 질문하기 (`ask`) | ✓ |
| 밤사이 Dream 만들기 | ✓ |
| 고른 생각 발전시키기 | ✓ |
| **Dream 발전시키기** | ✗ |

마지막 둘은 거의 같은 함수입니다. 같은 원본 생각을 같은 게이트웨이로 보냅니다. 한쪽만
가리개를 쓰고 있었습니다.

## 실제로 나가던 것

시험을 붙이고 예전 코드로 되돌려 보니 게이트웨이가 받은 본문이 이랬습니다.

```json
"content": "Dream:\n두 메모를 잇는 Dream 본문 password=dream-body-secret\n\n원본 생각:\n
            [1] 배포 절차 메모 {\"api_key\":\"sk-live-must-not-travel\"} 화요일 회의\n
            [2] 게이트웨이 점검 Authorization: Bearer sk-live-must-not-travel\n"
```

지금은 이렇습니다.

```json
"content": "Dream:\n두 메모를 잇는 Dream 본문 [민감정보 제거됨]\n\n원본 생각:\n
            [1] 배포 절차 메모 {[민감정보 제거됨]\"} 화요일 회의\n
            [2] 게이트웨이 점검 [민감정보 제거됨]\n"
```

**생각은 그대로 가고 비밀만 빠집니다.** "배포 절차 메모", "화요일 회의" 는 남아 있어야 합니다 —
Dream 은 남은 글로 발전시키니까요.

## 시험은 게이트웨이가 받은 것을 읽습니다

umm이 **보내려고 만든** 프롬프트가 아니라 게이트웨이가 **실제로 받은 요청 본문**을 봅니다.
그 둘은 중간에서 아무도 되돌리지 않을 때만 같습니다.

변형 둘 다 잡혔습니다.

| 바꾼 것 | 잡은 것 |
| :--- | :--- |
| 예전처럼 redaction 없이 보내기 | `sk-live-must-not-travel` 이 요청 본문에 있음 |
| redaction 이 전부 지우게 | "배포 절차 메모" 가 게이트웨이에 도착하지 않음 |

## 같은 모양을 이틀 연속 봤습니다

v0.59.0 은 **규칙이 두 가지 모양을 놓친 것**이었고, 이번은 **규칙을 한 군데서 안 쓴 것**입니다.
가리개가 있는지보다 **모든 문에 달렸는지**를 세는 편이 빠릅니다.
